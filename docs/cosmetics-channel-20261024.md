# 房间外观通道与兼容修复

2026-10-24，与 Godot 客户端 `0.0.0-beta.6` 配套。

## 外观协议

握手提供 cosmetics 能力。已批准的玩家可以上传 PNG、提交装备、发送已装备表情；
已批准的观战者只读。未批准连接不可读写或接收外观通知。

| 方法 | 用途 |
|---|---|
| `cosmetics.asset` | 上传 PNG，返回 SHA-256 标识 |
| `cosmetics.set` | 提交展示资料，不接受总部规则等字段 |
| `cosmetics.get` | 获取座位资料与 revision |
| `cosmetics.image` | 读取已装备图片 |
| `cosmetics.emote` | 按装备 Id 发送，服务端校验座位并限频 |

表情配置包含 `Id`、`Label`、`Image`，另有可选 `Style`、`Tint`、`EnemyImage`。
后者用于原版对手视角纸张底图；缺省字段保持旧资料可读。通知携带对应小写字段。
图片最多 2 MiB、4096 像素；每座位最多 24 张、24 MiB。TCP 客户端与服务端明确
使用 4 MiB NDJSON 帧，容纳 Base64 图片；其他读取器保留原来的 1 MiB 默认值。
规则层与牌组不读取展示字段。

## 同批机制修复

- 攻击收尾检查目标引用是否仍存活，避免替身/离场导致扣费和收尾中断。
- 独立创建的词条卡在没有实例记录时使用词条参数或默认值；已记录的零值仍有效。

验证：Orc.Game.Tests 1357/1357；Orc.Server.Tests 118/118。
客户端另修复旧原生效果快照在预选靶后重复询问的问题；该修复位于 Godot 桥接仓库。

## 产品边界

外观传输不等于任意 DIY 规则传输。当前 Godot 房间仅接受已装载的 `pack/` 卡，
没有提供把各玩家的 `diy/` 卡及贴图自动分发、准入并开局的完整界面流程。
