## 1. P0 · 编译阻断（实测）

用当前后端编译前端桥接工程，**首个错误**：

```text
SourceEffectAssembly.cs(83,39): error CS0246: 未能找到类型或命名空间名"CommandCard"
SourceEffectAssembly.cs(87,37): error CS0246: 未能找到类型或命名空间名"CommandCard"
```

修掉 `CommandCard` 后依次暴露另外 4 类（详见下表）——这说明它们是**串联**的，改完一类才能看到下一类。

### 1.1 `CommandCard` → `OrderCard`（9 处）

| 位置 | 现状 |
| --- | --- |
| `proto/bridge/.../SourceEffectAssembly.cs:31,71,83,87` | `card is CommandCard` / `OfType<CommandCard>()` / 参数类型 |

**改法**：全局替换为 `OrderCard`（后端 `Orc.Game.Cards.OrderCard:26`；全仓已无 `class CommandCard`）。

### 1.3 `OrderCard.AddActiveHandler` 已删除（1 处）

- 前端：`SourceEffectAssembly.cs:34`（"源卡主动执行"路径）。
- 后端：`OrderCard.cs:21-22` 明确"主动 handler 集入口（原 `AddActiveHandler`）已删除——主动效果一律经 `AddEffect` 挂载的 `ActiveEffect<TView>` 表达"。
- **改法**：把"指令被执行时做什么"从 handler 注册改为**主动效果**——派生一个 `ActiveEffect<CardTriggerView>` 子类（构造期可经 `CastTrigger.Register(...)` 注册施放事件，或传 `castEvents`），再 `order.AddEffect(effect)`；施放由 `OrderFlow` 经 `Effect.CastAsync` 调用。
  - 类型：`public abstract class ActiveEffect<TView> : Effect, ICastAction`（`src/Orc/Cards/Effect.cs:679`），构造 `protected ActiveEffect(name, bandType?, castEvents?, oneShot, disposalHooks)`（`:684-690`），施放触发器面 `protected Trigger<TView> CastTrigger`（`:716`）。

- 注意：主动效果**不进装载链**、不挂总线，生命周期由卡容器管理。

## 2. P1 · 运行期阻断（编译能过，但一跑就抛）

### 2.1 动作实现集必须注册（**最关键**）

- **现象**：`new Match(...)` → `CommandManager` → `MatchActionCatalog` → `ActionImplementationRegistry.Resolve()` 抛
  `InvalidOperationException: 未注册动作实现：请先注册默认实现集（ActionImplementationRegistry.SetDefault / FoundationActions.Register）。`
- **证据**：`src/Orc.Game/Actions/ActionImplementationRegistry.cs:79-83`；`Actions/MatchActionCatalog.cs:53-55`（构造期 fail-fast）。
- **现状差距**：前端 `Kards.Ui.OrcBridge.csproj` **没有**引用 `Orc.Foundation.Actions`，`OrcEngineHost.Initialize` 也只调了 `BuiltInPlugin.RegisterProcessDefaults()`（`OrcEngineHost.cs:50`）。
- **改法**（两步都要）：
  1. csproj 增加 `<ProjectReference Include="$(OrcEngineRoot)/../Orc.Foundation.Actions/Orc.Foundation.Actions.csproj" />`；
  2. `Initialize` 里 `BuiltInPlugin.RegisterProcessDefaults();` 之后加一行 `Orc.Foundation.Actions.FoundationActions.Register();`（进程级、幂等）。
- **替代路径**：把 `FoundationActionsPluginPackage.Load(<pluginsRoot>)` 并入 `extraPackages`（该目录下须有 `orc.foundation.actions/manifest.json`；包在装配期调 `FoundationActions.Register()`，见 `src/Orc.Foundation.Actions/FoundationActionsPluginPackage.cs:70`）。MCP 宿主采用的正是这条：`src/Orc.Mcp/McpService.MatchLaunch.cs:92-97`。

### 2.2 内置判定器已从 `Match.Initialize` 迁到内置插件

- **现象**：若 `Match` 不传 `packageActivator`，`Initialize` 在 `_judicators.Resolve(...)` 处抛 `KeyNotFoundException`（6 条内置判定器是无条件解析的）。
- **证据**：`src/Orc.Game/Match/Match.cs:596-598`（注释："内置判定器不再硬编码于装配中枢……`null`＝空目录＝无任何判定器"）、`:684-689`（无条件 Resolve）。
- **前端现状**：已传 `packageActivator: new SnapshotPackageActivator(snapshot)`（`OrcMatchSession.cs:289`）且快照含 `BuiltInPluginPackage.Load(...)`（`OrcEngineHost.cs:61`）→ **这条本身是通的**，但必须保证：
  - 快照里**一定有** `orc.builtin.core`（`BuiltInPluginPackage.Load` 提供）；
  - 快照里**同时有** `orc.foundation.actions`（依赖 `orc.builtin.core`，见 `BuiltInPluginPackage.LoadOrder:33-38`），否则 2.1 的动作集仍然缺失。

### 2.3 `action.input.allowed` 仍在，但依赖链变了

- 前端 A.20 的"UI 状态准入"仍可用：`Match.CanAcceptInput` / `Match.InteractionStateReader` 都保留（`Match.cs:290-296`），`ActionInputJudicator` 仍由 `Match.Initialize` 直接注册（`Match.cs:589-591`）。
- 但 `GameHooks.BuiltInJudicatorNames` 已从 22 条扩到 **26 条**（新增 `action.turn.owner`、`inhibit.leg.eligibility`、`unit.adjacent/type/side` 等）。前端 `tests/ActionPortalTests.cs:116` 的 `Contains(ActionInput, ...)` 仍成立；**若有断言总数＝22/23 的地方需要改**。

### 2.4 卡包锁（新增语义）

- 对局进行中 `EngineHost.TryUnloadCardPack` / `TryReloadCardPack` 一律失败（`EngineHost.cs:438-509`）。
- **建议**：前端在 `Match` 创建前 `LockCardPacks()`、终局后 `UnlockCardPacks()`，避免"重开/换包"时序错乱。

## 3. P2 · 数据与文件格式

### 3.1 manifest 升到 v2（`guid` 必填）

- 新格式：`{ schemaVersion:2, kind:"cardpack"|"plugin", id, guid, version, metadata[], requires[], name? }`（`src/Orc.Packages/PackageManifest.cs:44-94`）。
- **v1 清单若无 `guid` ＝ `FormatException`**（`PackageManifest.cs:137-144`：`RequireString(root,"guid")`）。
- 前端的 `samples/demo-card-pack/pack.json`（`schemaVersion:1`，无 `guid`/`metadata`）**不是**后端 manifest，属前端自有格式；但只要它被喂给 `PackageManifest.Read` 或放进 `<base>/packs/*/manifest.json` 就会失败。

### 3.2 sidecar ＋ 两份 lock

- 每个资产源文件旁边必须有 `<源文件>.meta.json`（`AssetMetadataJson.SidecarExtension`）。
- 包根必须有 `lock.formal.json` / `lock.test.json`（`AssetLock.cs:61-67`）。
- **迁移工具**：`AssetMigrationTool.Plan(packageRoot)` → `Apply(plan)`（`AssetMigrationTool.cs:214,337`），或 CLI `tools/Orc.Tools.Migrate`（默认 dry-run，`--apply` 落盘）。
- 缺失 sidecar **不会**整包拒绝（只进 Diagnostics），但 **manifest 的 `metadata[]` 指向的 sidecar 缺失/不可解析 ⇒ 整包抛 `InvalidDataException`**（`PackageRegistrar.cs:137-140`）。

### 3.3 效果预制体：`modings[]` → `wrappers[]`

- 前端构造模板 JSON 时仍写 `modings: []`（`OrcImportService.cs:220`、`DiyCardCompiler.cs:139`）。
- 新 schema：`wrappers[]`（每项必须带 `phase: before|after|replace`，可选 `seam`）＋ 新增 `judicatorWrappers[]`（`src/Orc/Cards/Prefabs.cs:314,364,425`）。
- `modings` 已无对应字段：后端读入会**忽略**（`System.Text.Json` 默认忽略未知字段），所以空数组不会炸，但**语义上已经是死字段**；前端若回写/导出预制体，应改字段名，避免"以为在传 wrapper"。
- 后端 `Templates/*.tpl.json` 实测 **不含** `modings`/`wrappers` 字段（0 命中），所以模板解析不受影响。

### 3.4 校验与模板资源

- `CardDistributionValidator.Validate` 签名未变，但**全空输入改为抛 `ArgumentException`**（`Cards/Data/CardDistributionValidator.cs:130-134`）——前端若在"无卡"场景调用需要 `catch`。
- `EffectParsing/Templates/*.tpl.json` 仍 31 个；`Templates/ops/*.csx.tpl` 仍 21 个（前端 csproj 用通配嵌入，无需改路径）。**若前端硬编码 op 名全集，请核对新增/删除项**。
