# 对外说明 — 卡池运行期注册与注销

把「本实例加载哪些卡包」从 spawn 时一次性给定的启动参数，变成**开局前可增删的运行期状态**：
管理员不重启进程、不改启动参数，即可调整下一局的卡池。

- 权威定义：`requirements.md`（R1–R7）、`implementation.md`（S1–S13）。
- 本文只写**对外可见的语义与用法**（工具描述、事件、字段迁移），实现细节见代码注释。

## 1. 三组名字的边界（先看这张表，避免"pool 一词两义"）

| 名字 | 是什么 | 语义 |
| --- | --- | --- |
| `pool.list` / `pool.register` / `pool.unregister` | **op**（管理面）＋ `pool.list` 同时也是工具 | 操作「**已注册包集合**」＝**下一局**开局会用到的输入 |
| `packset.changed` / `packset.reconciled` | **集合侧事件**（本轮新增） | 集合被写操作改变／失效条目被对账移除 |
| `pool.assembled` / `pool.assemble.failed` / `sandbox.state.pool` | **本局装配结果**（零改动） | 已经打完的那一局实际装了什么 |

一句话：`pool.*` 管"下一局要装什么"，`sandbox.state.pool`／`pool.assembled` 说"这一局装成了什么"。
二者生命周期与读者不同，**不合并**（`sandbox.state` 里不出现集合段）。

## 2. 已注册包集合的语义

- **归属**：进程级、可变；初值＝spawn 参数 `packDirectories`（已剔除沙盒固定包，顺序保留）。
- **不落盘**：进程重启回到 spawn 初值；管理器不保存、不恢复上次注册（它只代发 `pool.*`）。
- **只影响下一局**：变更立即作用于集合，但当前对局持有的是开局时装配好的卡库——即使注销的正是本局在用的包，本局照常打完。
  **不存在「待生效队列」**，`pool.list` 只有一份状态。
- **集合键＝(`manifest.id`, `manifest.version`)**：同 id 多版本可并存；`(id, version)` 是**每次读盘刷新**的快照
  （编辑器 promote 后同一目录版本号自动跟随，无需重新注册）。
- **空集合是合法状态**：允许注销到空；此时 `pool.list` 的 `ok=false` ＋ `issues[].code=EmptyPool`，开局必然失败并**特化说明**
  （不是笼统的"卡池装配失败"）。
- **沙盒固定包**（`<sandboxRoot>/pack`）**不进集合**、不受注册/注销影响，每局强制加入；清空它只能走 `sandbox.reset`。

## 3. 变更的合法性（不会出现"试算通过、开局失败"）

- 每次注册/注销：**先真对账 → 再用对账后的有效条目试算候选 → 通过才写入**；失败则**整体拒绝**，集合保持对账后的状态。
- 准入看 `fatal` 不看 `ok`：空集合（`ok=false`/`fatal=false`）允许写入；lock 冲突／环依赖／声明冲突（`fatal=true`）拒绝。
- 试算与开局装配**同一套实现**（`MatchCardAssembly.Inspect`），Server 层不解析 message、不复制冲突判定。
- 冲突响应的 `issues[].conflict` 给 `{kind, appId, firstPackageId, firstVersion, secondPackageId, secondVersion}`。
- **对账独立提交**：它一旦移除失效条目就生效，不随随后的变更被拒或开局失败而回滚，并单独发 `packset.reconciled`。

## 4. 用法建议（`pool.list` 是重操作）

`pool.list` **完整走一遍资产注册与分层计划**，且**不缓存**（不设 TTL、不留条目级缓存，只做单次调用的单飞合并）。
建议：**变更后查一次、开局前查一次**，**不要定时轮询**。

`pool.register`：
- 入参＝**绝对目录路径**（相对路径直接拒绝，不按进程 cwd 解析）；
- 只读该目录的 `manifest.json` 登记 `(id, version)`（+ 目录）；
- **不受可写根（`SandboxPathGuard`）约束**——它登记的是"要加载哪些包"，与"可写根"无关（资产库本来就在沙盒根外）；
- 沙盒固定包目录 ⇒ 明确拒绝（"每局强制加入…清空请用 `sandbox.reset`"），不静默幂等；
- 同一目录重复注册 ⇒ 幂等成功（`existed=true`/`added=[]`）；同一 (id, version) 换一个目录 ⇒ 失败并给 `details.existingDirectory`。

`pool.unregister`：入参＝**`packageId` ＋ `version`**（只给 id 不足以移除）；版本与当前快照不符 ⇒ `version-mismatch` ＋ `details.currentVersion`。

## 5. 入口与鉴权

| 能力 | 管理面 op | MCP 工具 |
| --- | --- | --- |
| `pool.list` | 有 | **两种模式都注册**（只读、角色不设限） |
| `pool.register` | 有 | **仅 sandbox**（`sandboxOnly` ＋ 写类门控 ＋ debug 角色 ＋ 回环来源） |
| `pool.unregister` | 有 | 同上 |

- play 实例的 `tools/list` **不含**写工具；`manager.admin` 可代发三个 op（管理器不解析、不缓存集合）。
- 轮换 drain 窗口：写操作被拒（`room-rotating`，说明为「房间正在轮换，卡包集合变更需等新 lobby 就绪后重试；`pool.list` 不受影响。」），
  `pool.list` **不受影响**（它不入队）。

## 6. 字段与脱敏（play vs sandbox）

`pool.list` 的载荷复用**同一个判定模型**（`ok`/`packages[]`/`issues[]`/`warnings[]`/`plan`）＋ 写操作的 `change` 段。
投影只有一处（`PoolProjection.Render`），管理面与工具面逐字段一致；差异只按**实例模式**：

| 字段 | play 实例（工具与 op 均然） | sandbox 实例 |
| --- | --- | --- |
| `packages[].directory` / `guid` / `error` | **不出现** | 出现（含绝对目录与自由文本） |
| `packages[]` | `packageId` / `version` / `ok` / `willRemove` / `errorCode` | 同上 ＋ `directory`/`guid`/`error` |
| `issues[]` | `{code, domain, appId, fatal, conflict?}` | 同上 ＋ `message`/`path[]` |
| `warnings[]` | 不出现（自由文本） | 出现 |
| `message` / `details` | 不出现（顶层 `message` 用固定短语） | 出现 |

> play 模式是**白名单**：以后新增任何自由文本字段默认不会泄露（漏的是"少给"而不是"多给"）。
> 客户端不要假设 play 与 sandbox 的字段集相同。

## 7. 两个集合侧事件（载荷均不含绝对目录）

```json
// packset.changed —— 写操作成功后发（失败不发）
{"added":[{"id":"...","version":"..."}],"removed":[...],"ok":true,"itemCount":3,"cardCount":12}

// packset.reconciled —— 真对账实际移除条目时发；未移除则不发
{"count":1,"removed":[{"packageId":"...","version":"...","cause":"directory-missing"}]}
```

`cause` 取值：`directory-missing` / `manifest-missing` / `manifest-invalid` / `kind-not-cardpack` / `io` / `id-changed` / `duplicate-key`。
（读目录 IO 失败在 `removed[]` 里记 `io`；同一场景在 `packages[].errorCode` 里仍是 `io-error`。）

## 8. 破坏性变更与迁移

1. **`match.start` 不再接受 `packDirectories`**：键出现即 `invalid-arguments`，message 含
   「卡池集合改由 `pool.register` / `pool.unregister` 管理；本参数已移除」。原"传空数组＝用实例默认池"的**静默回落已取消**。
2. **`instance.info.packDirectories` → `initialPackDirectories`**：语义变为"spawn 初值（历史信息）"，且剔除沙盒包路径；
   旧字段本体不保留，响应里给 `packDirectoriesRenamedTo: "initialPackDirectories"` 提示。
3. **新增**：三个 op、三个工具、`packages[].errorCode`（三种受众都有）、`packages[].willRemove`、`issues[].fatal`、判定结论的 `plan` 摘要。
4. **管理器**：`manager.admin` 无需改动即可代发 `pool.*`；`manager.spawn` 的 `packDirectories` **不再包含沙盒包路径**。

## 9. 开局路径（唯一真源）

- 本局输入＝**集合全部条目（注册序）＋ 合法沙盒固定包**，没有第二条路径。
- 装配前先做一次真对账（移除**保留**，不因本局后续失败回滚）；响应带
  `assemblyInput: { packages:[{id,version,directory}], sandboxIncluded, usedLastGood, sandboxDropped, reconciled }`。
  `packages[]` **只列集合条目**（按注册序）；沙盒固定包不在其中，由 `sandboxIncluded` 表达。
- 降级必须显式报告（非静默）：`usedLastGood`（按"最后一次成功输入"回退）、`sandboxDropped`（剔除沙盒包）；
  通道事件给同一信息但**不含目录**。
- 装配失败仍按「最后一次成功输入剔除沙盒包重试一次」降级（R9 不变）。
- 既有事件 `pool.assembled` / `pool.assemble.failed` 的名称与主体字段（含 `packages`＝本局目录列表）**零改动**；
  本轮只在载荷上**追加** `assembly`（无目录）与 `degradation` 两段。

## 10. 与既有交接文档的关系

- `docs/服务器管理器-长期生命周期/PROGRESS.md`（S10「卡池重装」）中 `sandbox.state.pool` 的语义**未变**：它仍报"本局装配结果"，
  集合是另一份状态，只经 `pool.list` 读取。
- `pool.assembled` / `pool.assemble.failed` 名称与主体语义零改动（仅新增 `degradation`/`assembly` 两个附加段，且不含目录）。
