## 1. 读者与前置

本库的**第一读者**是 DIY 作者：想做卡、不想改引擎。你只需要：

- 会读改 JSON；知道「事件/回调」是什么；能在命令行跑 `dotnet`。

## 3. 五段心智模型

一条效果的一生只有五段。每段都对应一个**你可以打断点/加日志**的符号。

### ① 装载：效果怎么挂上去（v4 现行）

> 本节已于 2026-10-28 按 v4 重写。旧链路 `Card.AddEffect → CardLoadout.MountEffect → Effect.ExecuteMount` 已随 `Effect` 删除。

`Card` 是薄容器，不持有效果列表。效果是**编排实体（`OrchestrationEntity`）上的组件实例**，由 `ComponentAttachment` 管理：

1. **构造**组件实体（`ComponentAttachment`）——填宿主引用（`owner.host` 可用）、初始化私有字段；
2. 判定 **`active-when`**（`loaded`＝在手即生效 / `placed`＝入场后装配，缺省 `placed`）；
3. **装配**（仅当命中时点）——`OrchestrationRuntime.Bind` 建立：成员声明边（`mounts`）＋ 包装边（`wraps`）＋ **框架注销边**（自动挂到 `card.destroyed`，位次恒最后，作者不能写）；
4. 之后成员才响应信号——**装配前不响应任何信号**（边尚未建立）。

> - **构造与装配分离**（R3i）：这是原「加载时构造 + 放置驱动装载」两套时点的收敛，不再有「装载完成动作」这一步。
> - **复装＝重建实例**：销毁后再次入场＝新建实例、私有字段复位；不存在「复用实例重跑初始化」。
> - **同一组件预制体在同一宿主上至多一份实例**：需要两份＝两个不同预制体。

### ② 触发：信号怎么找到 handler（v4 现行）

> 本节已于 2026-10-28 按 v4 重写。旧链路 `Bus` → `Trigger<TView>.InvokeAsync` → `RunEventsAsync`（`band×1000＋priority`）已随 `Bus`/`Trigger<TView>` 删除。

组件在 `mounts` 里声明「**哪个成员挂到哪个信号**」，信号名是成员地址 `engine#<信号>`：

```jsonc
"mounts": [ { "member": "onPlayed", "target": "engine#card.played" } ]
```

`LogicEngine` 发射该信号时，沿该成员的**边集合**执行（`OrchestrationEntity.RunEdgesAsync`，R1i）：

| 层 | 顺序 |
| --- | --- |
| 包装 | `before`（FIFO）→ 边集合（或被 `replace` 接管）→ `after`（FIFO）|
| 边集合（`first`，流程型默认）| **自有边**（`OwnedEdge`）→ 外来挂载边 |
| 边集合（`last`，管道型）| 外来挂载边 → **自有边** |
| 外来边内部 | 声明序 → 追加序 |
| 框架注销边 | 作为声明序边的一部分，位次恒最后 |

> **两处与旧模型的实质差异**，照旧文档调试会踩：
> 1. 排序键不再是 `band×1000＋priority`——band 概念整体退役，位次改由成员的 `OwnEdgePosition`（`first`/`last`）决定；
> 2. `before` 包装由旧模型的 **LIFO** 改为 **FIFO**（`src/Orc/Core/Model/OrchestrationEntity.cs` 类注释 R1i 与 `RunEdgesAsync` 为准）。
>
> 每个执行单元前检查停止：`ctx.Stop()` 只停**当前成员**剩余单元，已执行的 `before` 写入不回滚、不外溢。

### ③ 结算：handler 怎么改世界

handler 只做两件事：读视图/上下文 → 调**受控动作面**。`EffectRuntime` 是唯一游戏层门面（伤害、消灭、修饰、词条、抽牌、选靶、资源……），完整表见 [参考层 · api速查](./reference/api速查.md) §1；词条程序另有 32 个操作（同表 §4）。

### ④ 传播：数值怎么扩散

改数值不是「直接改字段」：动作面写入**修饰器**（`Modifiers`）→ 修饰机制集中重跑 → 有变化才发 `card.stat.changed`（载荷 `Card` + `ChangedFields`）→ 订阅者（守护、归零检查、你的效果）响应。**持续型加成**（光环）走 `DeclareAuraAsync`：受益方每次重跑时**现收集**，进场/离场自动随动。

### ⑤ 销毁：效果怎么收场（v4 现行）

> 本节已于 2026-10-28 按 v4 重写。旧链路 `Effect.ExecuteDispose` / `Bus.UnmountOwner` / `OnUnmount` 已随 `Effect` 删除。

唯一驱动是**框架注销边**（装配时自动挂到兜底信号，缺省 `card.destroyed`），执行的是「卸载」这一件事：

**逐句柄撤销**（该实例创建过的每条边——声明边、包装边、注销边——各有一份独立句柄，逐条精确撤销）→ **销毁组件实体** → 恰一次 `effect.removed`。

> - **没有 `OnUnmount` 需要你写**：撤销由框架按句柄完成；代码里也**不存在**「按来源扫某信号边表」的清理路径（旧按 owner 扫表的做法与多组件并发卸载不兼容）。
> - `disposal-signal` 可声明别的兜底信号（子 ?? 父 ?? 默认）；声明为 `effect.removed` ＝装载期拒绝（防自触发递归）。
> - 重复卸载＝空转（不抛、不重发）。

## 4. 最小可加载卡骨架

### 4.1 文件怎么放

```
my-card-pack/
├── cards/
│   └── diy.example.grenadier.card.json
└── effects/                  # 可选：被 cards 的 "prefabs": ["..."] 引用
    └── diy.example.grenade.prefab.json
```

- 卡文件名约定 `*.card.json`；效果库文件名 `*.prefab.json`（v4 组件资产用 `*.component.json`）。
- 内联效果（`effects.inline`）不需要单独文件——**单文件自包含**，推荐新手用。

### 4.2 可直接落盘的卡（已预检 0 error）

```json
{
  "schemaVersion": 1,
  "id": "diy.example.grenadier",
  "name": "示例掷弹兵",
  "components": [
    { "component": "typeCategory", "type": ["infantry"] },
    { "component": "factionCost", "faction": "Germany", "kredits": 1 },
    { "component": "battleStats", "operationCost": 1, "attack": 2, "defense": 3 },
    { "component": "tagData", "rarity": "Standard" },
    {
      "component": "effects",
      "inline": [
        {
          "schemaVersion": 3,
          "root": {
            "id": "diy.example.grenade",
            "version": 1,
            "mainTrigger": {
              "id": "t.main",
              "stableKey": "示例·部署伤害",
              "kind": "passive",
              "viewType": "Orc.Cards.CardEventView",
              "hooks": ["unit.deployed"],
              "events": [
                {
                  "id": "onUnitDeployed",
                  "entry": "HandleAsync",
                  "csx": "Func<Orc.Cards.CardEventView, Context, CancellationToken, Task> HandleAsync = async (view, ctx, ct) =>\n{\n    if (view.Unit is not Orc.Cards.Card deployed || !object.ReferenceEquals(deployed, view.Host))\n    {\n        return;\n    }\n\n    var runtime = Orc.Game.Effects.EffectRuntime.ResolveFor(deployed);\n    if (runtime is null)\n    {\n        return;\n    }\n\n    var targets = await runtime.SelectAsync(deployed, new Orc.Game.Effects.EffectSelector(\"one\", \"enemy\", null, null, null, null, null));\n    foreach (var target in targets)\n    {\n        await runtime.DamageAsync(target, 1, deployed, ct);\n    }\n};\n",
                  "version": 1
                }
              ],
              "version": 1
            },
            "otherTriggers": [],
            "wrappers": [],
            "injects": []
          }
        }
      ]
    }
  ]
}
```

**它在做什么**：本单位部署（`unit.deployed`）→ `view.Host` 过滤（只响应自己）→ 无头选一个敌方单位 → 造成 1 点伤害（`Source` 传本卡）。

### 4.3 六个组件（`components[].component` 的取值）

| 组件名 | 必填字段 | 说明 |
| --- | --- | --- |
| `typeCategory` | `type: string[]` | 类别词 `order`/`countermeasure`（至多一个且独占）＋兵种词（可多） |
| `factionCost` | `faction`, `kredits` | 阵营标识＋部署费；定义期必填槽位 |
| `battleStats` | `operationCost`, `attack`, `defense` | 仅单位卡 |
| `tagData` | `rarity` | 稀有度；可选 `tags` |
| `keywords` | `attributes: string[]` | 词条声明行（如 `"重甲3"`）；可选 |
| `effects` | `prefabs?: string[]`, `inline?: object[]` | 引用库内预制体 / 内联快照 |

> `id` 与 `name` 是根级必填；`schemaVersion` 必须为 `1`（卡数据）。读入宽（大小写不敏感、容忍注释与尾逗号），**写窄**（固定键序）。

## 5. 「装载≠触发」「注册≠生效」

| 说法 | 真实含义 | 典型症状 |
| --- | --- | --- |
| 装载 ≠ 触发 | 装载只是把触发器挂上总线；**信号不来，handler 永不执行** | 效果「装上了」但从不生效——hooks 写错/信号没发 |
| 注册 ≠ 生效 | 注册只是进事件表；**band/优先级/条件/归属过滤**任一不满足都可能空转 | handler 进了但提前 return（`view.Host` 不匹配等） |

自查顺序：**装载成功？→ 信号到了？→ handler 被选中？→ 条件通过？→ 动作面返回值？**

## 6. 来源两面：`Source` 与 `TriggerCard`

这是全库最容易混的一对概念，**不可合并**：

- **`Source`**＝这条事件**是谁引发的** —— 信号载荷键，**发射时确定、只读、可空**。用来判归属（「敌方弃牌」「敌方指令」）。
- **`TriggerCard`**＝当前这段 handler **由谁触发** —— 执行帧值，**逐事件解析**；卡/效果注册的 handler 覆盖为注册者的卡，非卡注册原样继承，**链上最后者胜**。handler 内再发信号时，把它作为新信号的 `Source` 往下传。

```
发射方                                    执行方
Emit*(..., source: S)  ──►  载荷 Source = S（恒写，可空）
                                      │
                                      ▼
                            Trigger.InvokeAsync
                        帧初值 = 载荷 TriggerCard ?? 父帧
                                      │
                     每个事件前：帧值 = 该注册项 SourceCard ?? 继承
                                      │
                                      ▼
                    handler：view.Source（事件引发者）
                             view.TriggerCard（当前触发者）
                                      │
                        再发信号：source: view.TriggerCard
```

三条读法：

| 我要判断 | 读哪个 | 例 |
| --- | --- | --- |
| 这次弃牌是不是敌方造成的 | `view.Source` | `view.Source` 的归属玩家 ≠ 自己 |
| 这段 handler 是不是我这张卡触发的 | `view.TriggerCard` | `ReferenceEquals(view.TriggerCard, Host)` |
| 我要把「谁害的」继续传下去 | 再发信号的 `source:` | `EmitCardDiscarded(..., source: view.TriggerCard)` |

> 现状提醒：`Source` 是否非空取决于**发射方**是否传了 source。逐信号现状见 [参考层 · 信号表](./reference/信号表.md) §7。
