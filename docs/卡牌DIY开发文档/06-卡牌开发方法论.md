## 1. 五步流程

```
① 文本归类 → ② 选承载 → ③ 选触发点 → ④ 选动作面 → ⑤ 自检
```

| 步 | 你要回答 | 判据 | 常见错误 |
| --- | --- | --- | --- |
| ① 归类 | 这句是「持续 / 触发 / 施放 / 替换 / 反制」哪一类？ | 有没有「当…时」＝触发；「始终/每有…就」＝持续；「使用后」＝施放；「改为/改为由…」＝替换；「敌方使用…时」＝反制 | 把持续写成触发（重复计数、离场不退） |
| ② 承载 | 词条程序 / 效果预制体 / 判定器 / wrapper / C# 效果？ | 能用既有词条表达的先用词条；能监听信号＋调动作面的用预制体；要改规则/流程才上代码 | 一上来写 C# |
| ③ 触发点 | 哪个信号？没有信号就找扩展位 | 查 [信号表](./reference/信号表.md)；旧 schema 的 `hooks` / v4 的 `mounts[].target` 必须写**真实存在**的信号名 | 用 `card.destroyed` 当死亡 |
| ④ 动作面 | 用哪个 `EffectRuntime` 方法？ | 查 [api速查](./reference/api速查.md) §1；返回 false/0 要处理 | 直接改攻防字段 |
| ⑤ 自检 | 幂等/重入/归属/离场/失败 | 用 §5 清单逐项过 | 只在「正常路径」手测 |

## 2. 何时用哪条承载

| 承载 | 适用 | 不适用 | 证据 |
| --- | --- | --- | --- |
| 词条（内置） | 行为已被引擎实现（闪击/奋战/重甲/守护/冲击…） | 需要新行为 | 声明 `keywords.attributes` |
| 词条程序 | 事件驱动的简单行为 + 规则点补丁，且可接受 JSON 表达能力 | 需要新 API/复杂时序 | `KeywordProgram.Parse` 通过 |
| 效果预制体 + csx | 监听信号 → 调动作面；条件分支；选靶 | 需要改判定/流程 | `PrefabJson.Deserialize` 通过 |
| 判定器/wrapper | 改「能不能/算多少」 | 做「发生什么」 | 代码侧注册 |
| C# 效果 | 需要状态、复杂时序、跨卡协作 | 一次性简单效果 | `dotnet test` 用例 |

## 3. 卡面 → 机制映射表（15 类）

> 「路径」列：**数据侧**＝`*.card.json`/`*.prefab.json`/csx 可完成；**代码侧**＝必须写 C#；**混合**＝数据为主、需一次性代码注册。

| # | 卡面句式 | 承载 | 触发点 | 动作面 | 路径 |
| --- | --- | --- | --- | --- | --- |
| 1 | 部署时，对敌方一个单位造成 1 点伤害 | 效果预制体 + csx | `unit.deployed`（`view.Host` 过滤） | `SelectAsync` + `DamageAsync` | 数据侧 |
| 2 | 打出时抽 1 张牌 | 效果预制体 + csx | `card.played`（`view.Card` ＝ 本卡） | `DrawAsync` | 数据侧 |
| 3 | 本回合 +2 攻击 | 效果预制体 + csx | `unit.deployed` / `card.played` | `BuffAsync(..., EffectDuration.TurnEnd, ...)` | 数据侧 |
| 4 | 所有友方步兵 +1 攻击（持续） | C# 声明（`PrefabDefinition`：成员 `onDeployed` 声明光环） | `unit.deployed` 或装配即声明 | `DeclareAuraAsync` | 代码侧 |
| 5 | 每有一个敌方轰炸机，本单位 +1 攻击 | C# 效果 + 状态 | `unit.deployed` / `card.died`（重算） | `BuffAsync` / 重建光环 | 代码侧 |
| 6 | 敌方弃牌时，从卡组抽取此牌 | 效果预制体 + csx | `card.discarded`（读 `view.Source` 判敌方） | `FetchFromDeckAsync` | 数据侧 |
| 7 | 友方单位死亡时，本方总部回复 1 | 效果预制体 + csx | `card.died` | `BuffAsync(hq, 0, 1, ...)`（HQ 走 `HqHealth`） | 数据侧 |
| 8 | 单位行动后回到手牌 | 效果预制体 + csx | `unit.acted` | `AddToHandAsync` | 数据侧 |
| 9 | 随机对敌方单位分配 3 点伤害 | 效果预制体 + csx | 任意触发信号 | `SelectAsync("random")` ×3 + `DamageAsync` | 数据侧 |
| 10 | 使该单位无法被指令指向 | 词条程序（`targeting.forbid`） | 规则点（非信号） | 判定器通道（无作者动作） | 混合（程序 JSON ＋ `ProgramKeywordComponent.Register`） |
| 11 | 重甲 1 / 免疫 / 隐蔽 / 守护 | 词条（内置） | 内建判定/伤害改写 | 无（内建行为） | 数据侧（声明即可） |
| 12 | 亡计：死亡时对敌方总部造成 2 点伤害 | 词条「亡计」＋ 内容效果 | 死亡流程「亡计结算」步 | `DamageAsync` | 代码侧（内容须 C# 授予） |
| 13 | 升为老兵 / 老兵卡 | 词条「老兵」＋ `BecomesVeteran:<id>` | 升级动作 | `UpgradeAsync`（或升级入口） | 数据侧（声明） |
| 14 | 敌方使用第二张指令时将其反制 | C# 效果 + 流程 band | `OrderFlowBands.Counter`（`OrderFlow`） | `ctx.Stop()`（默认）/ `ctx.Interrupt()`（可选，牌留手不扣费） | 代码侧（P4 起原生指令卡同样可被反制，见 08） |
| 15 | 被揭示时，对敌方总部造成 1 点伤害 | 效果预制体 + csx | `unit.revealed` | `DamageAsync` | 数据侧 |

> 数据侧只能监听**已发射**的信号；「被攻击时」等尚无信号的时机见 [08-能力边界](./08-能力边界.md)。

## 4. 反例：选错会怎样（5 个）

### 反例 1：用 `card.destroyed` 当「死亡」

```text
错：hooks: ["card.destroyed"] → 「本单位死亡时…」
症状：弃牌、爆牌、手牌处置也会触发；count 偏大；亡语在非战斗场景乱放。
后果：规则错误且难复现（取决于是否有弃牌）。
正解：hooks: ["card.died"]（游戏层死亡；载荷 { Card, Killer, Source }）。
排查树：01 §5 分支 2（信号发错）。
```

### 反例 2：用 `TriggerCard` 判「敌方所为」

```text
错：if (!ReferenceEquals(view.TriggerCard, Host)) { /* 敌方所致 */ }
症状：监听者以自己为注册者时 TriggerCard 恒为自己，条件永假/永真。
后果：R6e「敌方弃牌」永远不触发，或己方弃牌误触发。
正解：读 view.Source（事件引发者），再用归属比较；TriggerCard 只用于「当前 handler 是谁触发的」。
排查树：01 §5 分支 4（归属过滤）。
```

### 反例 3：部署信号用 `view.Card` 过滤

```text
错：if (view.Card is not Card unit || !ReferenceEquals(unit, view.Host)) return;  // 监听 unit.deployed
症状：永不触发——unit.deployed 的载荷键是 Unit，不是 Card。
后果：部署效果静默失效。
正解：用 view.Unit（或 CardEventView 的 Unit 键）；`card.placed`/`card.played` 才是 Card 键。
排查树：01 §5 分支 2/4。
```

### 反例 4：在共享流程上无条件下 `ctx.Stop()`

```text
错：挂到 engine#unit-attack 的成员里，一进来就 Stop，再处理自己的逻辑。
症状：同边集合后续单元（含默认伤害结算）全部跳过，攻击不结算。
后果：其它卡的效果被连带打断（跨卡污染）。
正解：只在满足条件时 Stop/Interrupt；或改用 wraps 的 after 相位（不截断默认流程）。
排查树：01 §5 分支 3（被截断）。
```

### 反例 5：直接改攻防字段

```text
错：unit.GetData<...>().Attack += 1;（或直接改 Modifiers 底层字段）
症状：守护/归零检查看不到变化；card.stat.changed 不发；离场不撤销。
后果：数值与规则面脱节，出现「看着 +1 但规则不认」。
正解：BuffAsync（一次性/有期限）或 DeclareAuraAsync（持续、集合随动）。
排查树：01 §5 分支 8（变化未传播）。
```

## 5. 交付前自检清单（14 项）

- [ ] 1. 触发点写的是 [信号表](./reference/信号表.md) 里真实存在的信号名（拼写/层级正确）
- [ ] 2. 载荷键用对：`unit.*` 读 `Unit`，`card.*` 读 `Card`，只有玩家的信号读 `Player`
- [ ] 3. 归属过滤用 `Host`/`TriggerCard` 判自身，用 `Source` 判引发者（两者不混用）
- [ ] 4. 归因场景确认 `Source` 现状（可能是 null）→ 有替代键就用替代键
- [ ] 5. 一个效果只做一件事；多效果拆多个事件/预制体
- [ ] 6. 幂等：重复触发/重复装载不产生叠加（尤其修饰与计数）
- [ ] 7. 重入：handler 内再发同类信号是否会自激；必要时加守卫
- [ ] 8. 失败分支：动作返回 `false`/`0`/空集时显式处理（不是「当成功」）
- [ ] 9. 目标合法性：`SelectAsync` 空集、targeter 取消都按零副作用处理
- [ ] 10. 离场/销毁：持续效果靠框架逐句柄撤销，**没有 `OnUnmount` 可写**；不依赖 `card.destroyed` 做业务
- [ ] 11. 旧 schema 限制：`injects.band` 只能填目标触发器 band 方案的成员（P3 起可用，否则隔离）；事件 `band` 只能用 `"default"` / `"disposing"`。**v4 资产改用 `wraps[].phase`／`mounts[].target`**（旧字段名会被拒绝装载）
- [ ] 12. 数值走动作面（`BuffAsync`/`DeclareAuraAsync`/`DamageAsync`），不直改字段
- [ ] 13. 证据：数据侧过 `CardDistributionValidator`；代码侧有 `dotnet test --filter` 用例
- [ ] 14. 文档化：卡面文本、触发点、动作面、已知边界四处写清（供他人复现）

## 6. 最小片段：从卡面到可加载效果

卡面：「打出时抽 1 张牌」。选型：数据侧 → 效果预制体 + csx → `card.played` → `DrawAsync`。

```json
{
  "schemaVersion": 3,
  "root": {
    "id": "diy.play.draw",
    "version": 1,
    "oneShot": false,
    "mainTrigger": {
      "id": "t.main",
      "stableKey": "diy.play.draw",
      "kind": "passive",
      "viewType": "Orc.Cards.CardEventView",
      "hooks": ["card.played"],
      "events": [
        {
          "id": "onPlayed",
          "entry": "HandleAsync",
          "csx": "Func<Orc.Cards.CardEventView, Context, CancellationToken, Task> HandleAsync = async (view, ctx, ct) =>\n{\n    if (view.Card is not Orc.Cards.Card played || !object.ReferenceEquals(played, view.Host))\n    {\n        return;\n    }\n\n    var runtime = Orc.Game.Effects.EffectRuntime.ResolveFor(played);\n    if (runtime is null)\n    {\n        return;\n    }\n\n    await runtime.DrawAsync(played, 1, ct, played);\n};\n",
          "version": 1
        }
      ],
      "version": 1
    },
    "otherTriggers": [],
    "wrappers": [],
    "injects": []
  }
}
```

把它放进卡的 `effects.inline`（或 `effects.prefabs` 引用库文件）即可；结构校验：

```csharp
var snapshot = PrefabJson.Deserialize(json);   // 失败＝FormatException（不静默）
```

> 注意：`card.played` 对所有打出都发射；`view.Host` 过滤是「只响应本卡」的关键。漏掉它＝全场打出都抽牌。
