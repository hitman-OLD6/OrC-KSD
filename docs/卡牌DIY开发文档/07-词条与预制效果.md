## 1. 词条是什么

词条＝**卡上的独立组件**（`KeywordComponent`）：自含数据（含参值）＋运行逻辑＋授予/移除回调＋可内嵌效果。

| 环节 | 符号 | 说明 |
| --- | --- | --- |
| 标识常量 | `KeywordIds` | 19 个固定字面值（对外数据契约） |
| 注册面 | `KeywordRegistry.Register(id, factory, isBattleKeyword)` | 标识 → 组件工厂；「注册即配置」、重复拒绝 |
| 卡上面 | `CardBase.Keywords`（`KeywordManager`） | `Has` / `GetValue` / `TryGetComponent` |
| 静态读口 | `KeywordRules.HasKeyword` / `GetKeywordValue` | 无需拿管理器；无词条面＝false/null、不抛 |
| 装载链 | `CardBase.LoadAsync` 词条步骤 | 存在性置位 → 运行逻辑＋内嵌效果 → `OnGrant`（先于 `card.load`） |
| 对战词条池 | `KeywordRegistry.BattleKeywordUniverse` | 「已实现且打标」的标识全集 |
| 池读取 | `BattleKeywordRules.GetBattleKeywords` / `CountBattleKeywords` / `HasAtLeastBattleKeywords` | 按卡现势筛选 |

> 数据侧通过 `*.card.json` 的 `keywords.attributes`（字符串数组）声明词条；**新增词条**（新标识或新组件）必须代码侧注册。

## 3. 词条程序（`KeywordProgram`）

### 3.1 结构与装配

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schema` | int | 必须为 `1` |
| `defaultValue` | int | 未提供参值时 `value` 的取值（0..10000，默认 1） |
| `state` | `Dictionary<string,int>` | 实例级命名状态（≤64 项；名字限字母/数字/`_`/`.`/`-`） |
| `rules` | `KeywordRulePatch[]` | 规则点补丁（≤64） |
| `handlers` | `KeywordEventHandler[]` | 事件处理（≤64） |
| `skills` | `KeywordActiveSkill[]` | 主动技能（≤16） |

装配＝**代码侧一次性注册**（词条标识 + 程序体）：

```csharp
using Orc.Game.Cards;

var program = KeywordProgram.Parse(json);                  // 校验失败＝InvalidDataException
ProgramKeywordComponent.Register("diy.deploy.ping", program); // 注册为可声明词条（isBattleKeyword 可选）
```

之后卡数据里 `keywords.attributes: ["diy.deploy.ping"]` 即可授予。

### 3.2 规则点（`RuleNames`，11 条）

| 规则点 | 作用 |
| --- | --- |
| `move.allowed` | 是否可移动 |
| `move.retreat` | 是否可撤退 |
| `attack.allowed` | 是否可攻击 |
| `combat.range` | 射程覆盖值 |
| `combat.counter.eligibility` | 反击资格 |
| `combat.guard.eligibility` | 被守护攻击资格 |
| `combat.interception` | 轰炸机拦截 |
| `combat.ambush.condition` | 伏击条件 |
| `deploy.frontline` | 部署到前线的资格 |
| `attack.limit` | 攻击次数上限 |
| `targeting.forbid` | 禁止被指定来源指向（`source`：`any`/`command`/`unit-effect`） |

规则补丁的作用范围（`scope`）：`self` / `linked` / `pair` / `friendly` / `enemy` / `all`。

### 3.3 事件（`EventNames`，17 条）

`unit.acted`、`turn.start.before`、`turn.end.before`、`card.played`、`unit.deployed`、`unit.joined`、`card.placed`、`turn.start`、`turn.end`、`card.damaged`、`card.dying`、`card.leaving`、`unit.attack.before`、`unit.attack.after`、`unit.destroy.before`、`keyword.ready`、`keyword.consumed`。

监听对象（`subject`）：`self` / `friendly` / `enemy` / `any` / `owner` / `opponent`。

> 词条程序的事件表与总线信号**不完全同名**（如 `unit.attack.before` 是词条内部相位，不是 `GameUpdates` 信号）。写程序时只认这 17 个名字。

### 3.4 操作（`Operations`，32 条）

| 操作 | 含义 | 操作 | 含义 |
| --- | --- | --- | --- |
| `state.set` | 置状态值 | `state.add` | 状态值加减 |
| `capture` | 记录数值到 `data.*` | `link` | 关联一个单位 |
| `unlink` | 解除关联 | `move.set` | 置可移动 |
| `attack.set` | 置可攻击 | `attack` | 效果发起攻击（`bypassRange` 可跳过射程） |
| `replace` | 替换入场 | `retreat` | 撤退到己方支援线空槽 |
| `damage` | 造成伤害 | `buff` | 攻防修饰（`temporary` 到期清理） |
| `stat.add` | 属性增减（`key`＝attack/defense/opCost/deployCost/hqHealth） | `stat.set` | 属性设定 |
| `heal` | 修复防御 | `kill` | 消灭（走死亡链） |
| `keyword.grant` | 授予词条 | `keyword.remove` | 撤销词条 |
| `emit` | 发词条事件（仅 `keyword.ready`/`keyword.consumed`） | `death.cancel` | 取消死亡 |
| `health.set` | 置剩余防御 | `copy.hand` | 复制卡入手 |
| `return.hand` | 回手 | `create.hand` | 新建卡入手 |
| `develop` | 部署（须给 `cards` 关联卡池） | `move` | 移动 |
| `draw` | 抽牌 | `points` | 点数增减 |
| `attach.prefab` | 挂预制体效果 | `targeting.forbid` | 禁止被指向 |
| `targeting.allow` | 解除禁止 | `if` | 条件分支（`when` → `then` / `else`） |

### 3.5 目标（`Targets`，14 条）

`self`（宿主）、`event`（事件单位）、`linked`（关联单位）、`attack.target`（攻击目标）、`enemy.hq` / `friendly.hq`、`enemy.units` / `friendly.units`、`enemy.frontline` / `friendly.frontline`、`random.enemy.frontline`、`choose.unit` / `choose.enemy.unit` / `choose.friendly.unit`（交互选择）。

### 3.6 数值表达式白名单（`Number` 校验）

| 类别 | 允许值 |
| --- | --- |
| 整数字面量 | `-10000..10000` |
| 宿主/进程量 | `value`（参值，缺省 `defaultValue`）、`entries`、`attacks`、`linked.alive` |
| 目标属性 | `target.attack`、`target.defense`、`target.cost`、`target.opCost` |
| 事件单位属性 | `event.attack`、`event.defense`、`event.cost`、`event.opCost` |
| 状态 | `state.<已声明状态名>` |
| 实例记录 | `data.<记录名>`（`capture` 写入；缺记录＝运行期 `InvalidOperationException`） |

比较算子（`when`）：`eq` / `ne` / `gt` / `gte` / `lt` / `lte`（条件 ≤16 条）。

### 3.7 校验与限制（`KeywordProgram.Validate`）

- JSON ≤ 250 KB；未声明字段＝拒绝（`UnmappedMemberHandling.Disallow`）。
- 数量上限：`state` 64、`rules` 64、`handlers` 64、`skills` 16、条件 16、动作 64、动作嵌套 8、`bindings` 32、`cards` 64。
- `emit` 只能发 `keyword.ready` / `keyword.consumed`（不允许伪造引擎事件）。
- `stat.add/stat.set` 的 `key` 只能是 `attack`/`defense`/`opCost`/`deployCost`/`hqHealth`。
- `targeting.forbid/allow` 的 `key` 只能是 `any`/`command`/`unit-effect`。
- `develop` 必须给非空 `cards`；主动技能 `id` 不得重复。

> **归因限制**：词条程序的事件处理走 `engine.Subscribe`（`ProgramKeywordComponent.Mount`），**没有执行帧**——拿不到 `TriggerCard`，只能读载荷 `Source`。需要 `TriggerCard` 时改用 csx/触发器路径。

## 4. 预制效果（`EffectSnapshot` 三层）

### 4.1 三层结构

```
EffectSnapshot（效果预制体，schemaVersion 3）
└── EffectPrefab（root：id/version/oneShot/mainTrigger/otherTriggers/wrappers/injects/disposingTrigger）
    └── TriggerPrefab（触发器：id/stableKey/kind/viewType/hooks/events/version）
        └── EventPrefab（事件：id/entry/csx/assemblyKey/downstream/seams/band/version）
```

### 4.2 字段表

**触发器预制体**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 触发器 id |
| `stableKey` | 否 | 稳定键（审查/引用） |
| `kind` | 否 | `passive`（默认）/`active` |
| `viewType` | 否 | 默认 `Orc.Cards.CardEventView`；必须是可解析的视图类型 |
| `hooks` | 被动必填 | 订阅的信号名（≥1，否则不可挂载） |
| `events` | 是 | 事件数组（不得缺失） |

**事件预制体**

| 字段 | 说明 |
| --- | --- |
| `id` | 事件 id（包装器 `target` 引用它） |
| `entry` | 脚本入口变量名（默认 `HandleAsync`） |
| `csx` / `assemblyKey` | 二选一：内联脚本 / 已注册处理器键 |
| `downstream` | 静态下游声明（审查用，不改行为） |
| `seams` | 本事件声明的动作缝名 |
| `band` | 只接受 `"default"` / `"disposing"`（保留槽）；其它值＝构造期 `ArgumentException`（不能指向自定义 band 方案，见 08 G-08） |
| `version` | 事件版本（缺省 1） |

**`injects`（把本效果的事件注入宿主触发器）**

| 字段 | 说明 |
| --- | --- |
| `target` | 宿主具名触发器名（如 `部署触发器`）；宿主未登记则回退对局级注册表 |
| `band` | 目标触发器带专门 band 方案时填其成员名（如 `Counter` / `Resolve`）；空＝默认区段。目标无专门方案、或名不是成员＝隔离记录（G-03 已解决，P3） |
| `event` | 本效果内的事件 id（必须有 handler） |
| `priority` | 注入后的 band 内优先级 |

**`wrappers[]`（预制体声明包装器）**

| 字段 | 说明 |
| --- | --- |
| `phase` | `before` / `after` / `replace` |
| `target` | 主触发器内的事件 id |
| `seam` | 缝名（仅 `before` 用；拼错＝运行期 `KeyNotFoundException`） |
| `handler` | 事件预制体形态（`id`/`entry`/`csx`/`assemblyKey`） |

### 4.3 最小可校验预制体

```json
{
  "schemaVersion": 3,
  "root": {
    "id": "diy.minimal",
    "version": 1,
    "oneShot": false,
    "mainTrigger": {
      "id": "t.main",
      "stableKey": "diy.minimal.deploy",
      "kind": "passive",
      "viewType": "Orc.Cards.CardEventView",
      "hooks": ["unit.deployed"],
      "events": [
        { "id": "onDeployed", "entry": "HandleAsync", "assemblyKey": "diy.deploy.handler", "version": 1 }
      ],
      "version": 1
    },
    "otherTriggers": [],
    "wrappers": [],
    "injects": [],
    "disposingTrigger": null
  }
}
```

```csharp
var snapshot = PrefabJson.Deserialize(json); // 本段已实测通过；失败＝FormatException
```

> `schemaVersion`：读入接受 **2 或 3**（2 会按默认补齐 `disposingTrigger`/`oneShot`/`band`），写出恒为 **3**。

## 5. 模板效果 / 效果 DSL / 效果预制体（三层对照）

| 层 | 制品 | 谁写 | 谁消费 | 说明 |
| --- | --- | --- | --- | --- |
| 模板效果 | `*.tpl.json`（`EffectTemplate`） | 机制作者/工具链 | `EffectParser` | 把卡面句式映射成 DSL 片段；`EffectTemplateLoader` 扫描加载 |
| 效果 DSL | `DslEffectInstance`（内存） | 解析器（由卡面文本生成） | `EffectCompiler.Compile(dsl, effectId, version)` | 解析与编译之间的中间层；`OpTemplateCatalog`（`*.csx.tpl`）提供每个 op 的 csx 片段 |
| 效果预制体 | `EffectSnapshot` / `*.prefab.json` | 手写或编译产物 | `PrefabManager` / 卡数据 `effects` | **运行期唯一形态**；可注册库、可内联 |

```
卡面文本 ──EffectParser（模板效果 + op 模板）──► DslEffectInstance
        ──EffectCompiler──► EffectSnapshot ──PrefabJson.Serialize──► *.prefab.json
```

适用者：

- **只做卡**：只写第 3 层（`*.prefab.json` 或内联），不需要模板/DSL。
- **要批量把卡面文本转效果**：用 `EffectCompilationDriver`（模板 + DSL + 编译，产物是预制体 JSON）。
- **要新增句式**：写模板效果（`*.tpl.json`）与 op 模板（`*.csx.tpl`），属工具链侧。

## 6. 词条程序 vs csx：同一行为的两种写法

| 维度 | 词条程序 | csx 效果 |
| --- | --- | --- |
| 载体 | JSON（`KeywordProgram`） | 脚本文本（事件 `csx`） |
| 装配 | 代码侧 `ProgramKeywordComponent.Register(id, program)` ＋ 卡上声明标识 | 预制体事件内联，随效果装载编译 |
| 能改规则 | **能**（`rules` 11 个规则点） | **不能**（改规则要 wrapper/判定器） |
| 能做的动作 | 32 个固定操作 | 任意 `EffectRuntime` 调用 + C# 逻辑 |
| 校验 | 装载期强校验（白名单/数量/字段） | 编译期 + 运行期 |
| 归因 | 只有载荷 `Source`（无 `TriggerCard`） | 有 `view.Source` + `view.TriggerCard` |
| 适合 | 事件驱动的小行为、规则补丁、主动技能 | 复杂时序、跨卡状态、需要精确归因 |

**同一行为：部署时抽 1 张牌**

写法 A · 词条程序（JSON，已实测 `KeywordProgram.Parse` 通过）：

```json
{
  "schema": 1,
  "handlers": [
    {
      "event": "unit.deployed",
      "subject": "self",
      "actions": [
        { "op": "draw", "target": "self", "value": "1" }
      ]
    }
  ]
}
```

```csharp
ProgramKeywordComponent.Register("diy.deploy.draw", KeywordProgram.Parse(json));
// 卡数据：keywords.attributes: ["diy.deploy.draw"]
```

写法 B · csx 效果（预制体事件，挂在 `unit.deployed`）：


两版的差异：

| 维度 | 写法 A（词条程序） | 写法 B（csx） |
| --- | --- | --- |
| 归属过滤 | `subject: "self"`（引擎按主体筛） | 手写 `view.Host` 比较 |
| 抽牌对象 | `target: "self"` | `DrawAsync(unit, ...)` |
| 前置成本 | 需一次代码注册（`ProgramKeywordComponent.Register`） | 无需注册，随卡数据装载 |
| 可校验性 | 装载期强校验（字段/数值/数量） | 编译期 + 运行期 |
| 扩展性 | 只能用 32 个操作 | 任意 `EffectRuntime` + C# |

> 选 A 的前提是「行为能被 32 个操作完整表达」。一旦需要循环、复杂条件组合或自定义 API，选 B。

**怎么选**：

- 行为能用「17 事件 + 32 操作 + 数值白名单」表达，且不需要 `TriggerCard` → 词条程序（可校验、可读、无编译）。
- 需要条件组合之外的 C# 逻辑、精确归因、跨卡状态、规则改写之外的流程控制 → csx 效果。
- 需要**改规则**（能不能移动/攻击/被指向）→ 词条程序的 `rules`，或代码侧判定器/wrapper（csx 做不到）。
