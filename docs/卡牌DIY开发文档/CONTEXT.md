# 卡牌 DIY 开发文档 · 上下文

本上下文服务于 `docs/卡牌DIY开发文档/`：界定「卡牌 DIY 创作」这一视角下的称谓，避免与引擎内核/游戏层既有术语冲突。通用术语一律引用仓库根 `CONTEXT.md`，此处只登记本视角新增或易混的称谓。

## Language

**DIY 作者**：
用本引擎制作卡牌、但不修改引擎源码的创作者；其产出是分发数据（卡数据体 + 效果预制体 + csx）与最小的装配代码。
_Avoid_: 玩家、MOD 作者、内容作者

**数据侧**：
以 `*.card.json`、`*.prefab.json` 与内联 csx 承载效果、不需要新增 C# 类型的创作路径。
_Avoid_: 配置侧、无代码方案、纯 JSON 方案

**代码侧**：
以 C# 声明（`PrefabDefinition` ＋ `MemberEdges.For<TView>`、`Judicator` 子类、`wraps`／`judge-wraps` 声明、装配期注册）承载行为的创作路径。
_Avoid_: 原生侧、引擎侧、硬编码、`Effect` 子类（该类型已删除）

**装配（原「装载链」）**：
宿主加载/入场时把一个组件实例挂上引擎的固定顺序：构造组件实体 → 判定 `active-when` → `Bind` 建立声明边／包装边／框架注销边 → 此后才响应信号。
_Avoid_: 装载链（旧模型用语）、初始化流程、注册流程

**触发点（信号）**：
引擎发射的一个具名信号（如 `unit.deployed`、`card.discarded`），是成员被执行的唯一入口；「哪个信号」等于「何时生效」。组件用 `mounts[].target = "engine#<信号>"` 挂上去。
_Avoid_: 事件名、hook 名（hook 是旧 schema 的字段名 `hooks`，v4 已由 `mounts` 取代）、总线（`Bus` 已删除）

**动作面**：
handler 内可调用的受控状态变更入口集合（`EffectRuntime` 的方法 + 词条程序操作）。
_Avoid_: API、工具函数、副作用接口

**词条程序**：
以 JSON 声明、由 `KeywordProgramComponent` 解释执行的词条行为体（规则补丁 + 事件处理器 + 主动技能），不经 csx 编译。
_Avoid_: 词条脚本、词条 DSL（DSL 专指效果解析器的中间层）

**战斗（Battle）**：
让两个单位各自以攻击力对对方造成伤害的动作；无视射程/守护/烟幕/拦截/伏击/反击资格，不付行动代价。
_Avoid_: 对战、交战、攻击（三者均指 `unit.attack` 流程）

**指挥对战**：
经 `unit.attack` 流程的一次攻击：合法性判定 → 反击资格 → 伏击改写 → 伤害结算；与「战斗」是两种不同动作。
_Avoid_: 战斗、对拼

**伤害触发端**：
按伤害来源语义划分的三路入口（`combat.damage` / `effect.damage` / `battle.damage`）；只负责改写伤害量与条件，不扣数值。
_Avoid_: 伤害类型、伤害通道

**伤害处理端**：
唯一的「对卡牌造成伤害」层（`damage.apply`）：所有触发端汇聚于此，只有它调用数值门户；免疫等全局改写挂在这里。
_Avoid_: 伤害结算、伤害入口

**预制效果**：
两种形态并存：(1) **v4 组件资产**（`*.component.json`，schemaVersion 4）——运行期统一形态，成员 ＋ `mounts` ＋ `wraps` ＋ `judge-wraps`；(2) **旧 `EffectSnapshot`**（三层：事件／触发器／效果预制体，schemaVersion 3）——仍可写可装载，但经 `LegacySnapshotComponentBinder` 转成前者后执行。
_Avoid_: 效果模板（模板效果专指 `*.tpl.json` 供解析器使用）、效果库

**能力边界**：
当前代码可表达与不可表达的明确分界；每条边界须给出层级（内核缺 / 游戏层未接线 / 规则缺失 / 部分可覆盖）与替代写法。
_Avoid_: 限制、TODO、已知问题

**文档库**：
由唯一阅读指南入口 + 主题分章 + 独立示例 + 纯查表参考层 + 模板层组成的可增长文档集合；每个文件可单独阅读。
_Avoid_: 手册、文档集、wiki

**阅读指南**：
文档库的唯一入口页：读者画像、前置知识、阅读路径、全量索引与章节状态。
_Avoid_: 目录页、首页、index

**章节模板**：
新增章节时必须复制的骨架（含固定元信息块与自检位）；保证新章与既有章同构、无需回改旧章。
_Avoid_: 格式规范、写作规范、样式指南

## Sample Dialogue

> DIY 作者：「每有一个敌方轰炸机，本单位 +1 攻击」我打算监听 `card.stat.changed` 自己加。
> 领域专家：那是**光环**——持续态的正解。你在组件装配时声明光环（`DeclareAuraAsync`），受益方每次链重跑时**现收集**，敌方轰炸机进场/离场自动随动；自己监听再加会重复计数，而且离场不会退回。
> DIY 作者：那「部署时打 1 点伤害」呢？
> 领域专家：那是**触发点**上的**动作面**调用——挂 `unit.deployed`，在 handler 里走 `EffectRuntime.DamageAsync`，不需要光环。
