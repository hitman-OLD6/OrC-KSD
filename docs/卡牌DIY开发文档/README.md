| 你是 | 你能在这里得到 | 你不需要 |

**读完最小闭环你能做什么**：写出一张 `*.card.json` ＋ 一个 `*.component.json`（挂在 `effects-v4/` 下），
让它在指定信号上执行动作，并能用一条 `dotnet test --filter` 或卡包预检证明它生效。

## 2. 前置知识

- **必需**：JSON 能读会改；知道「事件/回调」是什么；会用命令行跑 `dotnet`。
- **数据侧**（主干路径）：只需 JSON ＋ 少量 C# 表达式（csx 片段按模板抄）。
- **代码侧**（进阶路径）：C# 基础（类、委托、`async/await`、泛型粗读即可）。
- **不需要**：读过 `src/`；理解总线/调度器/反射细节——这些只在你排查「为什么没触发」时按章查阅。

## 3. 两条路径与选择判据

| 判据 | 数据侧（默认） | 代码侧（例外） |
| --- | --- | --- |
| 承载 | `*.card.json` ＋ `*.component.json`（v4 资产）＋ csx | C# 类型：`PrefabDefinition` ＋ `MemberEdges.For<TView>` / `Judicator` 子类 / `wraps` 声明 / 装配期注册 |
| 适合 | 监听信号→调用动作面；条件分支；选靶；词条程序 | 需要新判定规则、改写既有流程、复用状态、复杂时序 |
| 不适合 | 需要新判定器、需要替换流程核心、需要跨卡共享状态、需要给外来边定段 | 一次性简单效果（写 C# 成本更高） |
| 可用性标注 | 每章/每例标「数据侧可用」 | 标「仅代码侧可用」并给最小 C# 片段 |
| 证据 | `CardDistributionValidator` 预检 0 error | `dotnet test --filter` 通过 |

> 判据一句话：**能用预制体 + csx 表达的，不写 C#**；一旦要「改判定/改流程/改视图」，转代码侧。

## 7. 约定（读之前先知道）

1. **代码是唯一真源**：文档中的签名/路径以 `src/` 现状为准；文档不描述未实现能力。
2. **来源两面**：`Source`＝事件引发者（信号载荷、只读、可空）；`TriggerCard`＝当前 handler 的触发者（帧值、链上最后者胜）。handler 内再发信号时传 `source: view.TriggerCard`。
3. **能力缺口显式标注**：四级＝内核缺 / 游戏层未接线 / 规则缺失 / 部分可覆盖；每条必须给替代写法或「需改引擎」。
4. **示例必带证据**：命令 + 预期输出 + 等级（数据侧可用 / 仅代码侧可用）。
5. **只有一套写法**：v4 组件资产（`*.component.json`，schemaVersion 4）。旧 `*.prefab.json` / `effects.inline` 仍可装载，
   但本书不再教它；读旧资产按 [09 章](./09-新编排模型与术语迁移.md) 的映射表翻译。
6. **`view` 不能交给 helper 写**：装载期静态检查只覆盖直接写入（含直接别名），经方法/局部函数传递的 `view`
   只有运行期闸门兜底——这是**概率性保护**，不是确定性保护（09 章 §3.1）。
7. **三层别混**：`wrap.phase` 管成员外围、`band` 管成员内部边次序、`seam` 管 handler 内部插入点。选错层＝「改了但没生效」。
