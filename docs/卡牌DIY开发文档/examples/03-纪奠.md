# 示例 03：纪奠（R6c / D2）

## 1. 卡面文本

> 本方总部回复等同于本局已被摧毁单位数的生命。

## 2. 机制选型

- 承载：**组件资产 + csx**（数据侧）
- 触发点：`engine#card.played`（回复）＋ `engine#card.died`（全局计数）——**两个成员，一个组件**
- 动作面：`EngineVariables`（计数）＋ `BuffAsync(hq, 0, count, ...)`（回复）
- 判据：跨事件累计状态，用对局级变量袋即可；不需要 C# 类型。
- D2 口径：监听 `card.died`，**双方单位都计**，不用 `card.destroyed`；计数持久化。
- 路径可用性：**数据侧可用（有近似）**；证据等级：**L2** + 卡包预检 L1。

## 4. 触发时序

| 步 | 发生什么 | 符号 |
| --- | --- | --- |
| 1 | 卡加载时装配组件：两条 `mounts` 边建立（`card.played` / `card.died`） | `OrchestrationRuntime.Bind` |
| 2 | 任一单位死亡 → 发 `card.died` | `GameUpdates.EmitCardDied` |
| 3 | `onDied` 执行：计数 +1（双方都计） | `EngineVariables.Set` |
| 4 | 打出「纪奠」→ 发 `card.played` | `GameUpdates.EmitCardPlayed` |
| 5 | `onPlayed` 执行：读计数 → HQ 回复 N | `EngineVariables.TryGet` + `BuffAsync` |

## 5. 边界与坑

- **计数口径**：用 `card.died`（游戏层死亡、含战斗/效果击杀、双方）而不是 `card.destroyed`（引擎销毁，弃牌也会触发）。
- **起算点**：数据侧用对局级 `EngineVariables`，计数自**该卡效果装载**起算，不是严格「开局起算」；要严格开局起算需把该卡放进卡组并确保初始化装载（本示例的测试即此场景），或改代码侧在 Match 装配时清零。
- **多张同名卡共享同一 key**：数据侧近似；需要「每张各自计数」改用组件私有字段（`private-fields` + `owner.<Name>`，随实例销毁复位）。
- 回复是「加 `HqHealth` 修饰」，不是设置绝对值；HQ 已满血时仍会加上限（引擎无「上限」概念）。
- `BuffAsync` 的 `source` 传本卡：下游信号 `Source` 仍可能为 null（G-04），但 HQ 数值变化可读。
