# 示例 03：纪奠（R6c / D2）

> ⚠️ **实现表已过时（2026-10-28）**：本文档的**卡面文本与效果设计仍有效**，但"实现/追踪"表里引用的
> `CardLoadout.MountEffect`、`AddEffect`、`OnMount` 等符号已随 `Effect` 类删除。
> 现在的装配链：构造 `ComponentAttachment` → 判定 `active-when` → `Bind` 建边；数据侧写法本身不变。

## 1. 卡面文本

> 本方总部回复等同于本局已被摧毁单位数的生命。

## 2. 机制选型

- 承载：**效果预制体 + csx**（数据侧）
- 触发点：`card.played`（回复）＋ `card.died`（全局计数，两个触发器）
- 动作面：`EngineVariables`（计数）＋ `BuffAsync(hq, 0, count, ...)`（回复）
- 判据：跨事件累计状态，用对局级变量袋即可；不需要 C# 类型。
- D2 口径：监听 `card.died`，**双方单位都计**，不用 `card.destroyed`；计数持久化。
- 路径可用性：**数据侧可用（有近似）**；证据等级：**L2** + 卡包预检 L1。

## 4. 触发时序

| 步 | 发生什么 | 符号 |
| --- | --- | --- |
| 1 | 卡加载时，两个触发器挂载（`card.played` / `card.died`） | `CardLoadout.MountEffect` |
| 2 | 任一单位死亡 → `card.died` | `GameUpdates.EmitCardDied` |
| 3 | 计数 +1（双方都计） | `EngineVariables.Set` |
| 4 | 打出「纪奠」→ `card.played` | `GameUpdates.EmitCardPlayed` |
| 5 | 读计数 → HQ 回复 N | `EngineVariables.TryGet` + `BuffAsync` |

## 5. 边界与坑

- **计数口径**：用 `card.died`（游戏层死亡、含战斗/效果击杀、双方）而不是 `card.destroyed`（引擎销毁，弃牌也会触发）。
- **起算点**：数据侧用对局级 `EngineVariables`，计数自**该卡效果装载**起算，不是严格「开局起算」；要严格开局起算需把该卡放进卡组并确保初始化装载（本示例的测试即此场景），或改代码侧在 Match 装配时清零。
- **多张同名卡共享同一 key**：数据侧近似；需要「每张各自计数」改代码侧效果实例字段（D2 的原意）。
- 回复是「加 `HqHealth` 修饰」，不是设置绝对值；HQ 已满血时仍会加上限（引擎无「上限」概念）。
- `BuffAsync` 的 `source` 传本卡：下游信号 `Source` 仍可能为 null（G-04），但 HQ 数值变化可读。
