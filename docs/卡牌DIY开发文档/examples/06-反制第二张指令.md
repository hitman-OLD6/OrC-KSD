# 示例 06：反制第二张指令（R6f；G-01 已解决）

## 1. 卡面文本

> 敌方使用第二张指令时，将其反制。

## 2. 机制选型

- 承载：**C# 接线**（代码侧）：反制卡在装配期把一条边挂到 `engine#order.cast` 的 `Counter` 段
- 触发点：`engine#order.cast` 的 `Counter` 段（**不是信号**，是流程成员的段位）
- 动作面：默认 `ctx.Stop()`（指令**照常扣费、照常离手**，只是 `Resolve` 段不执行）；可选 `ctx.Interrupt()`（牌留手、不扣费）
- 判据：需要在**结算前**否决或中断 `Resolve`；只有段位能做——信号发得太晚。
- 路径可用性：**仅代码侧可用**（`order.cast` 的视图是空的，数据侧读不到施放者）；证据等级：**写法参考**。

## 3. 完整代码

**反制侧的接线**（装配期一次，随卡生命周期撤销）：

```csharp
using Orc.Core;
using Orc.Core.Model;
using Orc.Game.Model;
using Orc.Game.Triggers;

// 把「反制检查」挂到 order.cast 的 Counter 段（早于 Resolve 结算）
private IDisposable AttachCounterCheck()
    => _engine.AttachMemberEdge(
        EngineProcesses.OrderCast,          // 成员名：order.cast
        "反制检查",
        owner: this,                         // 撤销依据（引用相等），不是归因
        MemberEdges.For<OrderFlowView>(OnCounter),
        band: BandSchemes.Counter);          // 段名常量，不写裸字符串
```

**判断「第二张」**（计数放在反制卡自己身上）：

```csharp
private int _seen;

private Task OnCounter(OrderFlowView view, Context ctx, CancellationToken ct)
{
    _seen++;
    if (_seen >= 2)
    {
        // 本示例演示**严格中断**：牌留手、不扣费（Finalize 段一并跳过）。
        // 框架默认反制语义是 ctx.Stop()：指令照常扣费/离手，只是 Resolve 段不执行。
        ctx.Interrupt();
    }

    return Task.CompletedTask;
}
```

**施放**：

```csharp
// 第一张：正常结算
await match.Engine.OrderFlow.ExecuteAsync(caster, order, target, 2, ct);
// 第二张：Counter 段命中 → Interrupt → 目标不再受伤
await match.Engine.OrderFlow.ExecuteAsync(caster, order, target, 2, ct);
```

## 4. 触发时序

| 步 | 发生什么 | 符号 |
| --- | --- | --- |
| 1 | 施放指令（原生卡走 `PlayOrderAsync` → `IOrderAction`；本例直调 `OrderFlow`） | `OrderFlow.ExecuteAsync` |
| 2 | **`Counter` 段**：反制检查；第二次命中（默认 `ctx.Stop()`；本示例用 `ctx.Interrupt()`） | `engine#order.cast` |
| 3 | **`Resolve` 段**：未命中时先发 `card.played`，再调用主动效果；命中则本段整体不执行（含宣告） | `OrderFlow` |
| 4 | 施放链执行动作（本例 2 点伤害） | `EffectRuntime.DamageAsync` |
| 5 | **`Finalize` 段**：扣费 → 离手（`Stop` 不阻止本段；`Interrupt` 才整段跳过） | `engine#order.finalize` |
| 6 | 中断时：两阶段全停（牌留手、不扣费），链 `Outcome` 记录中断 | `Context.Interrupt` |

## 5. 边界与坑

- **原生 `OrderCard` 经过 `OrderFlow`**（P4 指令归一）：普通指令卡施放＝预打出 →（复验）→ `OrderFlow`（Counter → Resolve〔`card.played` → 主动效果〕→ Finalize〔扣费/离手〕）；反制卡效果 handler 注册到 Counter 段即可反制。
- **默认是 `Stop`，不是 `Interrupt`**：`ctx.Stop()` 只停其后的段——反制命中后指令**照常扣费、照常离手**，只是效果不触发；`ctx.Interrupt()` 是可选强反制（牌留手、不扣费）。
- **被反制的指令不发 `card.played`**（`Resolve` 整体被跳过的必然结果，视为「未成功打出」）：监听 `card.played` 的观察者收不到它；这是「反制后效果不触发」的代价——现有指令卡效果正是被动效果 hook `card.played`。
- **反制卡一次性消耗**：handler 调用 `Stop`/`Interrupt` ＝命中；命中后该卡从手牌移除并走弃置路径（`card.discarded`）、注销 Counter 段全部 handler、回到未激活，**不退费**。未命中保持激活（多张反制各自判定）。
- 反制计数在本效果实例上（`Seen`），多张反制各自计数；如果要「全局第 N 张」，计数需放 `EngineVariables` 或对局服务。
- `ctx.Interrupt()` 是**链级**中断（沿嵌套链传播、两阶段全停）；`ctx.Stop()` 只停本层剩余事件（Resolve 跳过、Finalize 照常）。
- 反制卡的效果 handler 读 `CardTriggerView`：`Card`/`Player`＝反制卡及其归属，`Source`＝被反制指令卡，`Target`＝施放目标，`Argument`＝数值（适配视图由 `CounterCard` 构造）。
- **撤销靠句柄**：`AttachMemberEdge` 返回的 `IDisposable` 在反制卡注销时 Dispose 即撤销那条边；没有 `OnUnmount` 可写。
- 测试用 `DamageOrderView` 而不是 `OrderFlowView`：`OnResolve` 只向施放链传 `Source/Target/Amount` 三键；`OrderFlowView` 另有必填的 `Source`/`Orders` 键，直接复用会绑定失败。
