# 示例 06：反制第二张指令（R6f；G-01 已解决 P4）

## 1. 卡面文本

> 敌方使用第二张指令时，将其反制。

## 2. 机制选型

- 承载：**C# 效果**（代码侧）：反制卡经 `CounterCard.AddEffectHandler` 装配效果 handler，激活时注册到 `OrderFlowBands.Counter`；指令本身实现 `ICastAction`
- 触发点：`OrderFlow` 的 Counter 段（`OrderFlowBands.Counter`），不是总线信号
- 动作面：默认 `ctx.Stop()`（指令**照常扣费、照常离手**，只是 Resolve 段不执行）；可选 `ctx.Interrupt()`（牌留手、不扣费）
- 判据：需要在**结算前**否决或中断 Resolve；只有流程 band 能做。
- 路径可用性：**仅代码侧可用**；证据等级：**L2**。
- **P4 边界已变化**：原生 `OrderCard` 的施放已由 `PlayOrderAsync` → `IOrderAction` → `OrderFlow` 承载（`Counter` 段反制判定 → `Resolve` 段先发 `card.played` 再执行主动效果 → `Finalize` 段扣费/离手）；反制卡激活时把效果 handler 注册到 `OrderFlowBands.Counter`，因此本示例的注入方式对原生指令同样生效。

## 3. 完整代码

**指令（ICastAction）**：

```csharp
using Orc.Cards;
using Orc.Core;
using Orc.Game.Effects;

[ContextView]
public class DamageOrderView
{
    [Optional][Read] public virtual Card? Source { get; set; }
    [Optional][Read] public virtual Card? Target { get; set; }
    [Optional][Read] public virtual int Amount { get; set; }
}

public sealed class DamageOrder : ActiveEffect<DamageOrderView>
{
    public DamageOrder()
        : base("测试伤害指令", castEvents: new[] { new TriggerEvent<DamageOrderView>("施放结算", CastAsync) })
    {
    }

    private static async Task CastAsync(DamageOrderView view, Context ctx, CancellationToken ct)
    {
        if (view.Source is not { } source || view.Target is not { } target)
        {
            return;
        }

        if (EffectRuntime.ResolveFor(source) is not { } runtime)
        {
            return;
        }

        await runtime.DamageAsync(target, view.Amount, source, ct);
    }
}
```

**反制效果**：

```csharp
using Orc.Cards;
using Orc.Core;

public sealed class SecondOrderCounterEffect : PassiveEffect
{
    private readonly LogicEngine _engine;

    public SecondOrderCounterEffect(LogicEngine engine)
        : base("第二张指令反制")
    {
        _engine = engine;
    }

    public int Seen { get; private set; }

    protected override void OnMount()
        => Inject(_engine.OrderFlow.Trigger, "反制检查", OrderFlowBands.Counter, OnCounter);

    private Task OnCounter(OrderFlowView view, Context ctx, CancellationToken ct)
    {
        Seen++;
        if (Seen >= 2)
        {
            // 本示例演示**严格中断**：牌留手、不扣费（Finalize 段一并跳过）。
            // 框架默认反制语义是 ctx.Stop()：指令照常扣费/离手，只是 Resolve 段不执行。
            ctx.Interrupt();
        }

        return Task.CompletedTask;
    }
}
```

**施放**：

```csharp
// 第一张：正常结算
await match.Engine.OrderFlow.ExecuteAsync(caster, order, target, 2, ct);
// 第二张：Counter 命中 → Interrupt → 目标不再受伤
await match.Engine.OrderFlow.ExecuteAsync(caster, order, target, 2, ct);
```

## 4. 触发时序

| 步 | 发生什么 | 符号 |
| --- | --- | --- |
| 1 | 施放指令（本例直调 `OrderFlow`；原生指令卡走 `PlayOrderAsync` → `IOrderAction`） | `OrderFlow.ExecuteAsync` |
| 2 | **Counter(1)**：反制检查；第二次命中（默认 `ctx.Stop()`；本示例用 `ctx.Interrupt()`） | `OrderFlowBands.Counter` |
| 3 | **Resolve(2)**：未命中时先发 `card.played`（priority 0），再按 `Orders` 登记序调用 `CastAsync(...)`（priority 100）；命中则本段整体不执行（含宣告） | `OrderFlowBands.Resolve` / `ICastAction.CastAsync` |
| 4 | 施放链执行动作（本例 2 点伤害） | `EffectRuntime.DamageAsync` |
| 5 | **Finalize(3)**：扣费 → 离手（`Stop` 不阻止本段；`Interrupt` 才整段跳过） | `OrderFlowBands.Finalize` |
| 6 | 中断时：两阶段全停（牌留手、不扣费），链 `Outcome` 记录中断 | `Context.Interrupt` |

## 5. 边界与坑

- **原生 `OrderCard` 经过 `OrderFlow`**（P4 指令归一）：普通指令卡施放＝预打出 →（复验）→ `OrderFlow`（Counter → Resolve〔`card.played` → 主动效果〕→ Finalize〔扣费/离手〕）；反制卡效果 handler 注册到 Counter 段即可反制。
- **默认是 `Stop`，不是 `Interrupt`**：`ctx.Stop()` 只停其后的段——反制命中后指令**照常扣费、照常离手**，只是效果不触发；`ctx.Interrupt()` 是可选强反制（牌留手、不扣费）。
- **被反制的指令不发 `card.played`**（`Resolve` 整体被跳过的必然结果，视为「未成功打出」）：监听 `card.played` 的观察者收不到它；这是「反制后效果不触发」的代价——现有指令卡效果正是被动效果 hook `card.played`。
- **反制卡一次性消耗**：handler 调用 `Stop`/`Interrupt` ＝命中；命中后该卡从手牌移除并走弃置路径（`card.discarded`）、注销 Counter 段全部 handler、回到未激活，**不退费**。未命中保持激活（多张反制各自判定）。
- 反制计数在本效果实例上（`Seen`），多张反制各自计数；如果要「全局第 N 张」，计数需放 `EngineVariables` 或对局服务。
- `ctx.Interrupt()` 是**链级**中断（沿嵌套链传播、两阶段全停）；`ctx.Stop()` 只停本层剩余事件（Resolve 跳过、Finalize 照常）。
- 反制卡的效果 handler 读 `CardTriggerView`：`Card`/`Player`＝反制卡及其归属，`Source`＝被反制指令卡，`Target`＝施放目标，`Argument`＝数值（适配视图由 `CounterCard` 构造）。
- 本示例用 `PassiveEffect` 注入：效果要挂在**在场**的卡上（`AddEffect` 后 `OnMount` 注入）；卡离场/销毁时框架自动撤销注入。正式卡走 `CounterCard.AddEffectHandler`（激活注册、取消/消耗注销）。
- 测试用 `DamageOrderView` 而不是 `OrderFlowView`：`OnResolve` 只向施放链传 `Source/Target/Amount` 三键；`OrderFlowView` 另有必填的 `Source`/`Orders` 键，直接复用会绑定失败。
