## 1. 架构与职责边界

```
房主客户端 ──拉起──> Orc.Server 进程（一个实例 = 一场对局）
   │                    │
   │   房间态：座位 + 控制器（local / remote / ai）
   │   对局态：引擎 + 串行执行 + 按座位投影
   │
   └── TCP/NDJSON（JSON-RPC 2.0）──> 其他客户端 / agent 客户端
```

| 谁 | 负责 | **不负责** |
|---|---|---|
| 服务端 | 规则裁决、投影生成、选靶归属、卡组校验、AI 驱动、脱敏 | 美术、卡面文本、输入、动画 |
| 客户端 | 渲染、输入、把玩家意图变成工具调用 | **任何规则判断**（可打出/可攻击/合法性） |

三种控制器：

- `local`：房主本人（也是唯一能开局、踢人、加 AI 的角色）；
- `remote`：远程客户端，凭 `seatToken` 绑定座位；
- `ai`：服务端进程内驱动（`AiPilot`），**完全不经过协议**，但对局里和人类同权。

服务端只服务**一局**：房间先于对局存在，终局后不可回到房间态。

## 2. 前端改动清单（最重要的部分）

旧前端把引擎跑在客户端进程内（`OrcEngineHost` 单例 + `OrcMatchSession` 持有 `Match` + `OrcMatchHost` 每帧 `Pump()`）。改装后对局逻辑全部移到服务端。

### 2.1 要删除/停用的

| 旧组件 | 处理 | 原因 |
|---|---|---|
| `OrcEngineHost`（进程级引擎单例） | 对局路径**停用** | 引擎在服务端；客户端不再 `WarmUp` 对局 |
| `OrcMatchSession`（持 `internal Match`） | 删除 | 活对象不出进程 |
| `OrcMatchHost.Pump()` 每帧投影 | 删除 | 改为 `notify/view` 推送 |
| `OrcMatchHost.PullSegments()` 轮询 | 删除 | 改为 `notify/segment` 推送 |
| `OrcMatchHost.Index`（暴露 `Card` 字典） | 删除 | 绕过投影的旁路 |
| `IUiTargetResponder.Complete/Cancel`（**同步** bool 接口） | 删除 | 协议上是异步请求-应答 |
| `Match._Process` 里的同步排空 | 删除 | 主线程只做渲染 |

> **DIY 编译链（Roslyn / V8 / `DiyCardCompiler` / `VerifiedCardPool`）不在对局客户端**。按既定决策：对局客户端不跑引擎，DIY/创作另起独立宿主。对局客户端只需要 `cardId → 美术/文本` 的查表能力。

### 2.2 要替换的

| 旧行为 | 新做法 |
|---|---|
| 本地 `CreateMatch` 建局 | `room.claim` ＋ `room.start` |
| 本地读 `Match` 算 `UiBattleActions` | 读推送里的 `actions` |
| 本地算可打出/可移动/可攻击 | 读 `actions.playableUids` / `moves` / `attackPreviews` |
| 本地选靶回调 | `target.submit` / `target.cancel` |
| 本地断线即结束 | `room.resume` ＋ `observe.view` 拉全量 |

### 2.3 要新增的

**协议层**：直接用 `Orc.Client`（推荐），或按 §5 自行实现。

**UI 面**：

1. **开房/连接面板**：显示端口、可连接地址（`room.info.addresses`，支持复制）、连接状态。
2. **座位面板**：两个座位的控制器类型/显示名/`ready`/`connected`；空座可「声明座位」或「添加 AI」；房主可「踢出」。
3. **选靶覆盖层**：候选高亮、`min/max` 约束、提交/取消；显示 `notify/target.expired` 时自动关闭。
4. **对手回合提示**：`view.activePlayerSide == "enemy"` 时禁用本方操作。
5. **断线遮罩**：连接断开 → 遮罩 → 自动重连（`room.resume`）→ 拉全量 → 恢复。
6. **终局面板**：以 `view.outcome`（`Win`/`Lose`/`None`）为准，**不要**用 `resultTitle` 文本反推。
7. **房主网络提示**：首次监听可能触发 Windows 防火墙弹窗；外部玩家连不上时优先指向这里。

## 3. 客户端状态机

```
Disconnected
   │ ConnectAsync + initialize
   ▼
Connected ──room.info──> RoomState(state)
   │                        ├─ lobby：座位面板
   │                        └─ in-match：对局面板
   │
   ├─ room.claim / room.add_ai / room.resume ──> Seated(seat, seatToken)
   ├─ notify/match.started ──> InMatch(phase)
   │       ├─ mulligan：换牌界面，mulligan.done
   │       ├─ play：出牌/指挥/选靶
   │       └─ over：终局面板
   └─ 连接断开 ──> Disconnected（保留 seatToken）
```

**状态来源**：只认 `room.info`、`notify/*`、`observe.view` 三者。不要自己维护"我以为的状态"。

**必须持久化**：`seatToken`（断线重连的唯一凭据）。

## 4. 连接与生命周期

### 4.1 拉起服务端（单机）

```csharp
await using var server = await ServerProcess.StartAsync(new ServerProcessOptions
{
    ExecutablePath = "dotnet",
    Arguments = ["run", "--project", "<repo>/src/Orc.Server/Orc.Server.csproj", "--no-build", "--",
                 "--packs", "<packDir>", "--port", "0"],
    LogPath = "<sandbox>/logs/server.log",
});
// server.Port 已从 stdout 就绪行解析出来
```

**就绪约定**：stdout 首行 `{"ready":true,"port":N}`，其余输出一律 stderr。

`ServerProcess` 会自动追加 `--parent-pid <自身 PID>`：客户端崩溃时服务端随之退出（2 秒轮询）。

**可选启动参数**：

| 参数 | 含义 |
|---|---|
| `--packs <dir;dir>` | 卡包目录（多个用 `;` 分隔） |
| `--sandbox <dir>` | 沙盒根（日志/临时文件） |
| `--port <n>` | 0＝系统分配（推荐） |
| `--parent-pid <pid>` | 父进程监视（客户端拉起时自动传） |

### 4.2 连接与握手

```csharp
await using var client = await OrcClient.ConnectAsync(new ClientOptions
{
    Host = "127.0.0.1",   // 局域网＝房主 room.info.addresses 里的 ip
    Port = server.Port,
});

var init = await client.InitializeAsync(new InitializeParams { ClientName = "godot" });
// init.ProtocolVersion = "1.0"；init.SchemaVersion；init.Capabilities = ["room","push","targeting"]
```

握手失败会抛 `InvalidOperationException`（版本不匹配等）。

### 4.3 心跳

- 服务端：45 秒无任何请求即断开；
- 客户端：静默超过 30 秒主动 `ping`；
- 断开后所有挂起请求**立即失败**（不会永久挂起）。

## 5. API 参考

### 5.1 协议方法

| 方法 | 参数 | 结果 |
|---|---|---|
| `initialize` | `{clientName?, protocolVersion?}` | `{protocolVersion, schemaVersion, capabilities[]}` |
| `ping` | — | `{pong:true}` |
| `tools/list` | — | `[{name, group, description, inputSchema}]`（**运行时自描述**，schema 以此为准） |
| `tools/call` | `{name, arguments}` | 业务结果壳（§6.1） |

### 5.2 前端必用工具

| 工具 | 参数 | 返回要点 |
|---|---|---|
| `room.info` | — | 房间快照（§6.2） |
| `room.claim` | `{seat, kind?, name?, deck[], deckConfig?, seatToken?}` | `details.seatToken`（**必须保存**） |
| `room.release` | `{seat, seatToken?}` | — |
| `room.add_ai` | `{seat, name?, deck?, deckConfig?}` | 房主专用；缺省卡组由服务端生成 |
| `room.start` | `{seatToken?}` | 房主令牌；成功后登记 `notify/match.started` |
| `room.kick` | `{seat, seatToken?}` | 房主专用 |
| `room.resume` | `{seatToken}` | 重连；`details.seat` 为座位号 |
| `observe.view` | `{seat?}` | 整枚投影 ＋ actions（§6.3）；`seat` 缺省取服务端配置 |
| `mulligan.begin` | `{owner}` | 进入换牌（若相位允许） |
| `mulligan.done` | `{owner}` | 确认（不换牌直接确认） |
| `match.end_turn` | — | 结束当前回合（当前方） |
| `match.concede` | `{owner}` | 认输 |
| `play.unit_pre` | `{ref}` | 单位预打出 → 返回 `targeting` |
| `play.unit` | `{ref, owner, slot}` | 直接指定槽位打出 |
| `play.command_pre` | `{ref}` | **指令预打出**（拖出即调）→ 进入选目标 |
| `play.command` | `{ref, ...}` | 与 `command_pre` 同一实现（**不要重复调用**） |
| `play.counter` | `{ref, ...}` | 反制打出 |
| `play.join` | `{ref, ...}` | 支援线部署（视卡而定） |
| `play.can_play` | `{ref}` | 单卡可打出（只读；也可直接用 `actions.playableUids`） |
| `command.begin` | `{ref}` | 指挥（把单位移到前线） |
| `command.move` | `{ref, ...}` | 移动 |
| `command.attack` | `{ref, ...}` | 攻击 |
| `command.leave` | `{ref}` | 撤离 |
| `command.availability` | `{ref}` | 单单位指挥可用性（只读） |
| `target.submit` | `{sessionId, picks[]}` | 提交选靶（**序号从 1 起**） |
| `target.cancel` | `{sessionId}` | 取消（零副作用） |
| `target.claim` | `{sessionId, claimant}` | 兼容保留；**已不参与路由**，前端不要用 |
| `docs.list` / `docs.read` | `{path?}` | 引擎文档（诊断用） |
| `service.info` / `service.tools` | — | 服务元信息（诊断用） |

> **参数细节以 `tools/list` 的 `inputSchema` 为准**（运行时自描述，避免文档与实现漂移）。

### 5.3 业务结果壳

```json
{ "ok": true,  "code": "ok",       "message": "",        "details": { } }
{ "ok": false, "code": "deck-invalid", "message": "…",   "details": { } }
```

`code == "targeting"` **不是错误**：表示动作已挂起，等选靶。`code == "cancelled"` 也是成功态。

## 6. 载荷参考

### 6.1 错误分层

| 情况 | 位置 |
|---|---|
| 报文非法 / 未知方法 / 参数形状错 | `error.code`（-32700 / -32601 / -32602 / -32600） |
| **业务失败** | `result.ok = false` ＋ `result.code` |

客户端判定只看 `result.ok` 与 `result.code`，**不要解析 `message`**。

常见业务码：

| code | 含义 |
|---|---|
| `ok` / `targeting` / `cancelled` | 成功态 |
| `busy` | 队列满，稍后重试 |
| `seat-taken` | 座位被占 |
| `unauthorized` | 令牌无效/非房主 |
| `room-not-ready` | 座位未满 |
| `room-started` | 房间已开局 |
| `deck-invalid` | 卡组不合法 |
| `invalid-arguments` | 参数缺失/格式错 |
| `unknown-tool` | 工具不存在 |
| `not-ready` | 无活跃对局 |
| `engine-rejected` | 引擎拒绝（门禁/状态） |
| `internal` | 服务端故障 |

### 6.2 房间快照（`room.info` 的 details）

```json
{
  "roomId": "a1b2c3d4",
  "state": "lobby",                       // lobby | in-match | ended
  "seats": [
    { "seat": 0, "controllerKind": "local", "displayName": "房主", "ready": true, "connected": true },
    { "seat": 1, "controllerKind": "",      "displayName": null,   "ready": false, "connected": false }
  ],
  "packPolicy": "loaded",
  "packFingerprint": "9f2c1a7b3d4e5f60",  // 两端对账用（16 位）；null＝未提供
  "addresses": [ { "ip": "192.168.1.7", "port": 54321 } ]
}
```

> **空座位的 `controllerKind` 是空字符串**（不是 null）。`addresses` 只含非回环 IPv4。

### 6.3 视图推送（`notify/view`）与 `observe.view`

```json
{
  "kind": "view.updated",
  "seat": 0,
  "matchId": "a1b2c3d4",
  "view": { /* §7.1 */ },
  "actions": { /* §7.2 */ },

  "turn": 3, "phase": "play", "activePlayerSide": "self",
  "selfHandCount": 5, "selfDeckCount": 30, "enemyHandCount": 5, "enemyDeckCount": 30,
  "selfKredits": 3, "selfMaxKredits": 3, "selfCounterCount": 0, "resultTitle": null
}
```

扁平标量是旧 `observe.view` 的兼容字段，**新代码只读 `view` 与 `actions`**。

### 6.4 段推送（`notify/segment`）

```json
{ "seat": 0, "segments": [ { "sequence": 12, "timestamp": "2026-10-20T…", "entries": [...], "children": [...] } ] }
```

条目结构：

```json
{
  "kind": "update", "timestamp": "…", "level": "info", "source": "…", "message": "…",
  "keywords": ["…"],
  "data": { "player": { … }, "card": { "$ref": "3a7f…", "name": "某单位", "$alive": true } }
}
```

**实体表示（重要）**：

| 形态 | 含义 |
|---|---|
| `{"$ref":"<GUID>","name":"…","$alive":true}` | 可见实体；`$ref` 是**对局内唯一键** |
| `{"$hidden":true}` | **对你看不见**（如对手抽牌）：只播动画，不要猜是什么 |
| `{"$effect":"…"}` / `{"$type":"…"}` / `{"$truncated":true}` | 非实体值/超深截断 |

### 6.5 选靶请求（`notify/target.request` / `notify/target.expired`）

```json
{
  "sessionId": "9f2c…",
  "selector": "field-unit",
  "mode": "Click",
  "min": 1, "max": 1,
  "seat": 0,
  "candidates": [ { "index": 1, "kind": "unit", "ref": "3a7f…", "name": "某单位", "alive": true } ],
  "identifiers": []
}
```

- 提交用 `index`（**从 1 起**），不是 `ref`；
- `seat` 为 `null` 时请求会广播给所有会话（兼容单人场景）；
- 收到 `notify/target.expired` 时立即关闭选靶面板（动作已按取消推进）。

## 7. 字段表

### 7.1 `UiMatchView`（单视角整盘投影）

| 字段 | 类型 | 说明 |
|---|---|---|
| `matchId` | string | 对局 id |
| `turn` | int | 全局回合数 |
| `selfPlayerName` / `enemyPlayerName` | string | 显示名 |
| `phase` | string | **小写字面量**：`mulligan` / `play` / `over` |
| `resultTitle` / `resultReason` | string? | 结果文案 / 原因（`hq-zero`、`concede`） |
| `outcome` | string | **枚举名**：`Win` / `Lose` / `None` |
| `concedingSide` | string | `None` / `Self` / `Enemy` |
| `finalTurn` | int? | 终局时的回合数 |
| `activePlayerSide` | string | `self` / `enemy`（相对本视角） |
| `selfKredits` / `selfMaxKredits` | int | 资源 |
| `enemyKredits` / `enemyMaxKredits` | int? | 对手资源（可见） |
| `selfHandCount` / `selfDeckCount` | int | 自己计数 |
| `enemyHandCount` / `enemyDeckCount` | int? | 对手计数（**无明细**） |
| `selfCounterCount` | int | 自己已挂反制数 |
| `selfHand` | UiCardView[] | 自己手牌（含明细） |
| `selfLine` / `enemyLine` | UiCardView[] | 双方前线（**只含占位卡**） |
| `frontLineSlotCount` | int | 前线**真实槽位数**（画空槽必须用它） |
| `supportLineSlotCount` | int | 支援线真实槽位数 |
| `selfHq` / `enemyHq` | UiCardView? | 总部 |
| `selectedTarget` | UiCardView? | 当前选中目标 |
| `pendingChoices` | UiCardView[] | 待决选项（与选靶面板配合） |
| `pendingChoiceCaption` | string? | 待决提示文案 |

> ⚠️ **同一条消息里存在两种命名风格**：`phase` 是小写字面量、`outcome` 是枚举名。这是既有投影口径，不要“统一”它。
> ⚠️ **空槽不能靠数卡片**：`selfLine` 只包含有卡的槽位，必须用 `frontLineSlotCount` / `supportLineSlotCount` 还原整条战线宽度。

### 7.2 `actions`

```json
{
  "playableUids": ["3a7f…"],
  "handPlayabilityKnown": true,
  "moves": [ { "uid": "3a7f…", "toZone": "front", "slotIndex": 2 } ],
  "attackPreviews": [ { "attackerUid": "3a7f…", "defenderUid": "8b2e…",
                        "damageToDefender": 3, "damageToAttacker": 2,
                        "defenderDies": false, "attackerDies": false } ],
  "orderTargets": [],
  "deploymentGaps": [ { "uid": "3a7f…", "gaps": ["aa01…", "bb02…"] } ],
  "canEndTurn": true,
  "attacksEnabled": true,
  "mulliganOpen": false
}
```

| 字段 | 用法 | 限制 |
|---|---|---|
| `playableUids` | 手牌高亮；与 `view.selfHand[].uid` 同键 | 不含“为什么不能打”（见 `play.can_play` 的 `blockedReasons`） |
| `moves` | 可移动到的前线空槽 | 只覆盖“推进”，无后撤/横移 |
| `attackPreviews` | 可攻击目标 | **不判断护卫/拦截**；伤害见下 |
| `deploymentGaps` | 单位部署的“缝隙”引用 | 缝隙不是槽位号 |
| `orderTargets` | **恒空** | 指令目标改为交互式（§8.4） |
| `canEndTurn` / `attacksEnabled` | 按钮可用性 | 不区分“是否轮到本方”，仍需配合 `activePlayerSide` |
| `mulliganOpen` | 换牌界面开关 | — |

**伤害数字的性质**：`damageToDefender` / `damageToAttacker` 是**有效攻击力（基础值）**，不是最终伤害。引擎的伤害会被管线 handler 改写（重甲减伤、伏击、免疫），这些只在真正结算时发生。UI 只能显示“大致伤害”，**不能**当权威值；`defenderDies`/`attackerDies` 恒 `false`（不预测死亡）。

### 7.3 `UiCardView`（每张卡）

| 字段 | 类型 | 说明 |
|---|---|---|
| `uid` | string | 实例键（GUID，N 格式）；**与 `actions`/`$ref` 同键** |
| `definition` | UiCardDefinition | 静态定义（§7.4） |
| `cardId` | string | 便捷字段＝`definition.cardId` |
| `effectiveCost` / `effectiveAttack` / `effectiveDefense` / `effectiveOpCost` | int? | 含修饰器与光环的**有效值** |
| `health` | int? | 单位当前血量 |
| `zone` | string | `hand` / `front` / `support` / … |
| `slotIndex` | int | 槽位号；`-1` 表示不在战线 |
| `ownerSide` | string | `self` / `enemy` |
| `visibility` | string | 可见性枚举名（`Full` 等）；通常恒 `Full`（对手手牌根本不下发） |
| `isHq` | bool | 是否总部 |
| `isVeteran` / `isCovert` / `isToken` | bool | 状态标记 |
| `unitTypes` | string[] | 兵种 |
| `canPlayCard` / `canAttack` / `canMoveAndAttack` / `canBeTargeted` | bool | 卡级标记（**辅助**；全局可操作性以 `actions` 为准） |
| `blockedReasons` | string[] | 不能打的原因（诊断/提示用） |
| `keywords` / `keywordValues` | — | 词条与数值 |
| `isSuppressed` / `isSilenced` / `isCounterArmed` | bool | 压制/沉默/反制已挂 |

### 7.4 `UiCardDefinition`

| 字段 | 说明 |
|---|---|
| `cardId` | 应用层 id（本地查表键） |
| `name` / `nameEn` | 名称 |
| `cardType` | **卡类型：`unit` / `command` / `counter`**（引擎归一化值；可直接据此区分单位/指令/反制）。注意卡包 JSON 里写作 `order`，但投影里是 `command` |

| `keywords` / `keywordValues` | 词条 |
| `cost` / `baseAttack` / `baseDefense` / `baseOpCost` | 基础值（`null`＝不适用，**不是 0**） |

## 8. 交互时序

### 8.1 开房 → 开局

```
房主：ServerProcess.StartAsync → 拿到 Port
房主：Connect + initialize
房主：room.claim { seat:0, kind:"local", name, deck[] } → 保存 seatToken
客人：Connect + initialize
客人：room.claim { seat:1, kind:"remote", name, deck[] } → 保存 seatToken
     （或房主：room.add_ai { seat:1 }）
房主：room.start { seatToken }
双方：收 notify/match.started
双方：收 notify/view（phase:"mulligan"）
```

### 8.2 换牌

```
双方：mulligan.done { owner: 自己座位 }（若需换牌，先按换牌逻辑再 done）
收到 phase:"play" 的 notify/view
```

### 8.3 出牌（单位）

```
点击手牌 → 是否为 playableUids 成员？
  是 → play.unit_pre { ref: uid }
       → result.code == "targeting"
       → 收 notify/target.request（seat == 自己）
       → 玩家点选候选 → target.submit { sessionId, picks:[index] }
       → 收新的 notify/view（手牌减少/战线出现卡）
       → 玩家取消 → target.cancel { sessionId }（零副作用）
```

### 8.4 指令（拖出即预打出）

```
拖动指令卡（definition.cardType == "command"）
  → play.command_pre { ref }        // 一次，不要放下时再调 play.command
  → 收 notify/target.request（候选就是目标）
  → 拖到候选上 → target.submit
  → 拖回/ESC   → target.cancel
```

**为什么不做"悬停预览"**：指令目标由效果 handler 运行期决定，引擎没有静态目标声明；静态产出等于执行效果。**取消零副作用**是引擎保证的（`PlayManager`：预打出失败/取消＝打出不发生、卡留手、不扣费）。

**代价**：预打出会挂起动作，选靶期间其他动作被门禁挡住（只放行 `target.*` 与只读工具）——这本来就是拖拽中，UI 不应允许其他操作。

### 8.5 回合与终局

```
房主/当前方：match.end_turn
  → notify/view（activePlayerSide 变化）
终局：
  view.phase == "over"，view.outcome == "Win" | "Lose" | "None"
  （注意：终局不会发 notify/match.ended）
```

### 8.6 断线重连

```
检测到断开（请求抛异常 / 心跳失败）
  → 显示遮罩
  → 新建 OrcClient（Host/Port 不变）
  → initialize
  → room.resume { seatToken }   → details.seat
  → observe.view { seat }       → 全量重建
  → 若仍在选靶，房主会重推 notify/target.request
```

## 9. 错误与重试

| 情况 | 处理 |
|---|---|
| `busy` | 200–500ms 后重试（同一操作最多 3 次） |
| `targeting` | **正常**：等选靶，不要当失败 |
| `cancelled` | 正常：动作被取消（含超时） |
| `room-not-ready` | 提示“还有座位未就绪”，刷新 `room.info` |
| `seat-taken` | 提示换座或刷新快照 |
| `unauthorized` | 令牌失效 → 清除本地令牌 → 重新占座 |
| `deck-invalid` | 显示 `message`（含具体卡 id/违规类型），回到构筑 |
| 请求抛异常（连接断） | 进入重连流程（§8.6），**不要静默重试风暴** |
| 长静默 | 30s 发 `ping`；45s 无响应即判定断线 |

**不要**：失败后轮询 `observe.view` 试探状态。所有状态变化都有推送。

## 10. 渲染与交互注意

1. **主线程**：网络回调在后台线程，必须 `CallDeferred` 回主线程再碰节点。
2. **不要轮询**：状态靠 `notify/view`；卡住了用 `observe.view` 拉一次全量。
3. **推送可能被丢弃**：服务端推送队列有界（256，丢最旧）。不要假设每帧都到；**段不是状态来源**。
4. **隐藏信息**：`{"$hidden":true}` 只播动画（如对手抽牌），不要猜卡；对手手牌根本不在投影里。
5. **空槽**：用 `frontLineSlotCount` / `supportLineSlotCount` 画槽，不要数卡片。
6. **卡类型**：用 `definition.cardType` 区分单位/指令/反制；未知值按“不可操作”处理。
7. **可操作性**：一律来自 `actions`；`canPlayCard` 等卡级字段只作辅助提示。
8. **数值**：卡面显示用 `effective*`（含光环）；`definition.base*` 只作参考，`null` 表示不适用而非 0。
9. **美术/文本**：`artPath`/`text` 恒空，用 `cardId` 查本地表；查不到用占位图。
10. **终局**：只认 `outcome`，不要用 `resultTitle` 文本反推。
11. **拖拽**：拖指令卡即刻调 `command_pre`，不要等放下；取消零副作用。
12. **重连**：`seatToken` 必须持久化；重连后必须 `observe.view` 重建，不能靠“记住的旧状态”。

## 12. 已知限制（不要当成 bug 报）

| 限制 | 影响 | 现状 |
|---|---|---|
| `orderTargets` 恒空 | 指令不能悬停预览目标 | 拖出即 `command_pre`，候选由 `target.request` 提供 |
| 伤害是基础值 | 与真实结算可能不符 | 只能显示“大致伤害” |
| `attackPreviews` 不判护卫 | 候选里可能含打不到的目标 | 按候选高亮，失败由服务端拒绝 |
| 段不补发历史 | 重连后没有离线动画 | 重连只拉全量投影 |
| 终局不发 `notify/match.ended` | 需看 `view.phase == "over"` | 对局对象终局后仍存活 |
| `target.claim` 已退役 | 不要用它抢选靶 | 保留仅为兼容 |
| WebSocket 承载 | 只能用 NDJSON/TCP | 未实现（可选） |
| 一服务端一局 | 不能承载多桌 | 需多实例 |
| 无观战/回放/账号/匹配 | 无第三方只读连接 | 范围外 |
| 示例卡包 `samples/card-pack-ai` | 只有 5 种卡，凑不出 39 张合法构筑 | 诊断/AI 夹具关规则；真实卡包必须合规 |

|---|---|
| 连不上 | 端口（`ServerProcess.Port` / `room.info.addresses`）；Windows 防火墙首次监听会弹窗 |

### 14.3 最小可跑骨架（伪代码）

```csharp
// 1. 拉起服务端
using var server = await ServerProcess.StartAsync(new(...));

// 2. 连接 + 握手
using var client = await OrcClient.ConnectAsync(new(host, server.Port));
await client.InitializeAsync(new() { ClientName = "godot" });

// 3. 推送分发（后台线程 → CallDeferred）
client.NotificationReceived += n => CallDeferred(nameof(OnPush), n.Method, n.Params!.ToJsonString());

// 4. 开房/占座
var claim = await client.CallAsync("room.claim", new JsonObject {
    ["seat"] = 0, ["kind"] = "local", ["name"] = "我", ["deck"] = deckArray });
SaveToken(claim.Details!["seatToken"]!.GetValue<string>());

// 5. 开局
await client.CallAsync("room.start", new JsonObject { ["seatToken"] = token });

// 6. 渲染循环：只消费 notify/view
void OnPush(string method, string json) {
    if (method == "notify/view") { var p = JsonNode.Parse(json)!; Render(p["view"]!, p["actions"]!); }
    if (method == "notify/target.request") ShowTargeting(JsonNode.Parse(json)!);
    if (method == "notify/segment") PlaySegments(JsonNode.Parse(json)!);
}
```
