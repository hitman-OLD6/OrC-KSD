# 无头对战开发指南

> 面向：在这个仓库里**做卡、调卡、跑引擎回归**的人。  
> 结论先给：所有"跑一局看效果"的事，都走这套无头环境——一条命令起实例，AI 或 MCP agent 占座，事件流落盘。  
> 相关文档：`requirements.md`（需求）、`implementation.md`（实现）、`AGENT-PLAYBOOK.md`（临时交接单，已被本文取代）。

---

## 1. 它能做什么

| 场景                  | 用什么                                   | 是否需要 agent   |
| ------------------- | ------------------------------------- | ------------ |
| 引擎回归（跑 N 局看有没有崩/卡死） | `ai + ai` ＋ `--games N`               | 不需要          |
| 新卡验证（看一张卡在真实对局里的表现） | `ai + agent` 单局                       | 需要（人或 agent） |
| 边跑边改卡（不重启换卡）        | `--mode sandbox --allow-debug-writes` | 需要编排连接       |
| 摆局面（直接造卡/单位化/设点数，不逐张出牌） | `--mode sandbox --allow-debug-writes` ＋ `sandbox.*` 调试原语 | 需要编排连接 |

三种模式的差别只有两点：**谁占座**、**调试工具有没有**。

## 2. 快速开始

### 2.1 引擎回归（最快，无人值守）

```bash
cd D:/OrC-KSD
bash scripts/headless.sh --seat0 ai --seat1 ai --games 3 --seed 7 --packs samples/card-pack-demo
```

产物（默认在 `./.orc-run/<时间戳>/`，或 `--run-dir` 指定）：

```
<run-dir>/
  summary.json           # 全局汇总（games/completed/failed/perRun[]）
  runs/run-001/
    events.jsonl         # 全知事件流（每行一整段）
    calls.jsonl          # 工具调用流水（谁、调了什么、结果码、耗时）
    summary.json         # 单局摘要（winner/turns/endReason/seed/卡组指纹）
    server.stderr.log
```

判读：`exit code 0` ＋ `summary.json.games == 期望局数` ＋ 每局 `endReason` 非 null。

### 2.2 用 agent 打一局（AI vs MCP agent）

```bash
bash scripts/headless.sh --mode play --packs samples/card-pack-demo --seat0 ai --seat1 agent
```

脚本做四件事：起实例 → 等 agent 入座 → 打印端口/运行目录/**可直接粘贴的 `mcpServers` 片段** → 终局后退出。

实例在 agent 连上之前**不会开局**（`--wait-agent` 默认 300 秒，超时退出码 3）。

### 2.3 改卡调试（sandbox）

```bash
bash scripts/headless.sh --mode sandbox --allow-debug-writes --packs samples/card-pack-demo
```

- 读类调试工具（`observe.snapshot`、`observe.segments`、`card.list`、`pack.info`、`diag.*`）默认就有；
- 写类（`card.write`、`card.load`、`effect.write`、`asset.*`、`editor.*`、`sandbox.*` 调试原语）**必须**加 `--allow-debug-writes`，且只对"回环 + 未绑定座位"的连接可见可用。
- `sandbox.*` 原语共 6 个（`instantiate` / `unitize` / `move` / `remove` / `points` / `draw`），语义与硬门槛见 §5.6。

## 3. 接 MCP

### 3.1 宿主里接（WorkBuddy / Claude Desktop 等）

把片段写进 MCP 配置（WorkBuddy 是 `~/.workbuddy/mcp.json`）：

```json
{
  "mcpServers": {
    "orc-seat1": {
      "command": "dotnet",
      "args": [
        "D:/OrC-KSD/src/Orc.Mcp.Bridge/bin/Debug/net8.0/Orc.Mcp.Bridge.dll",
        "--connect", "127.0.0.1:51888",
        "--token-file", "D:/OrC-KSD/outputs/agent-match/mcp-run/agent.token"
      ]
    }
  }
}
```

三条硬性注意：

1. **必须用绝对路径**（客户端工作目录不确定）。
2. **不要用 `dotnet run`**：首次构建会把 MSBuild 输出写到 stdout，MCP 客户端读到非 JSON 帧直接崩。只用 `dotnet <dll>`。
3. 信任后**工具不会热加载**——新开会话或重启宿主；且服务端要跑在**宿主之外**（独立终端），否则宿主重启时会把服务端一起回收，桥连不上、工具不注册。

### 3.2 不接宿主（自己写客户端）

`Orc.Client` 直连 TCP 即可，协议是 NDJSON。参考 `outputs/agent-match/play_match.py`（一个完整的陪练客户端）。

### 3.3 工具面

- 桥专属：`seat.state`、`seat.segments`、**`seat.board`**（新增，见 §4）。
- 服务端透传：`observe.view`、`play.*`、`command.*`、`match.*`、`target.*`、`room.*`、`service.*`、`docs.*`。
- 沙盒专属（`--mode sandbox` 才有）：`sandbox.*` 调试原语、`card.*`、`effect.write`、`asset.*`、`editor.*`、`diag.*`、`observe.snapshot`。写类还需 `--allow-debug-writes`。
- 每次 `tools/call` 的返回是 `{"result": <服务端结果>, "state": <桥精简状态>}`。

## 4. Agent 的每回合循环（照这个写）

**不要用 `observe.view` 做常规决策**——单次返回 3–5 万字符（全量卡定义＋所有攻击预览），十几回合就把上下文打爆。  
用 **`seat.board`**：约 1–2 KB，只有决策必需字段。

```text
loop:
  board = seat.board
  if board.phase == "over": break
  if board.phase == "mulligan": mulligan.done(owner=1); continue
  if board.yourTurn == false: sleep 200ms; continue

  # 1) 出牌：用 emptySupportSlots（已排除 HQ 占的槽）
  for uid in board.playable:
      if uid in [c.uid for c in board.hand] and is_unit(uid):
          play.unit(ref=uid, owner=1, slot=board.emptySupportSlots[0])
          if 返回 targeting: target.submit(sessionId=details.pending.sessionId, picks=[候选 index])

  # 2) 攻击：用 board.attackPreviews（已含 dies 判定；候选与 command.attack 同源）
  for pv in board.attackPreviews where pv.attackerUid in my_units:
      if pv.defenderDies and not pv.attackerDies:
          command.attack(ref=pv.attackerUid) → target.submit(picks=[该 defender 的 index])

  # 3) 无动作 → 结束回合
  match.end_turn
```

> `details.pending.sessionId` 是每一次 `target.submit` 的必填参数；`details.pending.action` 告诉你这一步在选什么
> （`attack` / `move` / `deploy` / `effect` / `mulligan`；指挥拖拽的合并请求为 `command`）。

`seat.board` 的字段：

```json
{
  "turn": 26, "phase": "play", "activeSide": "self", "yourTurn": true,
  "kredits": {"self": 12, "max": 12},
  "hq": {"self": 10, "enemy": 20},
  "handCount": 4,
  "armedCounterCount": 1,
  "hand":    [{"uid":"…","name":"步枪兵","cost":0,"atk":1,"hp":2,"handIndex":0,"zone":"hand","isCounterArmed":false}],
  "selfLine":[{…,"slot":1,"zone":"support","isCounterArmed":false}],
  "enemyLine":[{…,"slot":2,"zone":"frontline","isCounterArmed":false}],
  "emptySupportSlots": [0,3,4],
  "emptyFrontSlots": [],
  "playable": ["uid…"],
  "attackPreviews": [{"attackerUid":"…","defenderUid":"…","damageToDefender":3,
                      "damageToAttacker":2,"defenderDies":true,"attackerDies":false}],
  "moves": [{"uid":"…","toZone":"front","slotIndex":3}],
  "pendingSessionId": null
}
```

要点：

- `emptySupportSlots` 已经把 **HQ 占用的槽**（通常是 slot 2）排除掉了——别自己按 `0..4` 硬填。
- **手牌序号是 `handIndex`，战线序号是 `slot`**：两者不同域。手牌第 2 张 ≠ 支援线 2 号槽；用 `handIndex` 找卡，
  用 `slot` 找槽位。
- `handCount`＝手牌总数（含已武装的反制）；`armedCounterCount`＝已武装的反制数（与 `observe.view` 的 `selfCounterCount` 同口径）。
  判断某张反制是否已武装，读该卡的 `isCounterArmed`。
- `attackPreviews.dies` 是**基础伤害判定**（不含词条/效果改写）。它告诉你"这一击按裸伤害能不能打死"。
  预览的 `(attackerUid, defenderUid)` 与 `command.attack` 的候选**逐一对应**（同一份引擎候选）——预览里没有的目标，
  发起攻击也不会出现在候选里；反之亦然。
- `moves` 同样来自引擎移动候选：`toZone` 为 `front`（推进到前线空槽）或 `support`（后撤到己方支援线空槽），
  `slotIndex` 的语义随 `toZone` 解释。
- `pendingSessionId` 非空时才需要 `target.submit`；动作一旦结束它会被清空（见 §8）。

## 5. 做一张新卡：完整流程

### 5.1 放哪里

```
samples/card-pack-<你的包>/
  manifest.json
  cards/
    <你的卡id>.card.json          # 卡数据体（组件式）
  effects/
    <效果id>.prefab.json          # 可选的独立效果预制体
```

`--packs` 可以给多个目录（`;` 分隔）。

### 5.2 最小卡数据体

卡是"组件数组"，不是扁平字段：

```json
{
  "schemaVersion": 1,
  "id": "demo.grenadier",
  "name": "掷弹兵",
  "components": [
    { "component": "typeCategory", "type": ["infantry"] },
    { "component": "factionCost", "faction": "Germany", "kredits": 1 },
    { "component": "battleStats", "operationCost": 1, "attack": 2, "defense": 3 },
    { "component": "tagData", "rarity": "Standard" },
    { "component": "effects", "inline": [ /* 内联效果：mainTrigger + hooks + csx 入口 */ ] }
  ]
}
```

完整样例见 `samples/card-pack-demo/cards/demo.grenadier.card.json`（含内联 `unit.deployed` 效果的 csx 写法）。

### 5.3 校验

三层，从便宜到贵：

1. **写盘即校验**：`card.write` 会先解析，JSON 非法或结构不符**拒绝落盘**；`asset.validate` 可 dry-run。
2. **启动即校验**：实例装载 `--packs` 时解析全部卡；非法卡在**启动期**报错，不会带病进对局。
3. **对局内校验**：sandbox 模式 `card.load` 逐卡注册进当前对局（只追加、不覆盖），返回失败清单。

### 5.4 让新卡真的出场

这是最容易踩坑的一步：

- **AI 卡组是随机生成的**（`AiDeckGenerator`），新卡不一定被抽到。
- 想要稳定出场，选一个：
  - **小卡包**：让卡包里只有新卡 + 2–3 张填充卡，`--deck-rules lenient` 下会按 39 张填满（会重复同一张）；
  - **sandbox 边跑边加**：`--mode sandbox --allow-debug-writes`，对局中用 `card.write` 改卡、`card.load` 注册，然后 `shape.*` 摆出你要的局面；
  - **固定种子**：`--seed N`，同包同种子可复现同一开局（摘要里会记录实际种子）。

### 5.5 看结果

```bash
# 这局谁赢、几回合、为什么结束
cat <run-dir>/summary.json

# 事件流：每行一整段，含完整因果子树
python -c "
import json
for line in open(r'<run-dir>/events.jsonl', encoding='utf-8'):
    seg = json.loads(line)
    for e in seg['entries']:
        print(seg['sequence'], e.get('kind'), e.get('source'), e.get('message'))
"
```

- `events.jsonl` 是**全知**的（双方手牌都在），段序号从 **1** 起、逐局重开。
- `--log-seat-views` 额外产出 `seat0.jsonl` / `seat1.jsonl`（按座位脱敏，对手手牌写 `$hidden`）。
- 段与会话流水用 `sequence` 对齐；`calls.jsonl` 的 `segmentsFrom/To` 指向该次调用产生的段区间。

### 5.6 用调试原语摆局面（不用逐张出牌）

沙盒模式下有 6 个原语，**语义等价于"一张卡的效果做同样的事"**：该发的信号全发、该触发的监听全触发（`card.placed`、`unit.joined`、`card.drawn`、亡计结算……），只跳过**校验层**、保留**硬门槛**。

| 工具 | 参数 | 语义 |
|---|---|---|
| `sandbox.instantiate` | `definitionId`、`owner`、`zone`(`hand`/`deck_top`/`support`/`frontline`)、`slot` | 造卡并落到指定去向。**可指定精确槽位**（既有 `sandbox.spawn` 只能放支援线首个空槽） |
| `sandbox.unitize` | `ref`、`line`(`support`/`frontline`)、`slot` | 把单位卡单位化到指定槽；发 `card.placed` ＋ `unit.joined` |
| `sandbox.move` | `ref`、`line`、`slot` | 挪到另一空槽；不扣行动费、不消耗行动次数，跨线允许 |
| `sandbox.remove` | `ref` | 移除实体：在手牌→弃置链、在场单位→死亡链（结算亡计）、其余→一步式销毁 |
| `sandbox.points` | `owner`、`points` | 把点数**设为绝对值**（可低于当前值）；不受槽数限制，超出时返回 `warning: points-exceed-slots` |
| `sandbox.draw` | `owner`、`count` | 抽 N 张；满手按既有爆牌裁决（成功语义） |

**跳过什么**：指挥点是否够、是否己方回合、卡是否在该玩家手牌、相位是否允许、是否需要选靶交互、行动次数/行动费用。

**保留什么（硬门槛，触到即明确失败、零状态变更）**：阵线容量（各 5 槽）、槽位被占、单位已单位化、实例唯一归属（不能同时在两个区域）、已销毁实例不可放置。**手牌上限不在此列**——满手是爆牌，不是失败。

**新旧工具并存，别混用**：

| 旧（行为不变） | 新原语 | 差异 |
|---|---|---|
| `sandbox.spawn { definitionId, owner, zone }` | `sandbox.instantiate`（四去向、精确槽位） | 新面覆盖旧面，旧面保留 |
| `sandbox.set_points { owner, delta }`（**增量**，负值失败） | `sandbox.points { owner, points }`（**绝对值**，可减） | 参数与信号口径都不同 |
| `sandbox.kill` / `sandbox.damage` / `sandbox.emit` | —（无对应原语） | 继续使用 |

典型用法：

```jsonc
// 造一张卡到玩家 1 手上
{ "name": "sandbox.instantiate", "arguments": { "definitionId": "demo.grenadier", "owner": 1, "zone": "hand" } }

// 把它直接单位化到支援线 3 号槽（跳过费用与回合）
{ "name": "sandbox.unitize", "arguments": { "ref": "<上一步返回的 ref>", "line": "support", "slot": 3 } }

// 给双方补够费用
{ "name": "sandbox.points", "arguments": { "owner": 1, "points": 12 } }
```

**槽位编号两条线各自 0–4**，别把"前线 3 号"当成"支援 3 号"；HQ 通常占支援线 2 号槽（相关坑见 §8）。

## 6. 必须知道的规则（不然会打得很奇怪）

1. **槽位**：支援线 5 槽，**HQ 占其中一槽（通常是 2）**；前线 5 槽。出牌只能用空支援槽。
2. **单位每回合只能攻击一次**，且**当回合刚出场的单位不能攻击**。
3. **移动后不能再攻击**（`moves` 里的目标只是"能移到哪"，不是"移过去还能打"）。
4. **出牌与攻击共用费用池**：实测每次攻击后 `kredits` 减 单位的行动花费(和移动一样)。
5. **牌库抽空后引擎拒绝空抽**：`end_turn` 会返回 `not-ready`（message 是"卡组名单为空，无法抽取"）。无头默认 `lenient` 会补满 39 张，正常不会撞上。
6. **play 与 sandbox 的视角不同**：`play` 只给你按座位过滤的视图（看不到对手手牌明细）；`sandbox` 全知。
7. **`observe.view` 的 `attackPreviews.dies` 是裸伤害判定**，不考虑词条/效果改写；真正的结果以事件流为准。
8. **调试原语只摆状态，不替你判"能不能打"**：`sandbox.instantiate` / `unitize` 成功只说明状态摆对了，不代表这张卡此刻符合出牌条件。要判"能不能打"仍用 `play.can_play` 或 `seat.board.playable`。反过来，原语**不受**费用/回合/相位限制——这正是它存在的意义。

## 7. 参数速查

### 服务端（`Orc.Server.dll`）

| 参数                                        | 说明                                      |
| ----------------------------------------- | --------------------------------------- |
| `--headless`                              | 开启无头编排（预置座位/自动开局/日志/退出码）；**不开＝与现状完全一致** |
| `--mode play\|sandbox`                    | 权限面，默认 `play`；与 `--headless` 正交         |
| `--packs <dir[;dir]>`                     | 卡包目录                                    |
| `--seat0 ai\|agent` / `--seat1 ai\|agent` | 座位角色，默认 `ai + agent`                    |
| `--run-dir <dir>`                         | 运行目录（日志/令牌/摘要）；相对路径会自动绝对化               |
| `--port <n>`                              | 监听端口，`0`＝系统分配                           |
| `--seed <n>`                              | 随机种子（卡组生成与建局同源，可复现）                     |
| `--deck-rules strict\|lenient`            | 卡组校验档位，无头默认 `lenient`                   |
| `--wait-agent <秒>`                        | 等 agent 入座上限，默认 300                     |
| `--exit-on-end` / `--keep-alive`          | 终局自退（默认）/ 终局后存活（不支持再来一局）                |
| `--log-seat-views`                        | 额外产出按座位脱敏的双流                            |
| `--allow-debug-writes`                    | sandbox 下注册写类调试工具                       |

退出码：`0` 正常终局 / `1` 启动失败（含参数错误）/ `2` 运行期异常 / `3` 等 agent 超时。

### 脚本（`scripts/headless.sh`）

覆盖上面全部参数，另加：`--games <n>`（批量，仅 `ai+ai`）、`--no-build`（跳过构建）、`-h`。

### 桥（`Orc.Mcp.Bridge.dll`）

```bash
dotnet Orc.Mcp.Bridge.dll --connect <host:port|port> --token-file <agent.token>
```

退出码：`0` 正常收尾（含服务端退出）/ `2` 令牌失效（实例已重启，重新读 `agent.token`）。

## 8. 已知坑与排障

| 现象                                       | 原因                             | 处理                                     |
| ---------------------------------------- | ------------------------------ | -------------------------------------- |
| 工具列表里没有 `orc-seat1`                      | 宿主只在启动时加载 MCP；服务端若也死了，桥连不上就不注册 | 服务端跑独立终端 → 重启宿主                        |
| `SocketException: 每个套接字地址只能使用一次`         | 端口被占（含上一轮实例残留）                 | `netstat -ano \| grep :<port>`，换端口或杀残留 |
| 桥返回 `not-connected`                      | 服务端已退出（端口关闭）                   | 重启实例；桥会自行退出 0                          |
| 桥返回 `unauthorized`                       | `agent.token` 失效（实例重启过）        | 重新读 `agent.token`，重启桥                  |
| `end_turn` 返回 `not-ready`（"卡组名单为空"）      | 牌库抽空                           | 换大卡包；确认 `--deck-rules lenient`         |
| `play.unit` 返回 `TargetSlotOccupied`      | 槽被 HQ 或已有单位占用                  | 用 `seat.board.emptySupportSlots`       |
| `command.move` 后攻击返回 `NoActionAvailable` | 移动与攻击互斥（同回合）                   | 先攻击，或下回合再攻击                            |
| 反制激活了却拦不住指令 | 效果的 `viewType` 写成了 `CardEventView`（被判类型不符而隔离），或 csx 里没写 `ctx.Stop()` | 改 `CardTriggerView`（§10.2）；查 `events.jsonl` 的 `signature` / `unsupported-*` 记录 |
| 反制卡的效果"没反应" | 声明了 `otherTriggers` / `wrappers`——反制效果只承认 handler 面，这类声明会让整条效果不装配 | 去掉这两个面；Error 级留痕会指出是哪条 |
| `sandbox.spawn zone=support` 放不进去 | 旧工具只取支援线首个空槽，HQ 通常占 2 号槽 | 改用 `sandbox.instantiate { zone: "support", slot }` 精确指定 |
| 点数被设到超过槽数 | 引擎没有"点数 ≤ 槽数"这条不变量 | 不是错误；返回带 `warning: points-exceed-slots` |

**已修的五处**（2026-10-21，见各需求目录的 `PROGRESS.md`）：

1. `pendingSessionId` 提交成功后不清除 → 现在动作类调用结束即以返回载荷为准（有则更新、无则清空）。
2. `seat.state` 落后推送帧一帧 → 现在 `seat.state` / `seat.board` 返回前用 `observe.view` 权威刷新。
3. `attackPreviews.dies` 恒为 `false` → 现在按有效攻击力 vs 有效血量计算（不含词条改写）。
4. 反制卡的数据效果被装成总线监听、拦截不了指令 → 现在装载时装配成 `OrderFlow` 的 `Counter` 段 handler，`ctx.Stop()` 即拦截（见 `docs/反制效果装配/`）。
5. 反制卡激活中被销毁会在 `Counter` 段留下悬空注册 → 现在订阅 `card.destroyed` 注销，不退费。

## 9. 什么算"这局跑通了"

- 进程退出码 `0`；
- `summary.json` 的 `winner` / `turns` / `endReason` 非空；
- `events.jsonl` 段序号从 1 连续、无缺号；
- `calls.jsonl` 里没有 `not-connected` / `unauthorized`；
- 若开了 `--log-seat-views`，三份流的同一段序号能对齐。

达到这五条，就说明"实例、座位、桥、日志、终局"整条链是通的，可以在这上面做卡了。

## 10. 三条链怎么验（指令 / 反制 / 新卡）

前提：`--mode sandbox --allow-debug-writes`，且用编排连接（回环 + 未绑定座位）。

### 10.1 指令链

```
card.write → card.load（注册定义）
  → sandbox.instantiate { zone: "hand" }（造指令卡入手）
  → sandbox.points { points: 12 }（补够费用）
  → 若当前行动方不是该卡 owner：match.end_turn 推进到其回合
  → play.command { ref }
  → 断言：card.played 恰一次、点数扣减、卡离手、主动效果生效
```

`play.command` 仍走完整动作链（费用校验、己方回合、卡在手牌），所以前四步是必要的。

### 10.2 反制链

反制卡的效果**不是监听**，而是"激活时注册到 `OrderFlow` 的 `Counter` 段"。写法有硬要求：

```json
"mainTrigger": {
  "kind": "passive",
  "viewType": "Orc.Game.Triggers.CardTriggerView",
  "events": [{
    "id": "onCounter",
    "entry": "HandleAsync",
    "csx": "Func<Orc.Game.Triggers.CardTriggerView, Context, CancellationToken, Task> HandleAsync = (view, ctx, ct) => { ctx.Stop(); return Task.CompletedTask; };"
  }]
}
```

- **`viewType` 必须是 `CardTriggerView`**。写 `CardEventView` 会被判类型不符、整条隔离（Error 级）。
- `ctx.Stop()` ＝命中：本次指令的结算段不执行（**不发 `card.played`**、效果不触发），但照常扣费离手。
- `ctx.Interrupt()` ＝强反制：牌留手、不扣费。
- 都不调 ＝未命中：指令正常结算，反制保持激活、不消耗。
- 可读字段：`ctx.Source`＝被反制的指令卡、`ctx.Target`＝施放目标、`ctx.Argument`＝数值、`ctx.Card`＝反制卡本身、`ctx.Player`＝持有者。
- 声明 `otherTriggers` 或 `wrappers` ⇒ 该条效果**不装配**（Error）。反制效果只承认 handler 面。
- 反制卡的效果**不挂事件总线**：不会因为指令打出而"事后触发"响应——这正是 `Stop` 能生效的前提。

验证步骤：

```
sandbox.instantiate（反制卡 → 到手，owner B）
  → sandbox.points（双方补够）
  → match.end_turn 推进到 B 的回合
  → play.counter { ref }（激活；扣点）
  → match.end_turn 推进到 A 的回合
  → play.command { ref }（A 打指令）
  → 断言：card.played 计数 0、指令仍扣费离手、反制卡进入弃置（card.discarded）、反制 IsConsumed
```

### 10.3 新卡链

```
card.write（写盘即校验，非法拒绝落盘）
  → card.load（逐卡注册进当前对局，只追加不覆盖）
  → sandbox.instantiate（造出来）
  → 打出 / 观察效果
  → 断言：效果按预期触发；negative 用例：非法定义在 card.write 或 card.load 被拒
```

改一张已加载的卡必须**换新 id**（`card.load` 只追加不覆盖），否则会返回 `alreadyRegistered`。

验证清单（逐条打勾即可）：

- [ ] 指令：`card.played` 一次、扣费、离手、效果生效
- [ ] 反制：`Stop` 后 `card.played` 为 0、指令仍扣费离手、反制弃置且不可再激活
- [ ] 新卡：`card.write` → `card.load` → `sandbox.instantiate` → 打出，效果符合预期
- [ ] 三条链的段序号连续、`calls.jsonl` 无 `not-connected` / `unauthorized` / `internal`
