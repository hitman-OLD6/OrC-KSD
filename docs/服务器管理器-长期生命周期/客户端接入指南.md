# 客户端接入指南（现行协议，v2）

> 适用版本：多人联机模型重构（管理器-服务器-房间-seat-viewer-controller）落地之后。
> 本文件是**唯一现行**的接入依据；`前端交接-协议变更与API参考.md` 是重构前的预稿，已作废（见该文件顶部横幅）。
> 事实来源：`src/Orc.Server/Transport/ServerHost.cs`、`src/Orc.Protocol/*`、`src/Orc.Server/Admin/AdminApi.cs`。

## 0. 一句话

连上 → `initialize`（拿 `connectionId`）→ `session.attach`（申请角色＋座位＋卡组＋卡包，**立即返回 pending**）
→ 等 `notify/admission`（管理员批准）→ 用 `tools/list` / `tools/call` 打牌或观察。

**没有** `room.claim` / `room.resume` / `room.start` / `notify/room` / `seat.request`，也不保留 v1 兼容层。

## 1. 传输与信封

- TCP ＋ NDJSON（一行一帧，UTF-8，LF）。
- JSON-RPC 2.0 外形：请求 `{jsonrpc,id,method,params}`；响应 `{jsonrpc,id,result|error}`；推送 `{jsonrpc,method,params}`（无 `id`）。
- 业务失败**不占** `error`：放在 `result` 里的 `{ok:false, code, message, details}`。
- `error` 只承载解析错误、未知方法、参数类型错误。

### 1.1 请求方法（6 个）

| 方法 | 用途 |
|---|---|
| `initialize` | 版本协商；**唯一返回 `connectionId`**（还有 `roomId`/`label`） |
| `ping` | 心跳（也是"连接活着"的入站帧证据） |
| `session.attach` | 申请角色＋座位＋卡组＋卡包声明（一条报文带齐） |
| `session.detach` | 撤回申请／释放座位（对局态＝等价于断线，进入宽限） |
| `tools/list` | 按角色过滤后的工具清单 |
| `tools/call` | 调工具 |

### 1.2 推送（7 条）

| 通知 | 载荷要点 |
|---|---|
| `notify/view` | `{perspective:{mode:"seat",seat:N}, view, actions}` 或 `{perspective:{mode:"omniscient"}, views:[{seat,view,actions}×2]}` |
| `notify/segment` | `{perspective:{...}, segments:[...]}`（绑座＝脱敏段；全知＝全量段） |
| `notify/target.request` | 待决选靶（含 `sessionId`、候选） |
| `notify/target.expired` | 待决已过期 |
| `notify/admission` | `{decision:"admitted"|"rejected"|"revoked", roles, seat, seatToken?, reason?}` |
| `notify/room.rotated` | `{roomId, seatCount, epoch}`：旧房间终结，新 lobby 就绪 |
| `notify/room.seats` | `{roomId, seats:[{seat,occupied,state,displayName}]}`（**不含** deck/packages） |

`notify/match.started` / `notify/match.ended` **已删除**：开局/终局从 `notify/view` 的 `view.phase/outcome` 与 `notify/room.rotated` 读。

## 2. 连接的三段状态（前端状态机的基础）

| 服务端态 | 协议名 | 能做什么 |
|---|---|---|
| 已握手 | `connected` | `initialize`/`ping`/`session.attach`/`room.info` |
| 申请中 | `pending` | `ping`/`session.detach`/`room.info`；**零推送、零动作** |
| 玩家面 | `admitted` | 该 seat 的动作工具（`play.*`/`command.*`/`match.*`/`mulligan.*`/`target.*`）；兼任 viewer 时另收该 seat 脱敏视图 |
| 绑座观察 | `viewer` | `observe.view` ＋ 该 seat 脱敏推送；不能提交动作 |
| 全知观察 | `omniscient` | `observe.view` ＋ 全知推送；不能提交动作 |
| 调试面 | `debug` | 调试工具集（回环来源）；不收对局推送 |
| 已撤销 | `revoked` | 无；可重新 `session.attach` 申请 |

> 角色是"态"而不是若干布尔字段：不存在"既绑 seat 又能调调试 API"或"绑了 seat 却收全知输出"的组合。

## 3. 握手

```json
→ {"jsonrpc":"2.0","id":"1","method":"initialize","params":{"clientName":"godot","protocolVersion":"2.0","label":"player-a"}}
← {"jsonrpc":"2.0","id":"1","result":{"protocolVersion":"2.0","schemaVersion":1,
     "capabilities":["push","targeting","session","admin-channel"],
     "connectionId":"9f3c…","label":"player-a","roomId":"a1b2c3d4"}}
```

- `protocolVersion` 不匹配 ⇒ `error`（参数错误），不是业务失败。
- `label` 只是人读标签，不参与鉴权；管理员据此指代连接。

## 4. 申请角色

```json
→ {"jsonrpc":"2.0","id":"2","method":"session.attach","params":{
     "roles":["controller"],
     "seat":0,
     "displayName":"玩家A",
     "deck":["pack/ai.sample/ai.sample.infantry", "…39 张"],
     "deckConfig":{"mainFaction":"germany","allyFaction":null},
     "packages":[{"packageId":"ai.sample","version":"1c7bccff…","guid":"b0070000-…"}]
   }}
← {"jsonrpc":"2.0","id":"2","result":{"connectionId":"9f3c…","state":"pending","seat":null,"roles":[],"message":"申请已提交，等待管理员批准。"}}
```

规则：

- `roles` 取值：`controller` / `viewer` / `debug`；`controller` 与 `debug` 不能同时申请。
- `controller` 必须带 `seat`（0/1）、非空 `deck`、`packages`（引用形态）——否则拒绝（`code` 可读）。
- 只 `viewer` 且不带 `seat` ⇒ 全知（仍需管理员批准）。
- `debug` 只接受回环来源；**申请即生效**（返回 `state:"debug"`）。
- 申请已被占用的座位 ⇒ **同步拒绝** `{state:…, code:"seat-taken"}`，不产生 `pending` 记录。
- 重连：带 `token`（上次批准拿到的 `seatToken`）⇒ 跳过 `pending` 直接恢复；令牌无效 ⇒ `code:"invalid-token"`。

批准由管理员执行（管理面），结果经**本连接自己的** `notify/admission` 下发：

```json
{"jsonrpc":"2.0","method":"notify/admission","params":{
  "decision":"admitted","roles":["controller"],"seat":0,"seatToken":"6b1e…"}}
```

前端应持久化 `seatToken`（仅用于断线重连；房间轮换后失效）。

## 5. 房间态

`room.info` 对 `connected`/`pending` 也可调（否则未申请者看不到空位）。

```json
{"roomId":"a1b2c3d4","state":"lobby","seatCount":2,
 "seats":[
   {"seat":0,"occupied":true,"state":"admitted","displayName":"玩家A","kind":"remote","deck":["…"],"packages":[{"packageId":"ai.sample"}]},
   {"seat":1,"occupied":false,"state":"idle","displayName":null}],
 "addresses":[{"ip":"192.168.1.7","port":51888}]}
```

- 只给自己：`deck` / `packages`。
- **对手的 `deck`/`packages` 永不出现**——全知 viewer 也看不到（全知是对局输出，不是构筑隐私）。
- 调试面读全量声明。
- 座位状态变化经 `notify/room.seats` 推送（delta，不含 deck/packages）。

## 6. 对局输出

- **绑座 viewer（含 controller+viewer 兼任）**：每次状态变化收 1 条单视角帧 ＋ 1 条脱敏段。
- **全知 viewer**：1 条全知帧（`views` 含两份 seat 视角）＋ 1 条全量段。
- 只 controller、不兼任 viewer 的连接**不收**任何对局数据。
- 客户端区分帧类型**只看 `perspective.mode` / `perspective.seat`**，不做形状嗅探（"有没有 `views`"不算判据）。
- `observe.view` 与推送同形（重连拉全量用）：绑座＝单视角帧；全知＝全知帧；调试面＝对局摘要（含双方手牌）。

## 7. 断线、终止与轮换

| 场景 | 行为 |
|---|---|
| lobby 态 controller 断线 | 立即释放座位，可被重新申请 |
| 对局态 controller 断线 | 绑定保留；宽限**只在轮到该 seat 时**计时；到期服务器代其认输 |
| 局中换人 | 不允许：只能原 controller 凭 `seatToken` 重连；换人须 `room.abort` → 轮换 → 重新申请 |
| 管理员撤销 controller | 立即生效、不给宽限（对局中＝该 seat 认输并结束） |
| 管理员终止对局 | 无胜者：`winner=null`、`endReason="Aborted"` |
| 终局 | 服务器**不退出**：产出新 lobby，推 `notify/room.rotated`；绑座角色退回 `revoked`（调试面保留） |

轮换后：

- 用旧 `roomId` 调工具 ⇒ `stale-room`（不静默按新房间处理）。
- 用旧 `seatToken` 重连 ⇒ `invalid-token`。
- 不需要重新握手、不需要重拉 `tools/list`（描述符集合跨房间稳定）。

## 8. 错误码（客户端应按码分支，不靠 message）

`ok` / `not-admitted` / `seat-taken` / `stale-room` / `stale-seat` / `room-rotating`（带 `retryAfterMs`，建议 200）
/ `already-ended` / `invalid-token` / `unauthorized` / `pending-targeting` / `deck-invalid` / `busy`
/ `lock-conflict` / `missing-assets` / `instance-boot-failed`。

语义要点：

- `pending` 连接调任何动作/调试/观察工具一律 `not-admitted`（不按工具区分）。
- `room-rotating` 是**可重试**；`already-ended` 是**幂等成功**（对已结束对局调 `room.abort`）。
- 资产类判定（`lock-conflict`/`missing-assets`）由**管理器**产出；服务器原样转达。

## 9. 管理面（不在业务端口上）

- 管理面只有两个入口：`IManager` 进程内 API ＋ 管理器的 CLI（同一真身），以及**父子私有通道**
  （服务器子进程 stdin 命令 / stdout 回执＋事件）。它**不监听端口**，`tools/list` 里没有任何管理 op。
- 因此"远程可调" ⇔ 网络可达 ∧ 调用者非进程主人；父子私有通道两条都不满足，不构成远程。
- 管理 op：`connections.list` / `conn.admit` / `conn.reject` / `conn.revoke` / `seat.bind` / `seat.unbind`
  / `match.start` / `room.abort` / `sandbox.reset` / `instance.info`。
- 管理命令格式（NDJSON，一行一条）：

```json
{"id":1,"op":"connections.list"}
{"id":2,"op":"conn.admit","args":{"connectionId":"9f3c…"}}
{"id":3,"op":"match.start"}
```

回执 `{id, ok, code, message, payload}`；事件 `{event, payload}`（无 `id`）。

## 10. 最小客户端流程（伪代码）

```text
client = connect(host, port)
init = initialize(protocolVersion: "2.0", label: "player-a")   // 保存 init.connectionId
attach = session.attach(roles:["controller"], seat:0, deck:[...], packages:[...])
assert attach.state == "pending"
wait notify/admission where decision == "admitted"             // 保存 seatToken
loop:
  on notify/view      -> 按 perspective.mode/seat 渲染
  on notify/segment   -> 播放事件段
  on notify/target.request -> 呈现候选，调 target.submit / target.cancel
  on notify/room.rotated   -> 清画面，重新 session.attach（旧 seatToken 已失效）
调用动作: tools/call {name:"play.unit", arguments:{...}}
```
