# Requirements — 游戏层：手牌选靶与前线入场

为游戏层补上「从手牌选一张/多张」的通用选靶能力，并让效果侧具备「把单位直接加入前线」的入场动作面。

## Scope

- Includes:
  - 从**己方手牌**选一张或多张牌的 targeter 能力（交互式；候选由后端给出）。
  - 选择数量与当前手牌数不相容时的**取消**语义（零交互、零副作用）。
  - 效果侧「加入战场」能力，且落位可为**前线**（不扣部署费、不走部署词条）。
- Excludes:
  - 前端视觉实现（本需求只到呈现数据/语义事件）。
  - 新的选择器名与前端选择器视觉（除非确认需要）。
  - 效果 DSL / 解析器的新 op（除非确认需要）。
  - 改变既有「部署到支援线」规则、既有 `Mulligan` 换牌语义。

## Constraints

- 遵循既有 targeter 契约：候选＝后端快照；取消＝一等状态；非法选择可重试。
- 遵循 P1/P2：不做无条件数据更新、不做异步乱序传播。
- 不破坏既有基线（`contract-freeze.json`）与既有测试。

## Requirement Items

### R1: 手牌选靶 targeter

- Status: Confirmed
- Scenario/Trigger: 效果/流程需要让玩家从**己方手牌**中选择一张或多张牌（例如"弃一张牌""选择两张牌"）。
- Behavior: 系统应提供一次可复用的手牌选靶流程：候选＝该玩家当前手牌快照，点选交互，支持单选与多选，产出被选手牌。
- Acceptance:
  - [ ] 调用方给出 `min`/`max` 张数约束后，能取到被选手牌的引用列表（数量落在 `[min, max]`）。
  - [ ] 取消＝返回取消态、零副作用；非法选择＝可重试（同一选择器实例）。
  - [ ] 候选不来自前端；以手牌快照＋域判定（仍在该玩家手牌中）为准。
- Terminology: [目标选择](../../CONTEXT.md)

### R2: 张数约束与手牌数不相容＝自动取消

- Status: Confirmed
- Scenario/Trigger: 请求 `min` 张，但该玩家当前手牌不足 `min` 张。
- Behavior: 系统应直接返回**取消**态，不发起交互（不产出选择器）、不做裁剪降级。
- Acceptance:
  - [ ] `min > 手牌数` 时 `NextAsync` 不产出选择器（前端零交互）。
  - [ ] 结果三态为 `Cancelled`（不是 `Failed`、不是"空集即成功"）。
- Terminology: —

### R2a: 手牌数恰好等于 `min`＝必须交互、不得静默提交

- Status: Confirmed
- Scenario/Trigger: 手牌数恰好等于要求的 `min`（例如要 2 张、手里正好 2 张）。
- Behavior: 系统应照常发起交互，由玩家显式提交或显式取消；**不得**自动替玩家提交。
- Acceptance:
  - [ ] `min == 手牌数` 时仍产出选择器，等待玩家语义事件。
  - [ ] 玩家可提交（`Ok`）或取消（`Cancelled`），二者都被接受。
- Terminology: —

### R2b: `max` 大于手牌数＝收敛为上界

- Status: Draft（待确认）
- Scenario/Trigger: 请求"至多 `max` 张"，而手牌数少于 `max`。
- Behavior: 上界收敛为当前手牌数（仍须满足 `min`），不因此取消。
- Acceptance:
  - [ ] 手牌 2 张、请求 `min=1,max=3` ⇒ 呈现 `max=2`，可选 1~2 张。
- Terminology: —

### R3: 效果侧的「加入战场」触发器（两个触发端）

- Status: Confirmed
- Scenario/Trigger: 效果（csx handler / C# 效果）需要把某个单位加入战场。
- Behavior: 系统应向效果侧提供**两个具名加入战场触发端**——**加入前线**与**加入支援阵线**；效果侧可调用任一触发端把单位加入对应战线。加入走既有加入链（单位化＋`unit.joined`），**不扣部署费、不走部署词条**、不走打出链。
- Acceptance:
  - [ ] 两个触发端各自可调用，落位分别在前线与己方支援线。
  - [ ] 成功＝发 `unit.joined`、不发 `unit.deployed`、不发 `card.played`；指挥点不变。
  - [ ] 单位已单位化（已在场）＝失败、零副作用。
- Terminology: [加入战场](../../CONTEXT.md)、[触发器](../../CONTEXT.md)

### R3a: 加入前线的归属门禁＝效果侧自行判定

- Status: Confirmed
- Scenario/Trigger: 调用**加入前线**触发端，而前线存在**敌方存活单位**。
- Behavior: 触发端应**报错拒绝**（不落地）；"前线是否友方占领或无人"的判定由**效果处自行先行判定**，触发端不替效果作者做策略决策。
- Acceptance:
  - [ ] 前线有敌方存活单位时调用加入前线 ⇒ 失败、单位未单位化、槽位无变化。
  - [ ] 前线无敌方单位（空线或仅友方）⇒ 允许加入。
  - [ ] 效果侧可用于自判的判定口径有单一真源（复用既有 `move.frontline-enemy`：前线是否存在存活敌方单位）。
- Terminology: [判定器](../../CONTEXT.md)

### R4: 阵线语义＝有序单位列表（容量 5，HQ 计入）

- Status: Confirmed（语义＋落地口径＝硬切：`Slot` 退场，`FormationGap` 为唯一位置句柄）
- Scenario/Trigger: 任何需要表达"单位在阵线中的位置"的场合（部署、加入、移动、相邻/范围判定、UI 投影）。
- Behavior: 阵线应建模为**可插入的有序单位列表**，只约束「单位＋HQ 总数 ≤ 5」；位置由插入序决定，**不居中重排**，因此 HQ 可以在任意位置（含最左/最右）。
- Acceptance:
  - [ ] HQ 在最左、右侧 4 个单位 ⇒ 合法阵型。
  - [ ] 阵线元素数＝5 时不再有可部署位置。
  - [ ] 元素数 N<5 时，可部署位置＝N+1 个空隙（含首尾两端）。
  - [ ] 阵线元素数＝HQ 数＋单位数（HQ 占容量）。
- Terminology: [阵线/前线](../CONTEXT.md)

### R4a: 预部署候选由判定器产出

- Status: Confirmed
- Scenario/Trigger: 单位预打出需要"可用部署位置"候选。
- Behavior: 候选应由**判定器**产出（可被包装器改写），而不是由打出管理器内部硬算；位置是**临时生成**的（占用变化后旧候选失效）。
- Acceptance:
  - [ ] 预部署候选经判定器名获取（判定器名进受控常量集合）。
  - [ ] 占用变化后，旧候选不可再用于落地（失效可判别）。
  - [ ] 候选数＝N+1（N<5），满员＝0。
- Terminology: [判定器](../../CONTEXT.md)、[包装器](../../CONTEXT.md)

### R3b: 落位如何选定

- Status: Confirmed
- Scenario/Trigger: 调用任一加入战场触发端时，具体插到阵线的哪个位置。
- Behavior: 优先级＝**显式序号 > 守护 > 默认最左**。默认插到阵线**最左**（序号 0）；若该单位具**守护**（`CardDefinition.IsGuard` 或"守护"词条）则插到 **HQ 右侧**；调用方可选传入**目标序号**（插入后该单位所处的位置，0＝最左、N＝最右）。有序列表语义下**不存在"已在最右而无法插入"**：只要未满 5 个元素，右侧总可插入。
- Acceptance:
  - [ ] 无参调用、无守护 ⇒ 单位位于列表第 0 位。
  - [ ] 无参调用、有守护 ⇒ 单位紧邻 HQ 右侧。
  - [ ] 传入序号 k ⇒ 单位插入后位于第 k 位（0 ≤ k ≤ 当前元素数）；k 越界＝失败（不钳制）。
  - [ ] 目标线已满 5 个元素 ⇒ **warning 留痕＋静默失败**（返回失败、零副作用、不抛异常；非 UB——正常对局可出现）。
- Terminology: [守护](../../CONTEXT.md)、[阵线](../CONTEXT.md)

### R3c: 「报错」的形态

- Status: Confirmed
- Scenario/Trigger: 门禁不满足（敌方占线 / 无可用位置 / 已单位化）。
- Behavior: 一律**不抛异常**、返回可判别失败；差别只在留痕级别——敌方占线＝**Error** 级（"报错"），无可用位置＝**Warning** 级（静默失败）。
- Acceptance:
  - [ ] 三类失败均返回可判别结局，均不抛、不产生半落地状态。
  - [ ] 敌方占线留痕级别为 Error；满员留痕级别为 Warning。
- Terminology: —
