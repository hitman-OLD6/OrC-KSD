## 二、缺陷清单

### P1 — 契约违反 / 验收可信度

#### P1-1 包版本不是「内容指纹」：指纹只算 sidecar 路径列表

- **位置**：`src/Orc.Packages/PackageVersion.cs:39-55`；调用点 `AssetEditorSession.cs:380, 826`。
- **现象**：`Compute(packageId, metadata)` 的输入是 **sidecar 相对路径列表**（`manifest.metadata`），不读 sidecar 内容、不含资产版本。修改卡数据体或资产版本（sidecar 路径不变）时 `manifest.version` **完全不变**。
- **违反**：R17「包版本＝`hash(包 ID ＋ 包内元数据)`，仅内容指纹」；前端文档 §2.1 与 L9。
- **实证**：探针改 sidecar 内资产版本 `1.0.0 → 7.7.7` 后重算，指纹与 `manifest.version` 相同（断言通过）。
- **影响**：`AssetCatalogSnapshot.VersionLocks`（`id@指纹`）等审计记录失真；调试时无法用包版本判断「内容是否变了」。
- **建议**：把 sidecar 的**规范化内容**（或至少每条资产的 `guid/kind/id/version` 集合）纳入哈希；若坚持「布局指纹」，则需同步改文档 R17、§2.1、L9，避免前端误用。

#### P1-2 `version.set` 不同步内含资产版本（R4 违反）

- **位置**：`src/Orc.Packages/Editing/AssetEditorSession.cs:279-290`（`SetVersion`）→ `:736-745`（`ApplyVersion` 只改目标条目）。
- **现象**：对宿主 `effect` 调 `version.set` 后，同 sidecar 的 `trigger`/`handler` 仍停留在旧版本；而 R4 要求「内含资产**继承宿主文件版本**」。
- **实证**：探针 `CreateAsset(Trigger, anchor)` + `SetVersion(Effect, "1.1.0")` ⇒ 宿主 `1.1.0`、内含 `1.0.0`（断言失败）。
- **影响**：会话内 `asset_list`／`lock_preview`／`lock.test.json` 出现同文件版本分裂；`promote` 时 `ComputePromotedVersions`（`:747-765`）虽会按宿主版本统一覆盖而「自愈」，但**预览与实际不一致**，且若中途 `reload`／导出测试 lock 会得到非法组合。
- **建议**：`ApplyVersion` 对同 `sidecarRelative` 的条目统一改写版本与 GUID；或 `SetVersion` 显式拒绝内含资产并要求改宿主。

#### P1-3 三个「符号链接逃逸」测试在本机静默跳过，验收证据缺失

- **位置**：`tests/Orc.Packages.Tests/AssetEditorTests.cs:266-283`、`tests/Orc.Packages.Tests/PathNormalizerTests.cs:117`、`tests/Orc.Mcp.Tests/SandboxPathGuardTests.cs:106`。
- **现象**：三处均为 `if (!TryCreateDirectoryLink(...)) { return; }`——建链失败即**静默 return**，测试仍报「通过」。本机实测 `New-Item -ItemType SymbolicLink` 返回「此操作需要管理员权限」，即三个用例**全部未执行**。
- **影响**：S8 验收项「符号链接逃逸一律拒绝」在本机没有运行证据；`PathNormalizer.ResolveLinks`（`:252-328`）代码审查看起来正确（逐段 realpath、8 层上限、不可读即拒绝），但安全边界不能只靠代码阅读。
- **建议**：改用显式跳过机制（xUnit v3 `Assert.Skip`／`[Fact(Skip=...)]`），并在 CI 增加一个「管理员 / 开启开发者模式」的作业专跑这三例；至少在测试输出中打印「未验证」。

#### P1-4 编辑器可写入 `versions/` 历史目录（L5 违反）

- **位置**：`src/Orc.Packages/Editing/AssetEditorSession.cs:772-819`（`ResolveWritable`/`EnsureWritable` 仅校验「在临时包内」）。
- **现象**：`Commit("versions/9.9.9/cards/demo.ghost.card.json", content)` 被接受并落盘（探针通过）。
- **违反**：前端文档 L5、S8「`versions/<v>/` 不被编辑器编辑；编辑器只动当前正式版」。
- **影响**：可在历史版本目录制造当前版无法识别的副本；`promote` 时 `ApplyToFormalPackage` 会把该文件一起复制进正式包，污染历史归档。
- **建议**：`EnsureWritable` 增加 `IsUnderVersions(relative)` 拒绝（与 `EnumerateSidecars` 的排除规则同源）。

### P2 — 边界缺陷 / 健壮性

#### P2-1 声明冲突判定早于依赖剔除，可能把「本不会加载」的资产算进冲突

- **位置**：`src/Orc.Packages/LoadListPlanner.cs:143-167`（`conflictIndex = IndexByKey(nodes)` 在依赖检测 `:170-247` 之前）。
- **现象**：A 声明与 B 冲突、B 又依赖不存在的 C：B 本应因 `DependencyMissing` 被剔除，但 `DeclaredConflict` 仍触发且 `IsFatal=true`，整次计算失败。
- **违反**：S11 文档「判定集合＝本域 lock 合并后**实际参与加载**的资产」。
- **实证**：探针同时得到 `DependencyMissing` 与 `DeclaredConflict`（断言通过）。
- **建议**：把冲突扫描移到依赖传播之后，或先按 `excluded` 过滤 `conflictIndex`。

#### P2-2 删除宿主资产不级联内含资产，转正后产生孤儿

- **位置**：`src/Orc.Packages/Editing/AssetEditorSession.cs:244-272`（`DeleteAsset` 仅移除目标条目）。
- **现象**：删除 `effect` 宿主后，同 sidecar 的 `trigger`（`anchor=main`）仍在 `_assets` 与正式 lock 中，但宿主已不存在。
- **实证**：探针删除宿主 → `promote` → `PackageRegistrar.Register` → `LoadListPlanner.Plan` 产出 `OrphanEmbedded`（断言通过）。
- **建议**：删除宿主时级联删除同 `sidecarRelative` 的内含资产；或显式拒绝并提示「先删除内含资产」。

#### P2-3 `CommitPrefab` 在 sidecar 无宿主条目时抛 `NullReferenceException`

- **位置**：`src/Orc.Packages/Editing/AssetEditorSession.cs:698-715`（`committed!` 可能为 null）。
- **场景**：prefab 的 sidecar 只有内含条目（无 `anchor=null` 的宿主），`Commit` 后 `committed` 保持 null。
- **实证**：探针实际抛 `NullReferenceException`（非 `AssetEditorException`）。
- **影响**：MCP `Guard` 只捕 `AssetEditorException`（`EditorTools.cs:662-679`），NRE 会变成未映射的内部错误。
- **建议**：`committed is null` ⇒ 抛 `InvalidContent`（说明 sidecar 缺宿主条目）。

#### P2-4 `CreateAsset` 不校验源文件 `id` 与声明 `id` 一致

- **位置**：`src/Orc.Packages/Editing/AssetEditorSession.cs:174-240`。
- **现象**：可为 `cards/demo.rifleman.card.json`（内含 `id=demo.rifleman`）声明新资产 `demo.alias`，编辑器接受并在 sidecar 追加条目；注册面随后报 `IdMismatch`（R2 的「该资产非法」）。
- **实证**：探针通过（sidecar 出现 `demo.alias` 条目）。
- **建议**：`CreateAsset` 对 `kind=card` 读取源文件 `id`，不一致即 `InvalidContent`（编辑器应尽早失败，而非把问题留到注册期）。

#### P2-5 `AssetRegistry` 二级索引以 `packageId` 为键，与「GUID 由包 GUID 派生」不一致

- **位置**：`src/Orc.Packages/AssetRegistry.cs:138, 158-172`。
- **现象**：索引键是 `(PackageId, Kind, LocalId)`，而资产身份是 `(PackageGuid, Kind, LocalId, Version)`。D31 允许**同 ID、不同 GUID** 的包并存时，`VersionsOf` 会把两个包的候选混在同一列表，`AssetIdBridge` 定版可能选到另一个包的同一局部 ID。
- **建议**：索引键改为 `(PackageGuid, Kind, LocalId)`，或在 `VersionsOf` 增加按 `PackageGuid` 过滤的重载。

#### P2-6 `ListPackages` 优先使用 `PackageRoots` 且不校验授权根

- **位置**：`src/Orc.Packages/Editing/AssetEditor.cs:76-147`。
- **现象**：`_options.PackageRoots` 非空时直接枚举，完全绕过 `_policy`；可列出授权根之外目录的 `manifest.json` 元信息（`id/name/version`）。
- **建议**：每个 root 先 `PathNormalizer.Normalize` + 要求 `under` 授权根（与 `EnsureWritable` 同一规则），或明确文档化「PackageRoots 由宿主负责授权」。

#### P2-7 `promote` 非新建包无事务性，且历史归档可能被覆盖

- **位置**：`AssetEditorSession.cs:355-418`（`Promote`）、`:1057-1073`（`ApplyToFormalPackage`）、`:1113-1131`（`ArchiveHistory`）。
- **现象**：
  1. `ApplyToFormalPackage` 逐文件 `File.Copy(overwrite:true)`；中途 IO 失败会留下**部分更新**的正式包（临时包尚在，可人工恢复，但无自动回滚）。
  2. `ArchiveHistory` 对已存在的 `versions/<v>/` 同样 `overwrite:true`；手写版本回退或重复转正同一版本会**覆盖历史内容**。
- **建议**：正式包先写 staging 再原子替换；`versions/<v>` 已存在时拒绝或改名为 `<v>-<n>`，并在错误信息中指名。

#### P2-8 孤儿 meta 检测只覆盖 manifest 已列出的 sidecar

- **位置**：`src/Orc.Packages/PackageScanner.cs:112`（`SidecarFiles = manifest.MetadataList`）、`PackageRegistrar.cs:127-185`。
- **现象**：`effects/*.prefab.json.meta.json` 若不在 `manifest.metadata` 中，注册面**完全不会发现**——既不注册，也不报 `SourceMissing`。与 R2「孤儿 meta：不注册、进诊断」不符。
- **建议**：扫描 `effects/`（或所有资产目录）的 `*.meta.json` 与 manifest 列表取并集；未列入 manifest 的给一条 `UnlistedSidecar` 诊断（或迁移告警）。

## 五、修复优先级建议

1. **本批必修（P1）**
   - P1-1 包版本内容指纹（决定审计语义，改动小：把 sidecar 内容纳入 hash）。
   - P1-2 `SetVersion` 同步内含资产（改动集中在 `ApplyVersion`）。
   - P1-4 拒绝写入 `versions/`（一行判定 + 用例）。
   - P1-3 符号链接测试改为显式跳过 + CI 专跑（不改产品代码）。
