> **来源**：`代码审查与测试审查报告.md`（2026-10-21）的 P1×4 / P2×8 / P3×10，用户以「全面修复」批准报告 §5 的修复方案。
> **状态**：全部 Confirmed（用户已授权全面修复；本文件只写外部行为与验收，不含实现路径）。
> **范围**：`src/Orc.Packages`、`src/Orc.Mcp`、`src/Orc`、`tools/Orc.Tools.Migrate`、`tests/*`、`docs/资产元数据与后端编辑器/*`、`samples/*`。
> **不变量**：R1–R18 与 `前端交接文档.md` 的既有契约不得回退；修复后全量测试必须 0 失败、构建 0 错误。

## F1 包版本＝真正的内容指纹

- **Status**: Confirmed
- **现状**：`manifest.version` 只哈希 sidecar 路径列表；改内容不改指纹（报告 P1-1）。
- **期望行为**：`version = hash(包 ID ＋ 包内每份 sidecar 的规范化内容)`，无时间戳；同一内容恒得同一指纹；**同一路径下内容变化 ⇒ 指纹变化**；临时包带 `-tmp`、转正去掉；仍不参与依赖/lock/资产 GUID。
- **兼容**：既有 `Compute(包ID, 元数据路径列表)` 可保留为「布局指纹」，但 `manifest.version` 必须由新语义生成。
- **迁移**：`samples/*` 的 `manifest.json` 全部重算；`Orc.Tools.Migrate` 生成 manifest 时用新语义；`--dry-run` 仍 0 障碍。
- **验收**：
  - [ ] 同路径改 sidecar 内资产版本 ⇒ 指纹变化；
  - [ ] 同内容不同书写顺序 ⇒ 指纹相同；
  - [ ] 每个样例包满足「重算值 == manifest.version」；
  - [ ] 迁移工具 dry-run 0 障碍。

## F2 内含资产版本随宿主同步

- **Status**: Confirmed
- **现状**：`version.set` 只改目标条目，同 sidecar 的 trigger/handler 留旧版（报告 P1-2）。
- **期望行为**：对任一资产 `version.set` 后，同 sidecar 的宿主与全部内含资产**统一为目标版本**（GUID 同步重算）；`asset_list`、`lock_preview`、`lock.test.json` 三处一致；`promote` 后仍一致。
- **验收**：
  - [ ] 宿主 1.0.0 + 内含 1.0.0，set 宿主 1.1.0 ⇒ 内含亦 1.1.0；
  - [ ] 测试 lock 中两者版本相同；
  - [ ] 对含 2 个内含条目的 prefab 同样成立。

## F3 编辑器不得写历史版本目录

- **Status**: Confirmed
- **现状**：`commit`/`create` 可写 `versions/**`（报告 P1-4）。
- **期望行为**：目标路径落在 `versions/**` ⇒ `PathDenied`；`asset_create` 的 `sourcePath` 同样拒绝；错误信息指名路径。
- **验收**：
  - [ ] `commit("versions/9.9.9/cards/x.card.json", content)` ⇒ `PathDenied` 且无文件产生；
  - [ ] `createAsset(kind=card, id, sourcePath:"versions/1.0.0/cards/x.card.json")` ⇒ `PathDenied`。

## F4 重解析点逃逸用例必须真实执行

- **Status**: Confirmed
- **现状**：三处用例建链失败即静默 `return`，本机（无建链权限）从未执行（报告 P1-3）。
- **期望行为**：在 Windows 普通用户权限下也能构造重解析点（目录 junction）完成逃逸用例；无法构造时**显式标记未验证**（不得静默通过）；三处用例共用同一 helper。
- **验收**：
  - [ ] 本机运行 `AssetEditorTests`、`PathNormalizerTests`、`SandboxPathGuardTests` 的逃逸用例**真实通过**（非跳过）；
  - [ ] helper 在非 Windows 用 symlink、Windows 先 symlink 后 junction。

## F5 声明冲突只判定「实际参与加载」的资产

- **Status**: Confirmed
- **现状**：冲突判定早于依赖剔除，本会被剔除的资产仍触发 fatal（报告 P2-1）。
- **期望行为**：判定集合＝依赖检测与传播后仍在列表中的资产；被剔除者不参与冲突判定。
- **验收**：
  - [ ] A 声明与 B 冲突、B 依赖缺失 ⇒ 只报 `DependencyMissing`，不报 `DeclaredConflict`，`IsValid=true`；
  - [ ] 双方均合法 ⇒ 仍报 `DeclaredConflict` 且 fatal（原用例不回归）。

## F6 删除宿主级联删除内含资产

- **Status**: Confirmed
- **现状**：删除宿主 effect 后内含 trigger 成为孤儿，转正后产出 `OrphanEmbedded`（报告 P2-2）。
- **期望行为**：删除 `anchor=null` 宿主时，同 sidecar 的 `anchor≠null` 条目一并删除；sidecar 空则删源文件＋sidecar 并记墓碑；删除内含资产本身不连带宿主。
- **验收**：
  - [ ] 删除宿主后 `asset_get(trigger)` ⇒ `AssetNotFound`；
  - [ ] 转正后注册面 + `LoadListPlanner` 无 `OrphanEmbedded`；
  - [ ] 删除内含资产后宿主仍在。

## F7 提交／新建的前置校验（消灭 NRE 与迟到诊断）

- **Status**: Confirmed
- **现状**：`CommitPrefab` 无宿主时 NRE；`CreateAsset` 接受源 id 不一致；`CommitCard` 多卡 sidecar 不校验（报告 P2-3/P2-4/P3-1）。
- **期望行为**：
  - prefab sidecar 无宿主条目 ⇒ `InvalidContent`（结构化，非 NRE）；
  - `createAsset` 的卡/effect 源文件 id 与声明 id 不一致 ⇒ `InvalidContent`；
  - `commit` 的卡在「sidecar 声明了多张卡」且源 id 不在其中 ⇒ `InvalidContent`。
- **验收**：三条各一个用例，断言错误码为 `InvalidContent`。

## F8 注册表索引以包 GUID 为键

- **Status**: Confirmed
- **现状**：二级索引用 `packageId`，同 ID 不同 GUID 的双包候选会混（报告 P2-5）。
- **期望行为**：新增按包 GUID 的精确查询；同 ID 双包并存时，按 GUID 查询各只返回本包版本；既有按包 ID 的查询语义保持（可能跨包，文档写明）。
- **验收**：
  - [ ] 两个同 ID、不同 GUID 的包各注册 1 条同局部 ID 资产 ⇒ 按 GUID 查询各 1 条；按包 ID 查询 2 条。

- **期望行为**：`pack_list` 只返回落在授权根内的包；越界 root 静默跳过（不抛错、不泄露 manifest 内容）。
- **验收**：

## F10 转正事务性与历史冲突

- **Status**: Confirmed
- **现状**：逐文件覆盖无回滚；`versions/<v>` 已存在会被覆盖（报告 P2-7）。
- **期望行为**：
  - 落地失败 ⇒ 正式包恢复为转正前状态，临时包保留，抛结构化错误（含回滚失败明细，若有）；
  - `versions/<v>/<source>` 已存在且内容不同 ⇒ 拒绝转正并指名，不覆盖历史。
- **验收**：
  - [ ] 注入 IO 失败（目标文件只读/被占用）⇒ 正式包文件哈希与转正前一致，临时包仍在；
  - [ ] 预置 `versions/1.0.0/...` 后转正同版本 ⇒ 结构化拒绝，历史内容不变。

## F11 未列入 manifest 的 sidecar 可被发现

- **Status**: Confirmed
- **现状**：只扫 manifest.metadata，`effects/` 下漏列的 sidecar 完全不可见（报告 P2-8）。
- **期望行为**：扫描 `effects/**`（以及既有 `cards*`）的 `*.meta.json` 与 manifest 列表取并集；源文件存在 ⇒ 正常注册；源文件缺失 ⇒ `SourceMissing` 诊断。
- **验收**：
  - [ ] effects 下未列入 manifest 且源文件存在的 sidecar ⇒ 资产被注册；
  - [ ] 同场景源文件缺失 ⇒ 出现 `SourceMissing`。
