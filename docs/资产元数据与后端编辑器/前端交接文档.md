## 0. 一页速览

| 概念 | 一句话 |
|---|---|
| 资产（asset） | 跨版本实体：包 ID ＋ 种类 ＋ 局部 ID，例如"orc.bulwark 的 card：rifleman" |
| 资产版本（asset version） | 一份具体内容，由 GUID 标识；GUID = f(包 GUID, 种类, 局部 ID, 资产版本) |
| 应用层 ID | `pack/{包id}/{局部ID}`，卡组/引用/UI 用它，**与版本无关** |
| 中间层 | 应用层 ID → 资产版本（GUID）；测试段可遮蔽正式段 |
| 注册 | 读元数据、生成 DTO，不进对局 |
| 加载 | 合并 lock → 拓扑分层列表 → 按层装载；分正式段与测试段 |
| 正式 lock | `lock.formal.json`：卡包"正式版"的资产版本集合，**只能手动更新**（转正入口） |
| 测试 lock | `lock.test.json`：编辑器临时包产出，随放弃删除、随转正转正 |
| 临时包 | `<包目录>.tmp/`：编辑期全部提交的落点；包版本带 `-tmp` |
| service 资产 | 插件提供的引擎服务（判定器/词条/组件…）；`kind="service"` ＋ `serviceKind` 子类 |

**前端只需要记住三条**：

1. **只写临时包**：`<包目录>.tmp/`；正式包只读。
2. **版本只增不减**：默认尾段 +1；手写必须严格大于旧版（1..8 段纯数字）。
3. **正式版靠"转正"**：`editor.promote` 生成新版本 ＋ 两 lock ＋ `versions/<v>/` 归档；不转正则新版本只在测试段生效。

## 1. 文件布局（自描述）

### 1.1 卡包目录

```
orc.bulwark/
├─ manifest.json                    # 包身份 + 元数据列表（唯一入口）
├─ lock.formal.json                 # 正式版资产版本集合（手动更新）
├─ lock.test.json                   # 测试域（正式包里通常为空）
├─ cards/
│  ├─ bulwark.rifleman.card.json        # 卡牌数据体
│  └─ bulwark.rifleman.card.json.meta.json   # ← 元数据 sidecar（一对一）
├─ effects/
│  ├─ bulwark.rally.prefab.json
│  └─ bulwark.rally.prefab.json.meta.json
├─ keywords.json                    # 可选：卡包词条声明
├─ texts.json                       # 可选：卡面文本
└─ versions/
   └─ 1.2.3/                        # 历史版本（源文件 + sidecar 原样归档）
      └─ cards/…
```

**硬规则**

- 每个资产源文件（`*.card.json` / `*.prefab.json` / `*.csx` / 其他 json）**有且仅有一份**同目录 sidecar，文件名＝`<源文件名>.meta.json`。
- sidecar 是**权威**；源文件里的 `id` 必须与 sidecar 一致，不一致＝该资产非法。
- `versions/<v>/` 只被注册面扫描，**不被编辑器编辑**（编辑器只动当前正式版）。
- 源文件缺失而 sidecar 存在 ⇒ 孤儿 meta：不注册、进诊断（`source-missing`）。
- **没有 sidecar 也合法**：卡源文件按「无元数据」合成默认元数据（版本 `1.0.0`）并进诊断 `sidecar-missing`，包照常注册（不需要为每张卡补 sidecar 才能跑）。
- **未列入 `manifest.metadata` 的 sidecar 也会被发现**：`cards*` 顶层与 `effects/` 递归的 `*.meta.json` 与清单取**并集**；清单漏项不再导致资产不可见（清单只是声明，磁盘才是权威）。

### 1.2 插件目录（asm 插件）

```
orc.builtin.core/
├─ manifest.json          # kind=plugin（v2）
├─ assets.meta.json       # 包级资产清单（source＝程序集名）——asm 插件没有可挂 sidecar 的源文件
├─ lock.formal.json
└─ lock.test.json
```

> `assets.meta.json` 是**代码声明的落盘镜像**：权威在插件程序集（`IPluginAssetSource.Describe()`）。改动后由 `dotnet run --project tools/Orc.Tools.Migrate -- --plugin-assets` 重新生成。

## 2. 数据 Schema（逐字段）

### 2.1 `manifest.json`（v2）

```json
{
  "schemaVersion": 2,
  "id": "demo",
  "guid": "47a3508d-e398-f43e-107f-8681b6e85d22",
  "kind": "cardpack",
  "name": "示例包",
  "version": "1ffd538f184d8e06882fbc0123b7f6cf",
  "metadata": [
    "cards/demo.rifleman.card.json.meta.json",
    "effects/demo.rally.prefab.json.meta.json"
  ]
}
```

| 字段 | 说明 |
|---|---|
| `id` | 人类可读包 ID（也是应用层 ID 前缀 `pack/{id}/`） |
| `guid` | 包稳定身份；**资产 GUID 的派生输入**（`@{包GUID8}` 取前 8 位） |
| `kind` | `plugin` ／ `cardpack` |
| `version` | **内容指纹**＝`hash(包 ID ＋ 包内每份当前版 sidecar 的规范化内容)`，无时间戳；临时包带 `-tmp`。**不参与依赖、不进 lock、不进资产 GUID** |
| `metadata[]` | **只列当前正式版**的 sidecar 路径；历史版本靠 `versions/*` 自动扫描 |
| `requires[]` | **期望依赖的卡包 ID**（`session_begin{mode:"create"}` 的 `dependsOnPackages` **原样落盘**）；纯声明字段，不参与解析 |

> 已退役：`dependsOn`（读宽兼容、写窄不再产出）、`assets[]`（v1 遗留，仅插件内部合成路径还在读）。

### 2.2 `*.meta.json`（sidecar）

```json
{
  "schemaVersion": 1,
  "packageId": "demo",
  "source": "cards/demo.rifleman.card.json",
  "assets": [
    {
      "guid": "9be28f85-9837-11f3-f468-1a0d871f3f6d",
      "kind": "card",
      "id": "demo.rifleman",
      "version": "1.2.3",
      "loader": "builtin.card",
      "dependsOn": [
        { "kind": "effect", "id": "pack/demo/demo.rally", "version": "1.*.*" }
      ],
      "conflictsWith": []
    }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `source` | 源文件相对包根路径（不含 `.meta.json`） |
| `assets[].kind` | `card` / `effect` / `trigger` / `handler` / `service` |
| `assets[].id` | **局部 ID**（包内唯一）；应用层 ID 由 `pack/{packageId}/{id}` 拼出 |
| `assets[].version` | 1..8 段纯数字；**内含资产（trigger/handler）继承宿主文件版本** |
| `assets[].anchor` | 内含资产锚点：`stableKey` 或事件 `id`；独立资产为 null |
| `assets[].loader` | 加载器名（须为已注册；内含资产留空）。卡包不能自带加载器 |
| `assets[].serviceKind` | 仅 `kind=service`：`judicator`／`assetService`／`keyword`／`cardComponent`／`action`／`projection`／`observer` |
| `dependsOn[]` | `{ kind, id, versionConstraint }`；`id` 可写**应用层 ID 或裸局部 ID**（后端按当前包归一） |
| `conflictsWith[]` | 同上结构；语义＝**双向硬冲突**：双方同处一次加载集合 ⇒ 结构性失败 |

**契约**

- 版本一律按段数原样写出；读入后按"规范形（右补 0 至 8 段）"比较，`1.2 ≡ 1.2.0`。
- **禁止以字符串比较版本**。
- 读宽（注释/尾逗号/键名大小写不敏感）写窄（固定键序/2 空格/LF/UTF-8 无 BOM）。

### 2.3 `lock.formal.json` / `lock.test.json`

```json
{
  "schemaVersion": 1,
  "packageId": "demo",
  "domain": "formal",
  "assets": [
    {
      "guid": "9be28f85-9837-11f3-f468-1a0d871f3f6d",
      "kind": "card",
      "id": "pack/demo/demo.rifleman",
      "version": "1.2.3"
    }
  ]
}
```

- `domain` ∈ `formal` / `test`；**两域绝不互相合并**。
- 加载时合并参与方同域 lock：同一资产出现不同版本 ⇒ 报错；否则按依赖拓扑分层装载。
- 未入 lock 的版本**不参与加载**。
- lock **只能手动更新**：唯一入口＝编辑器 `promote`（转正）。

### 2.4 卡牌数据体（`*.card.json`）

```json
{
  "schemaVersion": 1,
  "id": "demo.rifleman",
  "name": "步枪兵",
  "components": [
    { "component": "typeCategory", "type": ["infantry"] },
    { "component": "factionCost", "faction": "usa", "kredits": 2 },
    { "component": "battleStats", "operationCost": 1, "attack": 2, "defense": 2 },
    { "component": "tagData", "rarity": "standard", "tags": [] },
    { "component": "keywords", "attributes": ["闪击"] },
    { "component": "effects", "prefabs": ["demo.rally"] }
  ]
}
```

- 组件注册名六项：`typeCategory`（构造期，必填）／`factionCost`（构造期，必填）／`battleStats`（单位必填）／`tagData`（缺失＝警报）／`keywords`／`effects`。
- 未知组件名或单组件反序列化失败＝**隔离该组件**（告警），其余照常。

### 2.5 效果预制体（`*.prefab.json`）

```json
{
  "schemaVersion": 2,
  "root": {
    "id": "demo.rally",
    "version": 1,
    "mainTrigger": { "id": "main", "stableKey": "demo.rally", "kind": "passive", "hooks": [], "events": [] },
    "otherTriggers": [],
    "injects": [],
    "wrappers": []
  }
}
```

- `wrappers[]` 条目：`{ phase: "before"|"after"|"replace", target: "<eventId | seam:名>", handler: {...} }`。
- 内含资产的 sidecar 条目 `anchor` 指向 `stableKey` 或事件 `id`。

## 3. 可用 API

### 3.0 版本递增规则（`asset.commit` / `version.set`）

| 场景 | 结果 |
|---|---|
| 首次提交**已有正式版**的资产（`1.2.3`） | 追加测试段 → `1.2.3.1`（`versionBumped:true`） |
| 同一会话内再次提交（`1.2.3.1`） | 尾段 +1 → `1.2.3.2` |
| 本会话**新建**的资产（`1.0.0`） | 首次提交版本不变（`versionBumped:false`） |
| 先 `version.set` 显式设定版本 | 本次提交不再自动递增（pinned） |
| 转正（`promote`） | 去测试段并递增正式版尾段：`1.2.3.5` → `1.2.4` |

> 手写版本必须**严格大于**旧版：`1.2`→`1.2.1` 合法；`1.2`→`1.2.0` 非法（补 0 后相等）；`1.2.3`→`1.2` 非法（降级）。

### 3.1 门控（先看这条）

- `editor.*` 仅在**沙盒模式（Authoring 档）**登记；Player 档工具清单中**不存在**。
- 写根＝沙盒根；可编辑包根＝沙盒根（`pack` 与 `pack.tmp` 均为其子项）。越界/符号链接逃逸 ⇒ `PathDenied`。
- 对局待决期间：只允许 `target.*` 与只读工具。

### 3.6 加载问题码（`editor.reload` / `AssetLoadIssueCode`）

| 码 | 含义 | 致命性 |
|---|---|---|
| `LockConflict` | 同域两份 lock 对同一资产锁定不同版本 | **结构性 ⇒ 本次计算不产出列表** |
| `DuplicateLockEntry` | lock 对同一资产 GUID 重复声明（自相矛盾） | **结构性 ⇒ 本次计算不产出列表**（保留 merge 稳定序首条，其余**每条各报一条**） |
| `Cycle` | 环依赖（`path` 为环路径） | **结构性** |
| `DeclaredConflict` | 声明冲突双方同处本次加载集合 | **结构性** |
| `Unregistered` | lock 引用的版本未注册 | 资产级（剔除该资产） |
| `DomainMismatch` | 注册域与 lock 域不符 | 资产级 |
| `DependencyMissing` | 依赖不在本次加载集合 | 资产级（连带依赖者 `DependencyInvalid`） |
| `DependencyVersionMismatch` | 依赖版本约束不满足（lock 为准，仍装载） | 仅报告 |
| `FormalDependsOnTest` | 正式资产依赖测试资产 | 资产级 |
| `TestDependsOnUnlockedFormal` | 测试资产依赖的正式资产不在正式 lock | 资产级 |
| `DependencyInvalid` | 依赖资产被判非法 | 资产级 |
| `OrphanEmbedded` | 内含资产找不到宿主 | 不参与拓扑 |

> 声明冲突的判定域＝**依赖检测与传播之后仍在列表中的资产**——本会被剔除的资产不参与冲突判定。
> 致命问题出现时 `editor.reload` 返回 `status:"Invalid"`，且**不改动已有缓存列表**。

### 3.7 插件 lock 问题码（`PluginAssetLockVerifier`）

| 码 | 含义 | 处置 |
|---|---|---|
| `missing-lock` | 缺少 `lock.formal.json` | 运行插件资产重锁 |
| `stale-lock` | lock 条目与注册面不一致（GUID 不存在，或 `kind`／`appId`／`version` 任一被篡改） | 重锁 |
| `unlisted` | 注册面有该资产但未入 lock（当前不会加载） | 重锁 |
| `duplicate-entry` | lock 对同一 GUID 重复声明 | **修改 lock 文本或重锁** |

## 4. 典型流程

### 4.1 编辑已有卡包并转正

```text
editor.pack_list                        → 选包
editor.session_begin{mode:"edit",packageRoot}
  ↳ 临时包 <包目录>.tmp/，资产版本＝正式版追加测试段（1.2.3 → 1.2.3.1）
editor.asset_list{kind:"card"}          → 选资产
editor.asset_commit{path, content}      → 解析+校验+重算 sidecar+按 3.0 规则递增（首次 1.2.3→1.2.3.1）
editor.dep_set{...}                     → 测试 lock 自动重算
editor.lock_preview                     → 看转正后将写出的正式 lock（预测）
editor.reload                           → 按合并 lock 计算分层列表（受 reloadGate 门禁）
editor.promote                          → 去测试段并递增（1.2.3.5→1.2.4）+ 两 lock + versions/1.2.3 归档
```

### 4.2 新建卡包

```text
editor.session_begin{mode:"create",packageId,dependsOnPackages,parentDirectory?}
  ↳ 资产从 1.0.0 起；包版本 hash-tmp；首个正式 lock 在转正时生成
editor.asset_create{kind:"card",id}
editor.asset_commit{path, content}
editor.promote
```

> `dependsOnPackages` **落盘为 `manifest.requires`**（纯声明，供前端/审查读取）；
> 它不参与解析、不进 lock——**运行时依赖一律是资产级 `sidecar.assets[].dependsOn`**。

### 4.3 放弃

```text
editor.session_end{mode:"discard"}      → 删除整个临时目录（含测试 lock），无残留
                                          返回结构与 promote 相同，但 assets／两 lock 均为空
```

### 4.4 查看插件服务资产（只读）

插件服务资产**不在编辑器会话内**（编辑器只管卡包）。查看方式：

- 文件：`<plugin>/assets.meta.json`（49 条示例：24 判定器 + 19 词条 + 6 卡组件）
- 运行时：`EngineHost.Assets` 注册面；lock 校验问题见 `host.LoadFailures`
- 诊断：`diag.*` 工具组

## 5. 限制与已知边界（前端必须处理）

| # | 限制 | 前端处置 |
|---|---|---|
| L1 | 编辑器工具 schema 的 `kind` 枚举**不含 `service`** | 服务资产只读展示；不要向 `asset_create` 传 service |
| L2 | 沙盒局（`sandbox.create`）不经卡牌加载器 | `diag.card_load` 的累积表为空，用 `source:"none"` 区分 |
| L3 | 沙盒脚手架首版 manifest 为 v1、无 sidecar | 首次 `asset.create/commit/version/dep` 会重写为 v2 |
| L4 | `editor.reload` 在沙盒流程常返回 `unchanged` | 沙盒注册面由宿主填充，不要把它当作"编辑失败" |
| L5 | `versions/<v>/` 不被编辑器编辑 | 历史版本只读；如需回滚另开需求 |
| L6 | `asset.list` 的 `tags` 只覆盖卡 | 非卡资产 `tags` 恒空 |
| L7 | 报告不落盘 | 需要留存时由调用方自行保存 |
| L8 | 插件（asm）不保留历史版本 | 官方更新后旧 lock 校验失败，必须重锁 |
| L9 | 包版本是内容指纹 | 不要用它排序/比较/做依赖；用资产版本 |
| L10 | 指纹覆盖包内**全部当前版** sidecar（含空 sidecar、非约定目录），`manifest.metadata` 只列**有资产声明**的 sidecar | 两者允许不同集：指纹＝内容、metadata＝资产清单（B-8） |
| L11 | 非约定目录（`cards*`／`effects` 之外）或更深嵌套的 sidecar 会改指纹，但**不产生资产** | 资产必须放在约定目录内才会被注册（B-7） |
| L12 | `versions/**` 下的历史 sidecar 只发现**卡源文件**（历史 `effects` 不可见） | 回滚需求另开；不要依赖历史 effects 注册（B-1） |

## 9. 附：一句话回答常见疑问

- **"我改的卡为什么没生效？"** → 你在测试段；需要 `editor.promote` 才进正式 lock。
- **"为什么版本报 VersionNotIncreasing？"** → 新版本未严格大于旧版（`1.2`→`1.2.0` 也算相等）。
- **"为什么 reload 没变化？"** → 资产未入任何 lock（先 `promote`），或返回 `unchanged`（无差异）。
- **"为什么找不到 service 资产？"** → 编辑器只编辑卡包四类；服务资产在插件的 `assets.meta.json` 与 `EngineHost.Assets`。
- **"为什么旧 lock 突然失败？"** → 插件/资产升版产生新 GUID；asm 插件不保留旧版本，按提示重锁。
- **"包版本能排序吗？"** → 不能。它是内容指纹；排序请用资产版本。
