# 编辑器未接入资产编辑器（AssetEditor）：DIY 工坊产物无法成为引擎资产

## 概要

Godot 内编辑器（DIY 工坊 / 卡牌编辑 / 效果编辑）把全部编辑结果写在 `user://diy-cards.json`、`user://diy-packs.json`，与后端《前端交接文档》定义的资产元数据体系（`manifest.json` v2 ＋ `*.meta.json` sidecar ＋ `lock.formal/test.json` ＋ `<包目录>.tmp/` ＋ `versions/<v>/`）完全并行。仓库内不存在 `AssetEditor` 会话调用，也不存在任何 `editor.*` 工具调用。

结论：**编辑器产物无法成为引擎资产**——不能被 `PackageDiscovery` 发现、不能分发、不参与 lock、没有版本与转正语义。

## 期望行为（依据前端交接文档）

1. 编辑只写临时包 `<包目录>.tmp/`，正式包只读。
2. 每个资产源文件有且仅有一份同目录 sidecar `<源文件>.meta.json`；sidecar 为权威。
3. 包清单为 `manifest.json` v2（`schemaVersion:2`、`metadata[]`、`requires[]`；`dependsOn`/`assets[]` 已退役）。
4. 版本 1..8 段纯数字、严格递增、`1.0.0` 起点；测试段 `1.2.3 → 1.2.3.1`；转正去测试段 `1.2.3.5 → 1.2.4`。
5. 正式版唯一入口是 `promote`：生成新版本 ＋ 两份 lock ＋ `versions/<v>/` 归档。
6. 效果预制体 `schemaVersion:2`，含 `wrappers[]`（`phase/target/handler`）；`moding` 已由 wrapper 取代。
7. 应用层 ID 为 `pack/{包id}/{局部id}`，与版本无关。

## 实际行为

- 编辑结果写 `user://diy-cards.json`（`{Schema:1, Cards:[...]}`）与 `user://diy-packs.json`（`{Schema:1, Packs:[...]}`），原子写用 `<文件>.tmp` 而非**临时包目录**。
- DIY 包仅通过 `WorkshopAuthoring.Configure` 在进程内重放注册，引擎宿主不感知；包目录下没有任何资产文件。
- 全仓 `AssetEditor|BeginSession|EditorSession` 命中 **0**；`editor.*` 工具调用 **0**。
- 无 sidecar / lock / 转正 / 归档实现。


### 2. 无 sidecar / lock / 临时包 / 转正

在仓库内检索 `meta.json`、`lock.formal.json`、`lock.test.json`、`promote`、`versions/`，仅命中与资产无关的实现（离线更新器的 `Promote(root,pending)`、卡面字段 `promoteCardFields`、素材目录 `_meta.json` 跳过）。**不存在** sidecar 读写、lock 预览、临时包、归档。

### 3. 未接入 `AssetEditor` / `editor.*`

前端只使用 `Orc.Packages` 的**只读消费面**：

```csharp
// proto/bridge/Kards.Ui.OrcBridge/OrcEngineHost.cs:52-63
var discovery = PackageDiscovery.Discover(baseDirectory);
_host = EngineHost.FromDiscovery(discovery, evaluator: null, extraPackages: [...]);
```

`TryLoadCardPack/TryUnloadCardPack/TryReloadCardPack/RestoreFrom/LoadCardPacks` 在前端 **0 次调用**。后端进程内 API 与 MCP 工具均已就绪（`src/Orc.Packages/Editing/AssetEditor.cs`、`src/Orc.Mcp/Tools/EditorTools.cs`），前端一个都未接。

### 4. 生成的 `manifest.json` 仍是 v1 形态

```csharp
// tools/OfficialCards/Program.cs:95-96
File.WriteAllText(manifest,JsonSerializer.Serialize(new {kind="cardpack",id=pack.Id,name=pack.Name,guid=new Guid(bytes[..16]).ToString(),version="1.0.0",
    dependsOn= new[]{new {id="builtin",version="1.*.*"}},assets=Array.Empty<object>()},jsonOptions));
```

缺 `schemaVersion:2` 与 `metadata[]`，仍写已退役的 `dependsOn`、`assets[]`；且不为卡源文件生成 sidecar。引擎读宽兼容能跑，但不满足交接文档 §2.1 的写窄要求。

### 5. 效果模板仍输出 `modings`，无 `wrappers[]`

```csharp
// proto/bridge/Kards.Ui.OrcBridge/DiyCardCompiler.cs:142-145
mainTrigger = new { id = "t_diy", stableKey = "diy." + type, kind = "passive", ... },
otherTriggers = Array.Empty<object>(), modings = Array.Empty<object>(), injects = Array.Empty<object>()
```

后端 `PrefabJson` 已无 `modings` 成员，`wrappers[]` 在前端全仓 **0 出现**；`injects[]` 只有只读诊断（`DiyInjectionCatalog.cs`），编辑器从不生成。

### 6. 无资产版本概念

`DiyCardDraft` / `DiyPackDraft` 均无 `version` 字段；前端唯一的“版本”是存档 schema 常量 `1`。自造词条改用**内容哈希进 id**（`k.Id + "." + hash`），改内容即换 id，与“同 id 升版本”语义冲突。

### 7. 应用层 ID 不符合 `pack/{包id}/{局部id}`

DIY 卡使用 `diy/<guid>`，修改内置卡靠 `SourceCardId` 覆盖本地实现；没有 sidecar 承载“同资产新版本”。

### 8. 样例包仍是旧 `pack.json` 模型

`samples/demo-card-pack/pack.json` 为 `{"schemaVersion":1,"kind":"pack","version":1,...}`，目录内无 `manifest.json`、无 sidecar。`PackageDiscovery` 的 `<base>/packs/<包>/manifest.json` 约定识别不到它；`samples/demo-card-pack/README.md` 仍在宣传 `pack.json`。

### 9. 仓库自认缺口与过期文档

- `docs/planning/ASSET_MODEL_MIGRATION_ISSUES_20261013.md:130`：**“卡包管理 UI 仍未实现（本期有意不做）”**。
- `docs/design/DIY_PACK_DESIGN_20261012.md` 仍以 `pack.json` + `PackSystem/PackLibrary/PackScreen` 为落地形态（对应源码已在 S8 删除）。

## 影响

- 编辑器新建/修改的包无法被引擎按约定发现，只能靠进程内重放，**无法分发、无法分享、无法参与 lock**。
- 无版本、无转正，因此“改的卡为什么没生效”“为什么 reload 没变化”这两类问题在架构上无解。
- 两份并行存档（`user://` 草稿 vs 资产文件）风险累积：后续任何导入/导出/回滚都要写第二套转换。
- 资产级依赖 `dependsOn`/`conflictsWith`、`DeclaredConflict` 检测、`AssetLoadIssueCode` 诊断在前端均无入口。

## 复现 / 检查方法

```powershell
rg -n "AssetEditor|BeginSession|EditorSession|editor\." .
rg -n "meta\.json|lock\.formal|lock\.test|promote|versions/" proto
rg -n "wrappers|modings" proto
rg -n "user://diy" proto
Get-Content samples/demo-card-pack/pack.json
Test-Path samples/demo-card-pack/manifest.json   # False
```

## 建议修复（按依赖顺序）

1. **定路线**：Godot 进程内直接引用 `Orc.Packages.Editing.AssetEditor`（同进程，无需 MCP），或起 `Orc.Mcp` 走 `editor.*`。二选一，停止继续扩展 `user://` 平行模型。
2. **会话壳**：工坊“创建/修改包”改为 `BeginSession(mode, packageRoot|packageId, dependsOnPackages)`；退出＝`EndSession(save|discard)`；新增 `promote` 与 `lock_preview` 视图。
3. **落盘改为资产文件**：`cards/<局部id>.card.json` ＋ sidecar、`effects/*.prefab.json` ＋ sidecar、`manifest.json` v2（写 `metadata[]`/`requires[]`，删 `dependsOn`/`assets[]`）。
4. **版本 UI**：显式展示 1..8 段与“测试段”，拒绝降级与补 0 相等；转正显示去测试段递增。
5. **prefab 升 schema 2**：删 `modings`，生成 `wrappers[]`（`phase/target/handler`）与可写 `injects[]`。
6. **错误面**：把 `details.editorCode` 与 `AssetLoadIssueCode`（含 `DeclaredConflict`/`LockConflict`/`DuplicateLockEntry`）映射到现有诊断区展示。
7. **样例与文档迁移**：`samples/demo-card-pack` 改为 v2 ＋ sidecar；修订 `DIY_PACK_DESIGN_20261012.md` 与 samples README。
8. **只读面补齐**：`editor.pack_list`、`service` 资产只读展示（交接文档 L1：不得向 `asset_create` 传 `service`）。

## 验收标准（可检查）

| # | 检查项 | 期望 |
|---|---|---|
| 1 | 编辑后目录 | 出现 `<包目录>.tmp/`，正式包内容不变 |
| 2 | 提交后 | 生成 `cards/*.card.json` ＋ 同目录 `*.meta.json`，`source`/`id` 一致 |
| 3 | 版本 | 首次提交 `1.2.3 → 1.2.3.1`；`1.2 → 1.2.0` 被拒并返回 `VersionNotIncreasing` |
| 4 | save | 临时包消失，`lock.formal.json`/`lock.test.json` 与 `versions/<v>/` 与 `promote` 返回一致 |
| 5 | discard | 临时包整目录删除，无残留 |
| 6 | 重新发现 | `editor.pack_list` / `PackageDiscovery` 能看到编辑器新建的包 |
| 7 | 效果 | 预览体为 `schemaVersion:2`，含 `wrappers[]`，无 `modings` |
| 8 | 诊断 | 结构性问题（lock 冲突/环/声明冲突）在前端可见 |

## 可保留、不必重做的部分

- 卡数据体走引擎 `CardDataJson` 序列化，组件名与后端一致（`typeCategory`/`factionCost`/`battleStats`/`tagData` 等）。
- 效果编译与准入判定走引擎（`OrcEffectEditing`、`DiyCapability`），UI 不伪造规则。
- 包发现的消费侧 `OrcEngineHost` 已符合 `<base>/packs/<包>/manifest.json` 约定，缺的只是写面。
