# 前端缺陷报告：`卡面文本引用了不存在的卡`（整包连带失效）

| 项 | 内容 |
| --- | --- |
| 报告日期 | 2026-10-26 |
| 来源 | 玩家反馈（DIY 创作时弹此错误，随后整个扩展包的卡全部消失） |
| 责任仓库 | `D:\Godot-orcKsd-main`（Kards.Ui，Godot + C#） |
| 严重级 | **S1**：单条脏数据使**整包**不可用，且用户无法在 UI 内自救 |
| 影响版本 | 工程版本 `0.0.0beta7.hotfix.3`（`project.godot`），问题代码自原生工坊（NativeWorkshop）引入起即存在 |
| 引擎侧结论 | **不是引擎 bug**。引擎按设计「非法卡不生成 DTO、只记诊断」，见 §7 排除项 |

---

## 1. 摘要

玩家在原生工坊里编辑自定义卡包时，界面报：

```
卡面文本引用了不存在的卡：card.ab58f238d9594300a4bdbbf621a2a52
```

随后**该扩展包的卡牌在卡牌一览、图鉴、构筑中全部消失**，且无法继续编辑保存。

根因不在卡包数据损坏，而在前端 `PackPresentationData` 把「展示文本表的引用完整性」当成**致命错误**抛出：

- `display-texts.json` 的键 `card.ab58…` 在本包 `content.Definitions` 里找不到对应卡 → `throw InvalidDataException`；
- 该异常发生在**包级作用域**（`OrcEngineHost.LoadPackCards` 的 per-package `try`）与**页面级作用域**（`NativeWorkshop.PreviewCards`），于是「一张卡的文本对不上」升级为「整包加载失败」。

真正让它会发生的，是另一条设计缺口：**编辑器允许提交字段级非法的卡**（草稿要能存半成品），而这类卡不进 `Definitions`，此前保存过的显示文本条目就永久成为孤儿。

---

## 2. 现象与影响面

| 位置 | 代码 | 表现 |
| --- | --- | --- |
| 工坊 · 卡牌一览 | `NativeWorkshop.PreviewCards()` → `BuildNativeLibrary` | 抛异常 → 页面渲染中断，只剩顶部标题 + 底部红字提示；**没有卡列表，无法点进任何卡** |
| 工坊 · 打开单卡 | `NativeWorkshop.CardPresentation()` | 抛异常 → 无法进入编辑页，坏卡本身也修不了 |
| 工坊 · 保存任意卡 | `NativeWorkshop.SaveCardPresentation()` | 函数内先调用 `Texts()` → 抛异常 → **整个包的所有卡都保存失败**（不只是坏卡） |
| 图鉴 / 构筑 | `OrcEngineHost.LoadPackCards()` | 该包被 `catch` 整体跳过 → 该包 0 张卡，`PackDescriptor` 也不加入 → 来源瓷砖消失 |
| 开对局 | `OrcMatchSession.PackCardDefinitions()` | 无 `try`，直接上抛 → 对局初始化失败 |

> 关键点：`SaveCardDocument` 的 `catch` 会把临时包整体回滚到保存前快照（`NativeWorkshop.Documents.cs:24-30`），所以**保存失败不会进一步损坏数据**——损失被限制在「无法继续操作」，不是「数据越改越坏」。

---

## 3. 最小复现

1. 新建卡包，新建一张卡（骨架为合法单位卡，见 `AssetEditorSession.CardStub`）。
2. 在卡上写入卡面文本并保存 → `display-texts.json` 出现 `"card.<guid>": "..."`。
3. 把该卡改为**指令卡 / 反制卡**，但不写任何 `effects`（或只写卡面文本、不生成规则）。
4. 保存。

第 4 步会**成功**（`CommitCard` 只校验“可解析”，不校验“字段级非法”）。此后：

5. 退出编辑会话，重新进入该卡包 → 卡牌一览报 §1 的错误，全包卡牌不再显示。

## 4. 代码定位

### 4.1 抛出点

`proto/bridge/Kards.Ui.OrcBridge/PackPresentationData.cs`

```csharp
// :17-30
public static IReadOnlyDictionary<string,string> Texts(CardPackContent content)
{
    var result = new Dictionary<string,string>(content.Texts, StringComparer.Ordinal);
    var path = Path.Combine(content.RootDirectory,"display-texts.json");
    if (!File.Exists(path)) return result;
    using var doc=JsonDocument.Parse(File.ReadAllText(path));
    foreach(var item in doc.RootElement.EnumerateObject())
    {
        if(!content.Definitions.Any(c=>c.Id==content.Prefix+item.Name))   // :25 ← 本缺陷抛出点
            throw new InvalidDataException("卡面文本引用了不存在的卡："+item.Name);
        if(result.ContainsKey(item.Name))
            throw new InvalidDataException("卡面文本同时声明了文本编译与已编译效果："+item.Name);
        result.Add(item.Name,item.Value.GetString()!);
    }
    return result;
}
```

`Plans()`（`:31-64`）同款判据，报「选靶声明引用了不存在的卡」（`:40`），是**同一缺陷的第二个实例**，必须一起修。

### 4.2 两个数据文件的分工

| 文件 | 归属 | 参与规则编译 | 本缺陷相关性 |
| --- | --- | --- | --- |
| `texts.json` | 引擎注册面（`CardPackContent.Texts`） | 是（卡面文本 → 效果） | 不校验引用完整性，**不会**引发本缺陷 |
| `display-texts.json` | 前端展示层（仅显示文本） | 否 | **抛出点** |
| `desktop-effects.json` | 前端选靶声明 | 否 | **抛出点（Plans）** |
| `workshop.presentation.json` | 前端展示元数据（flavor/规则图） | 否 | 不校验，只留脏数据 |

### 4.3 孤儿键的产生源

`display-texts.json` 的写入只有一处、清理只有一处：

## 5. 失败链

```
用户把单位卡改成指令卡但没写 effects
        │  （前端认为这是合法草稿，允许保存）
        ▼
CommitCard 通过（只校验 JSON 可解析）
        │
        ▼
磁盘状态：card.xxx.card.json（字段级非法） + display-texts.json["card.xxx"]（孤儿键）
        │
        ▼
下次 Register：load.Definition == null → 该卡不进 content.Definitions
        │
        ▼
PackPresentationData.Texts() 判 Prefix+key 不在 Definitions → throw
        │
        ├─→ PreviewCards() 抛        ⇒ 工坊一览空白、单卡打不开、任意卡都存不了
        ├─→ LoadPackCards() 被 catch ⇒ 图鉴/构筑里整包 0 张卡
        └─→ PackCardDefinitions() 抛  ⇒ 开不了对局
```

**死锁点**：所有修复入口（一览 → 单卡 → 保存）都在 `Texts()` 之后，用户没有任何 UI 路径能把包救回来。`BuildNativeLibrary` 里本来有「待修复的卡牌」兜底（`DiyWorkshopScreen.NativeWorkspace.cs:37-41, 51-54`），但它在 `PreviewCards()` 之后才执行，永远走不到。

'--- display-texts.json 孤儿键 ---'
(Get-Content (Join-Path $root 'display-texts.json') -Raw | ConvertFrom-Json).PSObject.Properties.Name |
  Where-Object { $ids -notcontains $_ }

'--- desktop-effects.json 孤儿键 ---'
(Get-Content (Join-Path $root 'desktop-effects.json') -Raw | ConvertFrom-Json).PSObject.Properties.Name |
  Where-Object { $ids -notcontains $_ }

补充判据（会产出孤儿键的四种「卡定义缺席」情形）：

| 情形 | 说明 |
| --- | --- |
| 字段级非法 | 上表 `Invalid` 判据命中，`Definition=null` |
| 卡文件被删/改名/移出 `cards*` 顶层 | `PackageScanner.Scan` 只扫 `cards*` **顶层**，放子目录就发现不了 |
| 只剩 `versions/<v>/` 历史版本 | 历史版本只注册、**不进当前版 `Definitions`**（`PackageRegistrar.cs:364-367`） |
| 导入的 ZIP 本身不一致 | 导出是整包复制，坏状态会随包传播给下载方 |

## 7. 排除项（避免走弯路）

| 假设 | 结论 |
| --- | --- |
| 引擎注册/宽松解析有 bug | 不成立。`Register` 只记诊断不抛（`AssetDiagnosticCode` 全量见 `PackageRegistrar.cs:14-33`）；`Definition=null` 是 D40 的既定语义 |
| id 前缀格式不一致（`pack/` vs `card.`） | 不成立。`AssetAppId.Prefix = "pack/"`，`CardPackContent.Prefix = $"pack/{manifest.Id}/"`，`Prefix+key` 与 `Definitions[i].Id` 同源 |
| `texts.json`（规则文本）参与本缺陷 | 不成立。`ReadTexts` 不校验引用，报错只来自 `display-texts.json` / `desktop-effects.json` |
| 卡包已损坏、需要重装 | 不成立。卡文件与卡数据完好，只是两个前端展示文件的键对不上 |

## 8. 修复方案

### P0-1 读取侧降级（止血，必做）

`PackPresentationData.Texts` / `Plans`：孤儿键与重复键**不再抛**，改为跳过 + 收集警告。

```csharp
public static IReadOnlyDictionary<string,string> Texts(
    CardPackContent content, ICollection<string>? warnings = null)
{
    var result = new Dictionary<string,string>(content.Texts, StringComparer.Ordinal);
    var path = Path.Combine(content.RootDirectory,"display-texts.json");
    if (!File.Exists(path)) return result;

    using var doc = JsonDocument.Parse(File.ReadAllText(path));
    foreach (var item in doc.RootElement.EnumerateObject())
    {
        if (!content.Definitions.Any(c => c.Id == content.Prefix + item.Name))
        {
            warnings?.Add($"display-texts.json：「{item.Name}」没有对应卡定义（已忽略该条）");
            continue;
        }
        if (result.ContainsKey(item.Name))
        {
            warnings?.Add($"display-texts.json：「{item.Name}」与 texts.json 重复（以 texts.json 为准）");
            continue;
        }
        result[item.Name] = item.Value.GetString() ?? "";
    }
    return result;
}
```

`Plans()` 同样处理。**注意保留可观测性**：警告要能出现在工坊「编辑会话提示」和图鉴加载失败明细里，不能静默吞掉。

### P0-2 消费侧隔离（止血，必做）

即使文本表整体不可读，也**不得影响卡定义输出**：

```csharp
// OrcEngineHost.LoadPackCards / OrcMatchSession.PackCardDefinitions
IReadOnlyDictionary<string,string> texts;
try { texts = PackPresentationData.Texts(content, warnings); }
catch { texts = content.Texts; }          // 兜底：退回规则文本，卡照常出
```

`NativeWorkshop.PreviewCards()` 同理——卡列表是主功能，文本只是装饰。

### P1-1 写入侧约束（阻断新增）

`SaveCardPresentation` 写 `display-texts.json` 前，先确认该 localId 在当前 `content.Definitions` 里。不满足时二选一：

- **推荐**：仍然允许保存文本（草稿语义），但**不写盘**，只在 `workshop.presentation.json` 里标记 `"displayTextPending": true`，等卡变合法后补写；
- 或：拒绝并提示「这张卡当前不合法，显示文本暂存未生效」，同时把卡标为待修复。

代价最小的实现是在 `SaveCardDocument` 成功 `Commit` 后补一次校验：卡若已非法，就把刚写入的键回退（与该函数已有的整体回滚语义一致）。

### P1-2 显式的“清理失效引用”

在卡包管理页加一个动作（或进入会话时静默检测 + 提示）：

```
发现 1 条失效的显示文本引用（card.ab58… 对应的卡已不存在或不可用）。
[清理这些条目]  [查看详情]
```

不要自动静默重写玩家的 json：用户可能手工编辑过这些文件，静默写盘会破坏其格式与备份预期。

### P2 体验收尾

- `_notice` 只显示 `ex.Message`（`DiyWorkshopScreen.Native.cs:29-30`），无包名、无定位。建议拼上包 id + 出问题的键。
- 图鉴加载失败明细（`failures`）目前无展示入口，建议在卡包管理页显示「N 个卡包加载失败」+ 明细。

## 10. 存量坏包的处理（发布版必须考虑）

玩家手里已经有坏包，修复上线后：

1. **必须能进得去**：P0 生效后，坏包可正常打开，坏卡显示为「待修复的卡牌」；
2. **不能继续传播**：导出 ZIP 前做一次孤儿键检测，有则提示「导出前清理 N 条失效引用」（否则下一个下载者也会中招）；
3. **建议加迁移**：`NativeWorkshop.Begin()` 时检测一次，把结果放进 `SessionWarnings`（现有机制，`DiyWorkshopScreen.NativeWorkspace.cs:20` 已有展示按钮），让玩家知道包里有什么问题。

## 11. 给玩家的临时话术（可直接回复）

> 这不是卡组或存档坏了，是卡包里某张卡的「显示文本」和卡清单对不上，程序把它当成整包错误，所以整个扩展包暂时不显示。
> 可以这样恢复：关闭游戏 → 打开
> `%APPDATA%\Godot\app_userdata\OrC-KSD · 卡牌指挥部\workshop\` → 找到对应卡包目录（未转正的草稿是 `<包名>.tmp`）→ 先复制一份备份 → 用记事本打开 `display-texts.json`，删掉 `card.ab58f238d9594300a4bdbbf621a2a52` 开头那一整行（注意上一行末尾的逗号）→ 保存后重进游戏。
> 之后那张卡会显示成「待修复的卡牌」，点进去把效果补上就好。
